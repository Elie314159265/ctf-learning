## 1. CVE-2026-0768 — Langflow Unauthenticated RCE

**Principle / root cause:** Langflow's custom component editor includes a code validator that is supposed to sandbox user-supplied Python before execution. The validator fails to properly restrict what the submitted code can do, so a specially crafted "component" definition escapes the intended sandbox and runs arbitrary Python in the context of the Langflow server process — without authentication.

**Mitigation:**
- Upgrade Langflow to the patched release referenced in the vendor advisory immediately.
- Do not expose the Langflow management/API interface directly to the internet; place it behind authentication and network-level access controls (VPN, allow-listed IPs).
- Treat any internet-facing instance that has not yet been patched as compromised: rotate any secrets/environment variables reachable from the Langflow process, and review logs for component-creation/execution requests from unrecognized sources.

**Affected:** Langflow (self-hosted deployments), all versions prior to the vendor's fixed release. VulnCheck telemetry recorded 50+ exploitation attempts within hours of disclosure on 2026-08-30, rising to 360+ by 2026-09-01, with attacker traffic querying environment variables and cached secrets — i.e., reconnaissance/credential-harvesting ahead of RCE.

## 2. CVE-2026-66066 — Ruby on Rails Arbitrary File Read → RCE

**Principle / root cause:** An unauthenticated arbitrary file-read primitive in Rails allows a remote attacker to read files from the server filesystem, including the Rails application's own environment and secrets store. Because Rails process configuration commonly holds `secret_key_base`, the Rails master key, database credentials, and cloud-storage/API tokens, the file-read bug lets an attacker harvest these secrets directly. `secret_key_base` disclosure in particular enables session/cookie forgery, and combined with other exposed credentials this path escalates to full remote code execution.

**Mitigation:**
- Patch Rails to the fixed version referenced in the official Rails security advisory without delay.
- Treat this as a secrets-compromise event even after patching: **rotate `secret_key_base`, the Rails master key, database passwords, and any cloud/API credentials** that were reachable by the vulnerable process, since leaked secrets remain useful to attackers after the software itself is patched.
- Audit access/application logs for anomalous requests to file-serving or asset paths and for any session activity that could indicate cookie/session forgery using a leaked `secret_key_base`.

**Affected:** Ruby on Rails applications on vulnerable versions (see rubyonrails.org security advisory for exact version ranges). Actively exploited in the wild as of 2026-09-01, often chained with the Langflow bug above in the same campaign (opportunistic scanning across both stacks).

## 3. CVE-2026-82329 — JFrog Artifactory Authentication Bypass → Admin Takeover

**Principle / root cause:** Improper authentication (CWE-287) in self-hosted JFrog Artifactory allows an unauthenticated attacker with network access to obtain administrative privileges under the default configuration. Reports describe attackers "minting themselves admin tokens" — i.e., the flawed auth check lets a crafted request obtain a valid admin-scoped token without ever proving identity. Because Artifactory frequently sits inside CI/CD pipelines with access to build artifacts, credentials, and downstream deployment systems, an admin-level compromise is a direct path into the software supply chain.

**Mitigation:**
- Upgrade self-hosted Artifactory to version **7.161.20** or later (released 2026-08-28), which patches this issue.
- JFrog SaaS/cloud-hosted Artifactory is **not** affected — only self-hosted instances.
- After patching, audit for unexpected admin users/API tokens created around or after 2026-08-28, and rotate all Artifactory tokens and any credentials/artifacts the platform had access to if compromise is suspected.
- Restrict network exposure of the Artifactory admin interface to trusted networks as defense in depth.

**Affected:** Self-hosted JFrog Artifactory instances, multiple versions, prior to 7.161.20. Exploitation began within days of the 2026-08-28 disclosure/patch and was still active as of 2026-09-01–02.

## 4. CVE-2026-81578 & CVE-2026-82078 — PaperCut NG/MF Pre-Auth RCE Chain

**Principle / root cause:** Two chained flaws in PaperCut NG/MF's web management interface:
- **CVE-2026-81578** (CVSS 8.8, auth bypass): specially crafted unauthenticated requests can cause administrative backend actions to execute *before* access-control checks complete, letting an attacker modify system configuration without credentials.
- **CVE-2026-82078** (CVSS 9.4, unsafe dynamic class loading): PaperCut's database-connection utility instantiates a database-driver class based on a configurable driver name without validating that name, so an attacker who can influence that config (via #1) can point it at an attacker-selected class already present on the application classpath, achieving arbitrary Java bytecode execution.

Chained together, these give an unauthenticated attacker full pre-authentication remote code execution.

**Mitigation:**
- Apply PaperCut's **second emergency patch ("Release 2")** — fixed builds are **24.1.10, 25.0.13, and 26.0.5**. Apply Release 2 even if the first emergency patch (2026-08-28) was already installed; researchers found bypasses for the initial fix.
- Until patched, restrict the PaperCut web interface to trusted/internal networks only (firewall/ACL) — do not expose it directly to the internet.
- Confirmed actively exploited and added to CISA's Known Exploited Vulnerabilities catalog (2026-08-31); treat any unpatched internet-facing instance as a high-priority incident.

**Affected:** PaperCut NG and PaperCut MF, versions 24, 25, and 26, prior to the respective Release 2 builds above.

## 5. Cisco IOS XR Software — Multiple Vulnerabilities (2026-09-02 advisory batch)

**Principle / root cause:**
- **CVE-2026-20040** (CVSS 8.8): insufficient validation of user-supplied arguments to specific CLI commands allows a low-privileged, authenticated attacker to elevate privileges to root and execute arbitrary commands.
- **CVE-2026-20046** (CVSS 8.8): incorrect task-group/privilege mapping in the source code for a specific CLI command allows an authenticated attacker to gain administrative control of the device.
- **CVE-2026-20074** (CVSS 7.4): a flaw in IS-IS multi-instance routing handling allows an unauthenticated, adjacent attacker to crash/restart the IS-IS process (denial of service).
- **CVE-2026-20118** (CVSS 6.8): improper handling of an Egress Packet Network Interface (EPNI) Aligner interrupt, also DoS-class.

**Mitigation:**
- Apply the fixed IOS XR software releases identified in the corresponding Cisco PSIRT advisories (published 2026-09-02) for each CVE — check device train/version against the advisory's "Fixed Releases" table.
- No workaround is generally available for CLI-argument-validation or privilege-mapping bugs; patching is required. For the IS-IS DoS issue, limiting IS-IS adjacencies to trusted, authenticated neighbors reduces exposure until patched.
- No public evidence of active exploitation as of this report; treat as scheduled patching, prioritized by the two CVSS 8.8 privilege-escalation issues.

**Affected:** Cisco IOS XR Software (specific platforms/trains per each advisory — verify against Cisco's advisory pages, as not all IOS XR platforms are affected by every CVE in this batch).

## 6. CVE-2026-84802 — Craft CMS Information Disclosure

**Principle / root cause:** `AssetsController::actionMoveInfo` in Craft CMS fails to enforce volume (asset-storage) permissions correctly, allowing an authenticated user without sufficient rights to obtain information about assets/volumes they should not have access to.

**Mitigation:** Upgrade Craft CMS to version 5.10.12 or later (fix applies to the 5.7.0–5.10.12 affected range).

**Affected:** Craft CMS versions from 5.7.0 up to (but not including) 5.10.12.

---

## 7. CVE-2026-84780 — WP Go Maps Unauthenticated DoS

**Principle / root cause:** The WP Go Maps WordPress plugin contains a flaw that allows an unauthenticated attacker to trigger a denial-of-service condition against sites running the plugin.

**Mitigation:** Update WP Go Maps to the latest patched version via the WordPress plugin repository.

**Affected:** WP Go Maps plugin for WordPress (see plugin changelog for the exact fixed version).
