## 1. CVE-2026-65660 — Microsoft SharePoint Server コードインジェクション（RCEへ再分類）

**原理・根本原因:** SharePointは特定の入力からのコード生成を適切に制御できておらず、認証済み攻撃者が細工した入力を送信すると、SharePointはそれをサーバー側コードとしてコンパイル・実行してしまう（CWE: コード生成の不適切な制御／コードインジェクション）。Microsoftの当初のアドバイザリではこの問題を「なりすまし」として分類していたが、その後の調査で実際の影響は認証済みリモートコード実行であることが確認され、攻撃者は別の未認証の配送用脆弱性と連鎖させて暗号化されたローダーペイロードを設置していることが観測されている。

**対策:**
- 未適用の場合は、Microsoft の SharePoint Server セキュリティ更新プログラム（2026年8月の月例更新に含まれる）を適用する。
- インターネットに公開されたオンプレミスSharePointファームは最優先で対応し、匿名／低権限アカウントの作成を制限し、w3wp.exeの異常な子プロセスを監視する。

**影響を受ける製品:** オンプレミスのMicrosoft SharePoint Server 2016、2019、およびSubscription Edition（SharePoint Online／Microsoft 365は対象外）。パッチは2026年8月から提供済み。悪用が確認されたことを受け、2026-09-25にCISA KEVへ追加された。

## 2. CVE-2026-67279 & CVE-2026-86060 — MikroTik RouterOS "MikroTrick" 未認証管理者権限奪取

**原理・根本原因:** RouterOSのSSHサーバーは、クライアントがユーザー認証を実際には完了していないにもかかわらず、クライアント主導の鍵再交換（rekey）後に認証後の接続プロトコルへ遷移してしまうことがある。これにより未認証のクライアントがセッションチャネルを開いてexec要求を発行でき、サーバー側はあたかもログイン済みユーザーからの要求であるかのように処理してしまう。その結果、設定情報や診断データを含むRouterOSの管理対象ファイル名前空間内のファイルの作成・上書き・再構成が可能になる。RouterOSログイン処理内の別の引数インジェクション脆弱性（CVE-2026-86060）と連鎖させる「MikroTrick」と呼ばれる手法により、パスワード・SSH鍵・認証完了のいずれも不要な完全な管理コンソールアクセスが得られる。

**対策:**
- RouterOSを6.49.21（Long-term）、7.23.4（Long-term）、または7.24.2（Stable）以降にアップグレードする。
- RouterOSデバイスのSSH／管理プレーンの露出を信頼できるネットワークに制限し、予期しない設定変更や新規管理者アカウントを監査する。

**影響を受ける製品:** 6.49.20 / 7.23.3 / 7.24.1以前のMikroTik RouterOS。ベンダーパッチは2026-09-03に公開されたが、CERT.plが観測した最初の攻撃通信はそれ以前（2026-09-02頃）に遡る。2026-09-25にCISA KEVへ追加された。

## 3. CVE-2026-94127 — F5 BIG-IP APM ヒープベースバッファオーバーフロー（未認証RCE）

**原理・根本原因:** BIG-IPの仮想サーバーにAccess Policy Manager（APM）のアクセスポリシーとOAuthプロファイルの両方が関連付けられ、APMがOAuth認可サーバーとして動作している構成において、その仮想サーバーへ送られる細工されたトラフィックが、要求処理パス内で安全でないメモリ操作（ヒープベースバッファオーバーフロー、CWE-122）を引き起こす。これにより未認証のネットワーク攻撃者がメモリを破壊し、リモートコード実行を達成できる。

**対策:**
- F5アドバイザリK000162605に従い、影響を受けるBIG-IP APMブランチ（17.1.x、17.5.x、21.1.0）向けのパッチを適用する。
- 直ちにパッチを適用できない場合は、対象の仮想サーバー向けの暫定的なiRuleベースの緩和策についてF5サポートに問い合わせる。

**影響を受ける製品:** APMアクセスポリシーとOAuthプロファイルが同一仮想サーバーに組み合わされたF5 BIG-IP APM（17.1.x、17.5.x、21.1.0ブランチ）。2026-09-22に公開されCISA KEVへ追加。公開時点でF5は実際の悪用を確認済み。

## 4. CVE-2026-85102 & CVE-2026-93616 — Check Point Security Gateway / Security Management の事前認証脆弱性

**原理・根本原因:** CVE-2026-85102は、Check Point Security Gateway／Spark FirewallのVPN証明書処理における証明書検証不備（CWE-295）であり、サイト間VPNまたはリモートアクセスVPNのネゴシエーション中に提示される不正な証明書を用いることで、未認証の攻撃者がコード実行を達成できる。CVE-2026-93616は、Check Point Security Managementにおける事前認証パストラバーサル脆弱性であり、攻撃者は認証情報なしに任意のファイルシステムパスからスクリプトを実行し、任意のJavaクラスをロードできる。

**対策:**
- Check Pointの修正パッチ（CVE-2026-85102向けは2026-09-09から提供）を、Security Gateway、Spark、Security Managementの全展開に直ちに適用する。
- 管理インターフェースおよびVPNエンドポイントの露出を信頼できるネットワークに制限し、9月中旬以降のVPN・管理ログで異常な証明書やパス関連のリクエストを確認する。

**影響を受ける製品:** 修正版より前のCheck Point Security Gateway、Spark Firewall、Security Managementサーバー。CVE-2026-85102に対する悪用は2026-09-12頃からSpark顧客を対象に世界的に観測されている（匿名化・VPN／プロキシインフラを起点とする）。CVE-2026-93616の悪用は今夏、限定的な標的型攻撃で既に観測されていた。いずれも2026-09-22にCISA KEVへ追加。

## 5. CVE-2026-93952 — Arista VeloCloud Orchestrator 入力検証不備（最大深刻度）

**原理・根本原因:** VeloCloud Edgeデバイスとオーケストレーター間で証明書ベース認証が設定されたVeloCloud Orchestrator（VCO）環境において、入力検証の不備により、VCOのWeb UIに到達可能でVeloCloud Edge認証証明書の公開部分のみを保持する（VCOテナント／オペレーター資格情報は不要）リモート攻撃者が、VCOホスト内部の特権機能に到達できてしまう。侵害されたVCOは、それが管理する全てのEdgeデバイスへアクセス・管理するための足掛かりとして利用され得る。

**対策:**
- オンプレミスVCOを5.2.3.16または6.4.2.8以降にアップグレードする。
- 証明書ベースのEdge→VCO認証が有効な環境では、公開時期以降のEdge／VCOログで想定外の管理操作がないか確認する。

**影響を受ける製品:** 証明書ベースのEdge認証が有効なオンプレミスArista VeloCloud Orchestrator（5.2.x系、6.4.x系）。外部からの報告により発見され、悪用が確認された。2026-09-22にCISA KEVへ追加され、連邦政府向け対応期限は2026-09-25とされた。

## 6. CVE-2026-7273 — Zyxel GS1900シリーズスイッチ スタックベースバッファオーバーフロー

**原理・根本原因:** Zyxel GS1900スイッチのCGI Web管理プログラムは攻撃者提供の入力の境界チェックを行っておらず、スタックベースバッファオーバーフロー（CWE-121）が発生する。ローカルネットワーク上の未認証攻撃者が細工したHTTPリクエストを送ることでこれに到達可能であり、悪用に成功するとスイッチ上で任意のOSコマンドを実行できる。

**対策:**
- 影響を受ける10機種のGS1900モデル全てに対し、Zyxelのファームウェア更新（2026年6月から提供）を適用する。
- 管理インターフェースへのアクセスを信頼できる管理VLAN／ネットワークに制限し、漏洩した可能性のある資格情報をローテーションする。

**影響を受ける製品:** ファームウェア2.90(XXXX.1)C0以前のZyxel GS1900シリーズスイッチ。中国系とみられる脅威アクターが、2026年8月以降、48か国にわたる推定約1,000台のインターネット公開スイッチから設定情報とハッシュ化されたrootクレデンシャルを窃取したとされる。2026-09-21にCISA KEVへ追加され、連邦政府向け対応期限は2026-09-24とされた。

## 7. CVE-2026-32996 — Veeam Agent for Microsoft Windows ローカル権限昇格

**原理・根本原因:** VeeamのEndpoint Backupサービスは、ローカルgRPC名前付きパイプを介してエージェント向けの特権操作を仲介している。同サービスは、クライアントが指定したセッションUIDに管理者相当の昇格済みアイデンティティを関連付けるが、そのUIDを実際の要求元プロセスやパイプ接続に安全に結びつけていない。これにより、低権限のローカルユーザーが特権セッションコンテキストを乗っ取り、NT AUTHORITY\SYSTEMとしてコマンドを実行できる。

**対策:**
- Veeam Backup & Replicationを13.0.2.29以降にアップグレードする（同梱のVeeam Agent for Windowsがビルド13.0.3.1220に更新され、修正が適用される）。アップグレード以外の確実な回避策は存在しない。

**影響を受ける製品:** 13.0.1.2067以前のVeeam Agent for Microsoft Windows（13.x系ビルド）。技術的詳細と動作するエクスプロイトコードが2026-09-14に公開され、その後、独立系研究者により侵害後の権限昇格チェーンでの実際の悪用が確認された。

## 8. CVE-2026-82843 — WP OAuth Server（"Login with WordPress"）OpenID IDアサーション誤結合

**原理・根本原因:** 当該プラグインのOpenID Connect実装は、発行するIDアサーションを、実際に引き換えられている認可グラントに結び付けていない。代わりに、サイト上で最も最近認証したユーザーに属するアサーションを返してしまう。これにより、認証済みの任意のユーザー（購読者ロール以上）が、サイト管理者を含む別のユーザーの正当に署名されたIDアサーションを取得し、そのサイトをシングルサインオンに利用する下流の任意のアプリケーションへ当該ユーザーとしてログインできてしまう。

**対策:**
- バージョン6.4.0以降へアップデートする。
- SSO用途で当該プラグインを利用しているサイトは、更新後、最近のSSOログインイベントの異常有無を確認し、セッショントークンのローテーションを検討する。

**影響を受ける製品:** 6.4.0より前のWP OAuth Server／"Login with WordPress"（WordPressプラグイン）。今週公開。大規模な悪用は現時点で未確認だが、悪用の敷居が低い（任意の認証済み購読者アカウントで可能）ため、速やかなパッチ適用が重要となる。

## 9. CVE-2026-67409 & CVE-2026-67404 — RabbitMQ OAuth2/JWKS 処理の脆弱性

**原理・根本原因:** CVE-2026-67409: RabbitMQのJWKS鍵取得コードは、OAuth2プロバイダーのJWKSエンドポイントから返されるHTTPステータスコードを検証していない。ボディが有効なJSONとしてパースできるが`keys`フィールドを含まない非200応答を受け取ると、RabbitMQは既にキャッシュしている全ての署名鍵を破棄してしまう。これにより、単一の不正な応答がブローカー上の全OAuth2/JWT認証ユーザーに対する永続的な認証サービス拒否を引き起こし得る。CVE-2026-67404は関連する証明書検証不備であり、中間者攻撃者がJWKS応答を偽造し、ブローカーに攻撃者制御下のJWTを正当なものとして受け入れさせることができる。

**対策:**
- 両問題を修正した RabbitMQ 4.3.3、4.2.9、4.1.14、4.0.23、または3.13.18（以降）へアップグレードする。
- 多層防御として、JWKSエンドポイント接続に対するTLS証明書検証が適切に強制されていることを確認する。

**影響を受ける製品:** リモートJWKS取得を伴うOAuth2/JWT認証を構成しているRabbitMQ Server 3.13.0から上記修正版より前のバージョン。今週GitHubセキュリティアドバイザリを通じて公開。

## 10. CVE-2026-100589 — OpenClaw AIエージェント ペアリングノード経由のサンドボックス回避

**原理・根本原因:** OpenClawのブラウザツールは、`allowHostControl=false`が設定されている場合、サンドボックス化されたエージェントセッションがホストに接続された（「ペアリングされた」）ブラウザを制御できないようにすることを意図している。しかし、ペアリングノードに対するブラウザ操作についてはこの制限が正しく強制されておらず、サンドボックス化されたエージェントセッションへの入力を制御できる攻撃者は、ペアリングノードを選択してホストブラウザ操作をそのまま実行でき、接続されたブラウザの認証済みセッションを検査・操作できてしまう。

**対策:**
- OpenClawをバージョン2026.7.1以降にアップグレードする。
- アップグレードするまでは、信頼できない入力を処理するエージェントセッションにホストブラウザをペアリングしない。

**影響を受ける製品:** 2026.7.1より前のOpenClawバージョン。今週、OpenClawのサンドボックス関連のより広範な調査結果の一部として公開された。実際の悪用は現時点で未確認。
