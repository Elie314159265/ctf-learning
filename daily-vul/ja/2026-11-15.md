## 最新項目（直近24〜72時間）

### 1. CVE-2026-123039 — Check Point Gaia OS のローカル権限昇格（root）（悪用確認済み）

**原理・根本原因：** Gaia の DynamicCLI 機能を支える root 権限のヘルパープロセスが、アクセス制御の緩すぎる（全ユーザー書き込み可能な）ローカルソケットで待ち受けています。さらに、受け取ったコマンドを実行する前に送信元を適切に確認していません。そのため、アプライアンス上の低権限のローカルアカウントやプロセスが、root 権限でコマンドを実行させることができます（CWE-269 不適切な権限管理、重要リソースに対する不適切なパーミッション設定）。攻撃者が別の初期侵入用の脆弱性と組み合わせてゲートウェイを完全に乗っ取ったとする報道もありますが、この組み合わせは独立に確認されていません。

**緩和策：**
- 本CVEに関する Check Point のアドバイザリに記載された修正を適用してください。複数の情報源が、運用中のバージョン向けの最新（2026年11月）Jumbo Hotfix Accumulator の適用を推奨しています。
- 悪用が確認されているため、侵害の痕跡を確認してください：見覚えのないローカルアカウント、変更された起動スクリプト、root で動作する不審なプロセス、説明のつかない設定変更など。
- Gaia アプライアンスへのシェルやローカルアクセスが可能な者を制限してください（管理ネットワークからのみ許可、管理者アクセスには MFA）。
- CISA の指針：ベンダーの緩和策を適用し、緩和策がない場合は製品の使用を中止すること。連邦機関の期限は 2026-11-16 です。

**影響範囲：** Security Gateway（Quantum / Force ファイアウォールを含む）、Management Server および Log Server、Multi-Domain Security Management、Maestro Orchestrator 上の Check Point Gaia OS。Spark ファイアウォールと Smart-1 Cloud は影響を受けないと報じられています。正確なバージョンと Jumbo Hotfix の Take 番号は Check Point のアドバイザリで確認してください（カナダサイバーセキュリティセンター AV26-1154 も参照）。

**公開日：** ベンダーアドバイザリは2026年11月上旬、CISA KEV への追加は **2026-11-13**。

### 2. CVE-2026-114713 — UnrealIRCd の IRCv3「label」メッセージタグによるコマンドインジェクション（悪用確認済み）

**原理・根本原因：** UnrealIRCd の labeled-response モジュール（IRCv3 `labeled-response`）が、クライアントから送られた `label` メッセージタグを適切にエスケープせずにサーバー応答に埋め込んで返します（CWE-140 区切り文字の不適切な無害化）。タグがエスケープされないため、接続中の一般ユーザーが、攻撃者の選んだデータをサーバー発の別のプロトコル行としてサーバーに扱わせることができます。その結果、サーバーは攻撃者に代わって、サーバーまたは IRC オペレーター権限で IRC コマンド（KILL、GLINE など）を実行します。プロジェクトはこれを約15年間で最も深刻な脆弱性と表現しています。

**緩和策：**
- **UnrealIRCd 6.2.7.1** 以降にアップグレードしてください（再起動不要のホットパッチとしても提供されているセキュリティリリース）。このリリースでは他の8件の問題も修正されています。
- すぐにアップグレードできない場合は、公式アドバイザリに記載された spamfilter による暫定回避策を適用してください。
- 11月上旬以降に想定外の KILL / GLINE / オペレーター操作がないか、サーバーログを確認してください。

**影響範囲：** UnrealIRCd 6.0.0 〜 6.2.7（6.2.7.1 より前のすべてのバージョン）。

**公開日：** **2026-11-07** に修正・告知（oss-security）、CVE は 2026-11-08 頃に公開。実環境での悪用が確認され、**2026-11-13** に CISA KEV へ追加。

### 4. CVE-2026-119618 — Apache HTTP Server mod_http2 の競合状態 → ヒープ破損 / RCE

**原理・根本原因：** HTTP/2 モジュールのヘッダー処理経路（`assign_headers()` 内と報じられている）における並行処理のバグ（CWE-362 競合状態）。特定のタイミング条件下で、リクエストやストリームの共有状態が変更中または解放中にアクセスされ、ヒープメモリが破損します。HTTP/2 で通信する認証不要のリモートクライアントがワーカープロセスをクラッシュさせることができ、最悪の場合はコード実行に至る可能性があります。

**緩和策：**
- **Apache HTTP Server 2.4.71** 以降にアップグレードするか、ディストリビューションのバックポート済みパッケージを適用してください（Red Hat は RHEL 9/10 を「Important」と評価）。モジュールを個別にビルドしている場合は **mod_h2 2.0.43** 以降を使用してください。
- すぐにパッチを適用できない場合は、公開サーバーで HTTP/2 を一時的に無効化してください（`Protocols` ディレクティブから `h2` / `h2c` を削除）。
- 2.4.71 では、他に低深刻度の問題2件（CVE-2026-109163、CVE-2026-106023）も修正されています。

**影響範囲：** mod_http2 が有効な Apache HTTP Server **2.4.55 〜 2.4.70**。httpd を同梱する製品（アプライアンス、コントロールパネル、コンテナのベースイメージ）も、これらのバージョンを含む場合は影響を受けます。CVE-2026-23918（2.4.67 で修正された二重解放）とは別の問題です。

**公開日：** **2026-11-11**。最新の報道時点で悪用報告はありません。

### 5. CVE-2026-126325 — PTC Windchill および FlexPLM の安全でないデシリアライゼーション

**原理・根本原因：** サーバーが信頼できないデータを検証せずにデシリアライズします（CWE-502）。攻撃者が制御するシリアライズ済みオブジェクトが脆弱なエンドポイントに届くと、アプリケーションサーバー内でオブジェクト生成の連鎖が引き起こされ、PLM サーバーの権限でリモートコード実行に至る可能性があります。

**緩和策：**

- パッチ適用までは、Windchill / FlexPLM サーバーへのネットワークアクセスを信頼できるユーザーとネットワークに限定してください。PTC が公開する暫定的な設定上の緩和策（リバースプロキシで該当する servlet パスをブロックするなど）も適用してください。

**影響範囲：** PTC Windchill および FlexPLM（サポート対象の複数リリース。正確なバージョン / CPS レベルは PTC のアドバイザリを参照）。

**公開日：** **2026-11-11**。悪用の確認報告はありません。

### 6. CVE-2026-124194 — Microsoft Outlook のなりすまし / NTLM ハッシュ漏えい（悪用済みゼロデイ）

**原理・根本原因：** 細工されたメッセージファイルによって、従来のデスクトップ版 Outlook が攻撃者の管理するネットワーク上の場所へ外向きの接続を開始してしまいます。その際、Outlook は外部コンテンツに対する通常の警告やブロックを行いません。この接続中に Windows が NTLM 認証情報を送信することがあるため、攻撃者はこのバグを利用してユーザーの NTLM ハッシュを収集しています。収集されたハッシュは、オフラインで解析されたりリレー攻撃に使われたりする可能性があります。CVSS は 6.5（Moderate）にとどまりますが、悪用されているため優先度を高く扱ってください。

**緩和策：**
- Office 独自の Click-to-Run / Office 更新チャネルで Office を更新してください。**この修正は Windows の累積更新プログラムでは配信されません。** ある報告によると、Microsoft 365 Apps Current Channel での修正はバージョン 2610（ビルド 20527.20196）です。
- インターネット向けの外向き SMB（TCP 445）/ WebDAV をブロックしてください。重要なユーザーを *Protected Users* グループに追加するか、外向き NTLM 通信の制限を検討してください。
- 報道によると Office 2016/2019 には修正が提供されないため、これらのインストールは移行してください。

**影響範囲：** Microsoft 365 Apps for Enterprise（32/64ビット）、Office LTSC 2021（報道では 16.0.14334.21048 未満のビルド）、Office LTSC 2024（報道では 16.0.17932.21140 未満のビルド）。

**公開日：** **2026-11-10**（Patch Tuesday）。CISA KEV 追加 2026-11-10、連邦機関期限 2026-11-24。

### 7. CVE-2026-125350 — Google Chrome の XML における解放後使用（悪用済みゼロデイ）

**原理・根本原因：** Chrome の XML 処理コンポーネントにおける解放後使用（use-after-free、CWE-416）。細工された Web ページによって、ブラウザが解放済みのメモリを使用してしまい、メモリ破損を経てレンダラーのサンドボックス内でコードが実行される可能性があります。攻撃者は通常、この種のバグをサンドボックス回避の脆弱性と組み合わせて使います。Google は実環境で悪用コードが存在することを認めています。2026年に悪用が確認された Chrome のゼロデイとしては8件目です。同じリリースで、2件目の XML の解放後使用（CVE-2026-125346）も修正されています。

**緩和策：**
- Chrome を **157.0.8103.50**（Linux）/ **157.0.8103.50/.51**（Windows、macOS）以降に更新し、ブラウザを再起動してください。
- その他の Chromium ベースのブラウザ（Edge、Brave、Opera、Vivaldi など）も、各ベンダーが修正を提供し次第更新してください。

**影響範囲：** 157.0.8103.50 より前の Google Chrome、および脆弱なバージョンをベースとした Chromium 系ブラウザ。

**公開日：** 2026-11-06 に報告、**2026-11-09** に修正、CISA KEV 2026-11-10（期限 2026-11-24）。

### 8. CVE-2026-116606 & CVE-2026-111560 — Barracuda Email Security Gateway の認証前攻撃チェーン（悪用確認済み）

**原理・根本原因：** 組み合わせることで、認証されていないリモートの攻撃者がアプライアンス上で root としてコマンドを実行できる2件の脆弱性です。公開情報では、一方は認証なしで到達できる入力処理の欠陥、もう一方はコマンド実行を可能にする欠陥とされています。研究者（watchTowr）による技術解説と検出ツールは、Barracuda のパッチ公開後に公開されました。Barracuda は少数の組織に対する攻撃を確認しています。

**影響範囲：** 9.4.0.030 より前の Barracuda Email Security Gateway（CVE-2026-116606、CVSS 9.3）。CVE-2026-111560（CVSS 8.6）は他の Barracuda 製品ラインにも影響します（ベンダーアドバイザリを参照）。

**公開日：** 2026-11-02 の週の前半にパッチ公開、同じ週の後半に技術解説が公開され、**2026-11-10** に CISA KEV へ追加（連邦機関期限 2026-11-13）。悪用の有無について当初の報道は食い違っていましたが、KEV への掲載で決着しました。

### 9. CVE-2026-123158「SSHole」— musl Linux 上の OpenSSH パスワード認証バイパス（悪用確認済み）

**原理・根本原因：** 2016年の変更に由来する移植性対応のコード経路が、**musl libc** を使い **PAM を使わずに** パスワード認証を行う Linux システム上で正しく動作しません。パスワードが異常に長い場合（報道では約256〜1,024バイト）に長さのチェックが誤り、sshd がパスワードを正しく検証しないままログインを受け入れることがあります。その結果、認証がバイパスされます。攻撃は公開から数時間〜1日以内に始まりました。報告されたペイロードには、ボットネット / 暗号資産マイナーの展開や Python 製のバックドアが含まれます。

**緩和策：**
- **Portable OpenSSH 10.6p2** 以降、またはディストリビューションの修正済みパッケージに更新してください（Alpine は 2026-11-05 に修正パッケージを公開）。
- 暫定策として、パスワード認証を無効化（`PasswordAuthentication no`）して鍵認証を使うか、許可リストで SSH の公開範囲を制限してください。
- 公開されている musl ベースのホスト（sshd を動かす Alpine ベースのコンテナを含む）で侵害の痕跡を調査してください。

**影響範囲：** PAM を使わないパスワード認証を行う **musl ベース** の Linux システム上の、10.6p2 より前の Portable OpenSSH。glibc ベースのディストリビューションや PAM を使う構成は影響を受けません。

**公開日：** **2026-11-05**、2026-11-05/06 から悪用、CISA KEV 2026-11-09（期限 2026-11-12）。

**影響範囲：** IBM Aspera Faspex **5.0.0 〜 5.0.19**。

**公開日：** IBM の速報は2026年11月上旬、CISA KEV **2026-11-09**（連邦機関期限 2026-11-12）。

### 11. CVE-2026-19868 — SonicWall SonicOS SSLVPN の SAML / MFA バイパス（悪用確認済み）

**原理・根本原因：** SSLVPN ログインで SAML が有効な場合でも、SonicOS はその方式を厳格に必須としていません。設定済みの *別の* 認証方式（LDAP、RADIUS、TACACS+、ローカルなど）の有効な資格情報を持つユーザーは、その方式でログインして SAML の手順を省略でき、SAML が強制する MFA も回避できます（CWE-308）。その結果、盗まれたパスワードだけで VPN にアクセスできてしまいます。

**緩和策：**
- SonicWall アドバイザリ **SNWLID-2026-0014** の修正済み SonicOS ビルドにアップグレードしてください（報道では Gen7 **7.3.4-7013** 以降、Gen8 **8.2.3-8015** 以降）。
- 報告されている暫定回避策：SSLVPN に不要な、ファイアウォール上に設定された LDAP / RADIUS / TACACS+ 認証サーバーを無効化または削除する。
- VPN ユーザーの資格情報をリセットし、SAML を経由していないログインがないか VPN ログを確認してください。

**影響範囲：** SAML による SSLVPN ログインが有効な SonicOS Gen7 **7.3.3-7015 以前**、Gen8 **8.2.2-8015 以前**。

**公開日：** **2026-11-06**（アドバイザリに含まれる7件の修正の1つ）、CISA KEV 2026-11-06（期限 2026-11-20）。

### 12. Microsoft 2026年11月 Patch Tuesday（概要）

**原理・根本原因：** Microsoft の月例リリースとして過去最大規模で、約1,094件の CVE を扱います。サードパーティ / Chromium の CVE を数えるかどうかにより、情報源によって約1,093〜1,235件と報じられています。Critical は63〜64件です。悪用が確認されているのは CVE-2026-124194（項目6）のみで、リリース前に公開されていたものは報告されていません。

**緩和策：** 11月の Windows 累積更新プログラムと、別途配信される Office / Microsoft 365 の更新を展開してください。インターネットに公開されたサービスと Critical の RCE 修正を優先してください。

**影響範囲：** Windows クライアント / サーバー、Office / Microsoft 365、その他の Microsoft 製品（Microsoft Security Update Guide を参照）。

**公開日：** **2026-11-10**。
