## 1. CVE-2026-123039 — Check Point Gaia OS のローカル権限昇格（「DynamicCLI」）

**原理・根本原因：** Gaia OS では root 権限の `dynamic_server` デーモンが、ローカル IPC ソケット（`/tmp/dynamic_socket`）でコマンドを受け付けます。このソケットは誰でも書き込める権限で作成され、デーモンは接続元を認証しません。そのため、権限の低い Web／ポータルのプロセスを含むどのローカルプロセスでもコマンドを送ることができ、デーモンはそれを root として実行します（重要なリソースへの不適切な権限割り当て、CWE-732）。確認された攻撃では、これは攻撃チェーンの第 2 段階でした。攻撃者はまず Mobile Access ポータルの PHP2Shell 脆弱性（#13）でコードを実行し、次にこの脆弱性でゲートウェイの root 権限を得ました。

**緩和策：**
- 使用しているリリースブランチ向けの Check Point ホットフィックス／Jumbo Hotfix を直ちに適用してください。ある報道によると R82.20 は Jumbo Take 14 で修正済みです。他のブランチは sk 番号付きのアドバイザリで確認してください。
- すぐにパッチを当てられない場合は、Check Point の推奨どおり `dynamic_server` を停止し、再起動しないようにしてください。停止中は一部の CLI 機能が使えなくなる可能性があります。
- パッチ適用後、ソケットが誰でも書き込める状態でなくなったことを確認してください。報道によると、権限は `0660`、所有者は `root:config` になるはずです。
- Mobile Access／SSL VPN を有効にしているインターネット公開ゲートウェイから優先して対処し、侵害の痕跡（想定外の root プロセス、新しいアカウント、設定の変更）を調査してください。

**影響範囲：** Gaia R81.20、R82、R82.10、R82.20 上の Check Point Security Gateway、Firewall、Scalable Platforms、Security Management Server、Multi-Domain Management。R81.10 と R81 も対象とする情報源もあります。悪用は 2026-10-30 頃に始まり、Check Point によると被害を受けた顧客は「数十社」です。**公開日：** 2026-11-12（Check Point アドバイザリ）。2026-11-13 に CISA KEV に追加。

## 2. CVE-2026-114713 — UnrealIRCd のメッセージタグ経由のコマンドインジェクション

**原理・根本原因：** UnrealIRCd は IRCv3 メッセージタグの値に含まれる区切り文字を正しく無害化していません（CWE-140、区切り文字の不適切な無害化）。リモートのクライアントが細工したタグ内容を送ると、サーバーはそれをエスケープせずに転送します。その後の解析でこの内容が追加のプロトコルデータやコマンドとして扱われるため、攻撃者は信頼できないユーザーデータと、信頼されたサーバー間通信・コマンドの領域との境界を越えられます。メンテナーはこれを約 15 年で最も深刻な UnrealIRCd の問題と呼び、インターネット上での悪用を確認しています。

**緩和策：**
- **UnrealIRCd 6.2.7.1** 以降にアップグレードするか、2026-11-07 に公開された公式ホットパッチを適用してください。
- どちらもすぐにできない場合は、まずメンテナーが案内している暫定の spamfilter 回避策を適用してください。
- UnrealIRCd 5 は 2023-07-01 にサポートが終了しています。該当するサーバーはバージョン 6 に移行してください。

**影響範囲：** UnrealIRCd 6.0.0～6.2.7（6.2.7.1 より前のすべてのバージョン）。各ディストリビューション（Fedora、Gentoo など）のパッケージでも追跡中です。**公開日：** 2026-11-07（修正版／ホットパッチ）。2026-11-13 に CISA KEV に追加。2026-11-14 に公開エクスプロイトの報告あり。

## 3. 「4EverAble2Shell」— N-able N-central の認証不要 RCE チェーン（CVE-2026-90436 を含む）

**原理・根本原因：** **Legacy API** を有効にした N-central サーバーを狙う、認証前の攻撃チェーンです。その一段階では、同梱の Apache Axis Web サービスコンポーネントの欠陥（CVE-2026-90436、CVSS 9.8）を悪用します。認証なしのリクエストが、本来は認証が必要な SOAP 機能に届き、チェーンの最後に root としてコードが実行されます。この新しいチェーンは、以前の「Able2Shell」の公開を受けて 2026-11-10 にリリースされた N-central 2026.4 Hotfix 2 を適用したサーバーでも成立します。研究者は、N-central の脆弱性とされる約 33 件と PoC コードとあわせて、調整された開示を経ずにこれを公開しました。

**緩和策：**
- どうしても必要な場合を除き、**Legacy API モードを無効にしてください**。チェーンが成立する条件がなくなります。N-able も Legacy API と Intune 連携の機能を制限しています。
- N-central 2026.4 Hotfix 2 以降を適用し、N-able が追加のホットフィックスを出したらすぐに適用してください。
- 可能であれば N-central の Web インターフェースをインターネットに公開しないか、既知の IP アドレスからのみアクセスできるようにしてください。
- 侵害の痕跡を調査してください：N-central サーバー上の想定外のシェルスクリプト、XMRig／Monero マイナーのプロセス、新しいスケジュールタスク。N-central は配下の Windows エージェントを管理しているため、それらのエージェントに想定外の動きがないかも確認してください。

**影響範囲：** Legacy API を有効にしたセルフホスト型 N-central サーバー（2026.4.0.31 や 2026.4 Hotfix 2 を含む）。ホスト型インスタンスは N-able がアップグレードします。研究者は少なくとも 21 台の侵害を確認しており、そのうち 19 台は最新パッチ適用済みでした。N-able のアドバイザリでは侵害は確認していないとされています。**公開日：** 2026-11-12。数時間以内に悪用が続きました。

## 4. CVE-2026-119618 — Apache HTTP Server mod_http2 の競合状態（ヒープ破損 → RCE）

**原理・根本原因：** `mod_http2` の `assign_headers()` は、並行して処理される HTTP/2 ストリーム間で共有される状態を、適切な同期なしに読み書きしています（CWE-362、競合状態）。並行するリクエストによってヒープメモリが破損する可能性があり、Apache はリモートコード実行もあり得ると評価しています。HTTP/2 は 1 本の接続で多数のストリームを多重化するため、リモートのクライアントがこの並行処理を作り出せます。

**緩和策：**
- **Apache HTTP Server 2.4.71**（2026-11-11 リリース）、または修正がバックポートされたディストリビューションのパッケージ（例：Red Hat RHSA-2026:34355）に更新してください。
- すぐに更新できない場合の一時的な選択肢は、HTTP/2 の無効化です（`Protocols` から `h2`/`h2c` を外すか、`mod_http2` をアンロードする）。性能は低下します。
- httpd で動いているインターネット公開のリバースプロキシや TLS 終端サーバーから優先して対処してください。

**影響範囲：** mod_http2 を有効にした Apache HTTP Server 2.4.55～2.4.70。単体の mod_h2 2.0.8～2.0.42 を挙げる情報源もあります。インターネットに公開された多数のサーバーが該当します。実環境での悪用は報告されていません。**公開日：** 2026-11-11（2026-11-12 とする情報源もあり）。

## 5. CVE-2026-123710 — Red Hat Quay レジストリの署名鍵乗っ取り

**原理・根本原因：** 認可チェックの不備により、匿名トークンを持つ認証なしの呼び出し元が署名鍵を登録でき、レジストリはその鍵を信頼し、鍵は失効しません。攻撃者はこの鍵でレジストリが受け入れるトークンを発行できるため、事実上トークン署名を乗っ取り、プライベートリポジトリにもアクセスできます。Red Hat は、修正ビルドを導入するまでは不正な鍵を削除しても効果が続かないと注意しています。

**緩和策：**
- お使いのリリースストリーム向けに、Red Hat エラータ RHSA-2026:99023／99024／99026（またはそれ以降）の Quay 更新を適用してください。
- 更新後、想定外のサービスキーがないか確認して削除し、認証情報とトークンをローテーションしてください。
- Quay インスタンスのネットワーク公開範囲を絞り、不要であれば匿名アクセスを無効にしてください。

**影響範囲：** Red Hat Quay（サポート中の複数の 3.x ストリーム。正確なビルドはエラータを参照）。**公開日：** 2026-11-11（2026-11-12 更新）。悪用は未確認。

## 11. CVE-2026-123158（「sshole」）— musl／非 PAM ビルドの OpenSSH におけるパスワード認証バイパス

**原理・根本原因：** portable OpenSSH を **musl libc かつ PAM なし** でビルドすると、`sshd` が特定のシャドウパスワードフィールドを誤って扱います。フィールドで無効またはキー認証専用とされているアカウント（例：`*` のみ）について、musl の `crypt()` は glibc と動作が異なり、`sshd` にはその違いを考慮したチェックがありませんでした。その結果、こうしたアカウントで任意の異常に長いパスワードを受け入れることがあります。この欠陥は約 10 年間コードに存在していました。

**緩和策：**
- **OpenSSH 10.6p2** 以降に更新してください。Alpine の修正ビルド：edge 10.6_p2-r0、3.24.4、3.23.8。
- 暫定策：`PasswordAuthentication no`（および `KbdInteractiveAuthentication no`）を設定し、鍵認証だけを使ってください。
- Alpine ベースのコンテナやアプライアンスを確認してください。パスワード認証を有効にしたまま sshd を動かしていることがよくあります。

**影響範囲：** musl でビルドし PAM を使わない 10.6p2 より前の OpenSSH portable（Alpine Linux の既定の sshd、一部の組み込みシステムやコンテナ）。glibc／PAM のビルドは影響を受けません。**公開日：** 2026-11-05。PoC 公開済み。2026-11-09 に CISA KEV に追加（期限 2026-11-12）。

## 13. CVE-2026-109618 & CVE-2026-109619（「PHP2Shell」）— PHP ランタイムの RCE（参考）

**原理・根本原因：** PHP ランタイムのリクエスト処理にある 2 件の欠陥です。細工された HTTP リクエストにより、パッチ未適用の PHP で動くアプリケーションでは、フレームワーク（WordPress、Drupal、Magento など）に関係なくコードが実行される可能性があります。Apache mod_php に対するものを含め、実環境での悪用が確認されています。攻撃者は Check Point への攻撃（#1）で、これを最初の侵入に使いました。

**緩和策：** PHP を **8.5.12、8.4.27、8.3.36、8.2.35** 以降に更新してください。CMS やプラグインの更新では修正されません。PHP を組み込んだアプライアンスには、ベンダーのホットフィックスが必要です。

**影響範囲：** 上記より前の PHP 8.2～8.5 系。**公開日：** 2026-10-20 頃（今回の対象期間より前ですが、悪用が続いているため掲載）。

## 14. CVE-2026-19868 — SonicWall SonicOS SSL-VPN の MFA バイパス（参考）

**原理・根本原因：** 有効な認証情報を持つユーザーが別の認証方式でサインインすると、SAML で強制している MFA の要件を回避できます（代替経路による認証の弱体化）。

**影響範囲：** SonicWall SonicOS SSL-VPN（バージョンはアドバイザリを参照）。**状況：** 2026-11-06 に CISA KEV に追加。
