## 1. CVE-2026-83548・CVE-2026-83549 — SonicWall SMA1000 連鎖型SSRF+コマンドインジェクション(ゼロデイ)

**原理・根本原因:** CVE-2026-83548は、SMA1000の「Work Place」Webインターフェースにおける認証前SSRF(サーバーサイドリクエストフォージェリ)で、リモートの未認証リクエストが本来直接到達すべきでない内部機能に到達できます。CVE-2026-83549は、Appliance Management Consoleにおけるコマンドインジェクションの欠陥で、単体では認証済み管理者権限が必要です。この2つを連鎖させることで、SSRFを介して間接的にコマンドインジェクション経路をトリガーし、未認証の攻撃者がアプライアンス上でリモートコード実行を達成できます。

**対応(緩和策):**
- SonicWallのホットフィックス(12.4.3-03526、12.5.0-02952、またはそれ以降)を直ちに適用する。
- 未パッチでインターネットに公開されたSMA1000アプライアンスは最優先のインシデントとして扱う。SonicWall・CISAともに即時対応を求めている。

**対象:** SonicWall SMA1000シリーズアプライアンス(6210、7210、8200v)。2026-09-01にSonicWallアドバイザリSNWLID-2026-0016で開示。ゼロデイとして実悪用が確認されており、2026-09-02にCISA KEVへ追加。

## 2. CVE-2026-9586 — Sangoma Switchvox 未認証SQLインジェクションからRCEへ

**原理・根本原因:** 未認証のWebエンドポイント(`/pa`)がXML形式のリクエストボディを解析し、ユーザーが制御可能な`PhoneIP`フィールドをサニタイズやパラメータ化を行わずに背後のPostgreSQLクエリへ直接組み込みます(SQLインジェクション、CWE-89)。注入されたSQLはPostgreSQLのスーパーユーザー権限で実行され、さらにホスト上でのOSコマンド実行にも悪用されます。

**対応(緩和策):**
- Switchvox 8.4.0.2以降へアップグレードする。修正版は2026-07-14から提供されているが、適用が進んでいない。
- Switchvoxの管理インターフェースのネットワーク露出を制限し、予期しないリバースシェルやプロセス列挙の兆候を監視する。

**対象:** Switchvox SMB Edition 8.3(ビルド104997)以前。2026-08-30に大規模な悪用が開始(攻撃者はリバースシェルを展開)。2026-09-02にCISA KEVへ追加。悪用開始時点でインターネットに露出した未パッチのインスタンスは約4,000件と推定される。

## 3. CVE-2026-49869 — Kestra OSS 未認証コマンドインジェクション

**原理・根本原因:** Kestraの認証フィルタは、リクエストパスが`/configs`で「終わる」かどうかのみをチェックし、完全一致では検証していません。そのため、細工したリクエストパスによって認証フィルタを回避し、認証情報なしでワークフロー作成APIへ到達できます。悪意あるワークフロー定義はデフォルトのスクリプト実行プラグインを呼び出すことができ、ワーカーコンテナ内でroot権限によるコード実行につながります。

**対応(緩和策):**
- Kestra 1.0.45または1.3.21(あるいはそれ以降)へアップグレードする。
- パッチ適用までは、Kestra APIのネットワーク露出を信頼できるネットワークに限定する。

**対象:** 修正版より前のバージョンのKestra OSSワークフローオーケストレーションプラットフォーム。実悪用が確認されており、2026-09-02にCISA KEVへ追加。

## 4. CVE-2026-59822 — BerriAI LiteLLM MCP認証バイパス

**原理・根本原因:** LiteLLMのMCP(Model Context Protocol)Streamable HTTPエンドポイントは、偽装された`Authorization`ヘッダーを受け入れます。キー検証が失敗した場合に「OAuth2パススルーフォールバック」というコードパスへ移行し、リクエストを拒否する代わりに空・匿名の認証オブジェクトに置き換えてしまいます。その結果、未認証の呼び出し元がMCPツール群、さらにはそれらツールが接続する背後のサービスに到達できます。

**対応(緩和策):**
- LiteLLMをバージョン1.84.0以降へアップグレードする。
- MCPツール呼び出しのログを確認し、未認証や異常なセッションがないか監査する。

**対象:** 1.84.0より前のLiteLLM AIゲートウェイの導入環境。実悪用が確認されており、2026-09-02にCISA KEVへ追加。AIインフラ関連ツールにおける実悪用中の脆弱性として注目される。

## 5. CVE-2026-48710 — Starlette(Python ASGIフレームワーク)リクエスト/レスポンス密輸

**原理・根本原因:** Starletteは`request.url`を、実際にリクエストがルーティングされたパスと照合せずに、生の`Host`ヘッダーから再構築します。低レベルのルーティングは実際のHTTPパスを使用する一方、アプリケーションコードは再構築された`request.url.path`を信頼することが多いため、細工した`Host`ヘッダーによって両者の認識が食い違い、リクエストスマグリングや、再構築されたURLに基づいてアクセス制御を行うアプリケーションにおける認証バイパスにつながる可能性があります。

**対応(緩和策):**
- Starletteをバージョン1.0.1以降へアップグレードする。
- 多層防御として、リバースプロキシ・エッジ層で`Host`ヘッダーを検証・正規化する。

**対象:** 1.0.1より前のStarletteを基盤とするアプリケーション(内部でStarletteを利用する多くのFastAPI環境を含む。ピン留めされたStarletteのバージョンを確認すること)。CVSSは中程度だが実悪用が確認されており、2026-09-02にCISA KEVへ追加。

## 6. CVE-2026-20212 — Cisco Nexus 9000 未認証root権限RCE

**原理・根本原因:** Silicon One ASICを搭載したNexus 9000スイッチでは、内部サービスが制限のないIPアドレスにバインドされており、デフォルトのL3 VRF内でTCPポート43210/43211へ到達可能な状態になっています。このサービスへのアクセスに資格情報は不要で、細工した入力を送信するとroot権限で処理されます。同じ露出は、基盤となるプロセスをクラッシュさせデバイスの再起動を強制する(サービス拒否)ことにも悪用可能です。

**対応(緩和策):**
- Ciscoアドバイザリcisco-sa-n9k-s1-rce-EH8dEtrで示された修正済みNX-OSリリースへアップグレードする。
- 暫定対応として、スイッチ管理アドレス宛のTCPポート43210/43211への受信を拒否するインフラストラクチャACL(iACL)を適用する。

**対象:** 修正済みNX-OSリリースより前の、Silicon One ASICを搭載したNexus 9000スイッチ。2026-09-02開示。Cisco PSIRTは開示時点で既知の公開悪用はないと報告しているが、予防的なパッチ適用が推奨される。

## 7. CVE-2026-62911 — Microsoft Exchange Server キャプチャ・リプレイによる認証バイパス

**原理・根本原因:** インターネットから到達可能なMRSProxyエンドポイントが、Extended Protection for Authenticationを適切に強制していません(CWE-294、キャプチャ・リプレイによる認証バイパス)。Exchangeマシンアカウントに関連するNTLM認証情報を(リレーや強制認証技術などによって)取得できた攻撃者は、その情報をExchangeに対してリプレイすることで、既に認証済みの昇格された権限を持つアイデンティティとして扱われる可能性があります。

**対応(緩和策):**
- 対象Exchangeバージョン向けに提供された最新の累積更新プログラムに含まれるMicrosoftの修正を適用する。
- Extended Protection for Authenticationを有効化し、MRSProxy/EWS関連エンドポイントのインターネット露出を制限する。

**対象:** Exchange Server 2016 CU23、Exchange Server 2019 CU14/CU15、Exchange Server Subscription Edition RTM。公開されたエクスプロイトコードが存在し、インターネット上での大規模スキャンが進行中。2026-08-31時点で約21,900件のユニークIPが依然として脆弱・露出状態にあると報告されている。本レポート作成時点ではCISA KEVへの掲載は未確認だが、近く追加される可能性が高く、緊急対応が推奨される(CVSSベクトルは二次情報源による裏付けであり、可能な限りMicrosoft公式アドバイザリでの確認が望ましい)。

**対象:** 7.161.20より前のセルフホスト型JFrog Artifactory(SaaS/クラウドホスト型Artifactoryは対象外)。既にCISA KEVに掲載済み。

## 9. CVE-2026-19949 — All-in-One WP Migration and Backup(WordPressプラグイン) 二次的SQLインジェクション

**原理・根本原因:** サイトのエクスポート・インポート時にデータベース内容を書き換えるアーカイブ復元処理において、エスケープされたバックスラッシュや引用符の解析が誤っています。未認証の攻撃者はWordPressのトラックバックを介して細工したデータを仕込むことができ、それは管理者が通常のエクスポート・インポート操作を行うまで潜伏します。その時点で、注入されたSQLによってプラグインの秘密インポートキーが公開コメント経由で露出する可能性があります。このキーを使うことで、攻撃者は実行可能コードを含む悪意ある`.wpress`アーカイブをインポートさせ、サイトの完全な乗っ取りにつながります。潜伏後に発動する二次的(格納型・遅延トリガー型)SQLインジェクションの連鎖です。

**対応(緩和策):**
- バージョン7.110以降へ直ちに更新する。
- 直ちに更新できないサイトは、トラックバック・ピンバックを無効化し、予期しないエクスポート・インポート操作を監視する。

**対象:** All-in-One WP Migration and Backup、バージョン7.109以前(有効インストール数500万以上)。修正版は2026-08-20にリリース、2026-09-02にWordfenceが詳細を公開。2026-09-03時点で更新済みは約35%にとどまり、推定325万サイトが露出している。実悪用の確認報告は現時点でないが、パッチの提供状況と適用率の乖離から、近い将来の標的となる可能性が高い。

## 11. CVE-2026-72529・CVE-2026-72530 — TrueConf Server(本日が連邦機関対応期限)

**原理・根本原因:** CVE-2026-72529は、TCP/4307上で文書化されていない機能を公開しており、未認証のリモート攻撃者が資格情報なしに任意のスクリプトを実行できます。CVE-2026-72530は、TrueConfのサンドボックス化・分離された実行環境内でコード実行に成功した攻撃者が、そのサンドボックスを脱出し、システム権限でホストOS上の任意コマンドを実行できるというものです。この2つは通常、連鎖させてホストの完全な侵害に用いられます。

**対応(緩和策):** TrueConf Server 5.3.9、5.4.9、5.5.5、またはそれ以降(2026年6月に修正版がリリース済み)へ更新する。

**対象:** 上記修正版より前の、2022年以降の全バージョンのTrueConf Server。ハクティビストグループ「Head Mare」による実悪用が2026年7月以降少なくとも確認されている(悪意あるクライアントインストーラーの差し替え・バックドア展開)。2026年8月下旬にCISA KEVへ追加。より深刻なCVE-2026-72529に対する連邦機関の対応期限は本日2026-09-03であり、初回開示時期は今週の対象期間より前であるものの、この理由から本レポートに含めています。
