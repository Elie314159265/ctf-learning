## 1. CVE-2026-0768 — Langflow 未認証RCE

**原理・根本原因:** Langflowのカスタムコンポーネントエディタには、ユーザー提供のPythonコードを実行前に制限するためのコード検証ステップがあります。この検証機構は、送信された「コンポーネント」定義が実行できる範囲を十分に制限していないため、悪意あるコンポーネントが想定された制約を回避し、未認証のままサーバープロセスのコンテキストで任意のPythonコードを実行できます。

**対応(緩和策):**
- Langflowをベンダーの修正済みリリースに更新する。
- Langflowの管理・API画面をインターネットに直接公開しない。認証やネットワークレベルのアクセス制御(VPN、IP許可リスト)の背後に置く。
- 未パッチでインターネットに公開されていたインスタンスは侵害された可能性があるものとして扱う。Langflowプロセスからアクセス可能なシークレット・環境変数をローテーションし、見覚えのない送信元からのコンポーネント作成・実行リクエストがないかログを確認する。

**対象:** ベンダー修正版より前のバージョンを使用する、セルフホスト型Langflowの導入環境。脅威インテリジェンスのテレメトリでは、環境変数、Langflowのスーパーユーザー資格情報、AWSシークレット、OpenAI APIキーを狙った、大量のスキャン・悪用試行の再燃(主にロシア関連インフラを起点とする)が2026-09-02時点で報告されています。

## 2. CVE-2026-66066 — Ruby on Rails Active Storage: 任意ファイル読み取り → RCE

**原理・根本原因:** Active Storageが画像バリアントを生成する際にlibvips画像処理ライブラリを使用する構成では、アップロードされたファイルが、一部のレガシー・「未ファジング(unfuzzed)」なファイル形式ローダーを無効化しないままlibvipsに渡されます。悪意ある形式で構成されたアップロードファイルは、Rails/libvips/libmatio/HDF5の処理チェーン全体にわたるフォーマット混同を悪用でき、バリアント生成時にサーバーが本来アクセスすべきでないファイル内容(`secret_key_base`など、サービスの資格情報を含むプロセスの環境変数データを含む)を読み取って返してしまいます。`secret_key_base`はRailsの署名付き・暗号化されたクッキーの基盤であるため、これが漏洩すると信頼された直列化データの偽造が可能になり、さらに遠隔コード実行へと段階的にエスカレートできます。

**対応(緩和策):**
- Rails/Active Storageをベンダーの修正済みバージョンに更新し、libvipsも未ファジングローダーを無効化できるリリースに更新する。
- パッチ適用後もシークレット漏洩イベントとして扱う。`secret_key_base`、Railsマスターキーおよびそれで復号される資格情報、データベース資格情報、ストレージサービスの資格情報、影響を受けるプロセスからアクセス可能な外部API トークンをローテーションする。
- 異常なアップロード・バリアント生成リクエストや、偽造クッキーと一致するセッション活動がないかログを確認する。

**対象:** デフォルト構成でActive Storageとlibvipsによる画像バリアント生成を使用する、ベンダー修正版より前のRuby on Railsアプリケーション。2026-09-01/02時点の報告では、この不具合が上記Langflowの問題と(スタックは異なるが同一キャンペーン内で)連鎖して利用される、便乗的なスキャンが確認されています。

## 3. CVE-2026-82329 — JFrog Artifactory 認証バイパス → 管理者権限の乗っ取り

**原理・根本原因:** セルフホスト型JFrog Artifactoryの認証処理に関する不具合(不適切な認証、CWE-287)により、ネットワークアクセスを持つ未認証の攻撃者が、デフォルト構成下で管理者権限のアクセストークンを取得できます。事実上、本人確認を一切行わずに有効な管理者資格情報を自ら発行できることになります。Artifactoryはビルド成果物、パッケージリポジトリ、資格情報にアクセス可能なCI/CDパイプライン内に組み込まれることが多いため、管理者レベルの侵害はソフトウェアサプライチェーンへの直接的な侵入経路になります。

**対応(緩和策):**
- セルフホスト型Artifactoryをパッチ済みリリース(7.161.20以降)にアップグレードする。
- JFrogのSaaS/クラウドホスト型Artifactoryサービスは影響を受けません(セルフホストのインスタンスのみが対象)。
- パッチ適用後、公開時期前後に作成された想定外の管理者ユーザー・APIトークンがないか確認し、侵害が疑われる場合はすべてのArtifactoryトークンおよびプラットフォームがアクセス可能だった資格情報・アーティファクトをローテーションする。
- 多層防御として、Artifactoryの管理インターフェースへのネットワークアクセスを信頼できるネットワークに制限する。

**対象:** 修正版より前の複数の7.x系リリースを使用する、セルフホスト型JFrog Artifactory。現在の報告によれば、開示から数日以内に悪用が始まり、2026-09-01/02まで継続しています。

## 4. CVE-2026-81578 & CVE-2026-82078 — PaperCut NG/MF 未認証RCEチェーン(3回目の緊急パッチ)

**原理・根本原因:** PaperCut NG/MFのWeb管理インターフェースにおける2つの連鎖する不具合:
- **CVE-2026-81578**(認証バイパス):特殊に加工された未認証のリクエストにより、アクセス制御チェックが完了する前に管理バックエンドの操作をトリガーでき、攻撃者は資格情報なしでシステム構成を変更できます。
- **CVE-2026-82078**(安全でない動的クラスロード):設定可能なデータベースドライバ名が十分な検証なしにクラスのインスタンス化に使用されるため、(上記の不具合を通じて)この設定に影響を与えられる攻撃者は、クラスパス上に既に存在する攻撃者が選んだクラスを指定でき、任意コード実行を実現できます。
これらを連鎖させることで、未認証の攻撃者が完全な未認証リモートコード実行を達成できます。

**今回の新情報:** PaperCutは2026-09-01に3回目の緊急パッチ(「Release 3」)を公開しました。これは以前の2つの緊急パッチを置き換えるもので、それらが引き起こした2つの回帰(SAMLログインフローの破損、外部カード検索に使用するレガシーMicrosoft SQL Serverドライバのサポート失効)を修正し、関連する攻撃チェーンに対する追加的な強化策を加えています。

**対応(緩和策):**
- 既に以前の緊急パッチを適用済みであってもRelease 3を導入する。これは累積的な修正であり、以前のパッチが事前に適用されていることを前提としません。
- パッチ適用まではPaperCutのWebインターフェースを信頼できる内部ネットワークのみに制限し、インターネットに直接公開しない。
- この脆弱性チェーンはCISAの既知悪用脆弱性(KEV)カタログに掲載されています。未パッチでインターネットに公開されたインスタンスは優先度の高いインシデントとして扱ってください。

**対象:** PaperCut NGおよびPaperCut MF、メジャーバージョン24、25、26。

## 5. CVE-2026-84802 — Craft CMS 情報漏洩

**原理・根本原因:** Craft CMSのコントロールパネルにある`AssetsController::actionMoveInfo`エンドポイントは、ボリューム(アセットストレージ)単位の権限を正しく適用していません。認証済みのコントロールパネルユーザーが、本来アクセスできないはずのボリュームに関する情報(アセット数、ストレージ総容量)を照会できます。

**対応(緩和策):** Craft CMSをバージョン5.10.12以降に更新する。

**対象:** Craft CMSのバージョン5.7.0以上、5.10.12未満。CVSS 4.3(Medium)— 認証済みで低権限のコントロールパネルアカウントが必要であり、アセットの内容ではなくメタデータのみが漏洩します。

## 7. CVE-2026-8452 — Citrix NetScaler ADC/Gateway: SAML解析オーバーフロー → RCE(実悪用中、CISA KEV掲載)

**原理・根本原因:** NetScalerのAAAサービスにおけるSAMLシングルサインオンメッセージを解析するコード内の、未認証で到達可能なヒープメモリオーバーフロー(CVSS v4.0 8.8)です。Citrixは当初2026-06-30にこの不具合を開示し、サービス拒否(DoS)にしか至らない問題として説明していました。しかし8月中旬、研究者らが同じオーバーフローを単なるクラッシュではなく未認証の遠隔コード実行に発展させられることを実証しました。脆弱なコードへの到達には資格情報もユーザー操作も不要です。

**今週の新情報:** RCEに関する研究成果の公開に続き、実際の悪用が確認され、防御側は侵害されたアプライアンス上で攻撃者がWebシェルを設置し、基本的な調査コマンド(例:`id`、`echo`)を実行している様子を観測しています。CISAはこの不具合を既知悪用脆弱性(KEV)カタログに追加し、連邦機関に対して2026-08-29を対応期限としました。

**対応(緩和策):**
- 修正を含むビルド(14.1-73.32以降、または13.1-63.21以降。対応するFIPS/NDcPPビルドを含む)に更新する。
- この問題は6月時点でDoS限定の問題としてパッチ済みとされていたため、6月の当初の勧告のバージョンだけでなく、RCEに至るオーバーフローを具体的に対処したビルドであることを確認する。
- アプライアンスがインターネットに公開されていて未パッチだった場合は、想定外のWebシェル・スクリプトや見覚えのない管理操作がないか、ファイルシステムとログを確認する。

**対象:** 上記バージョンより前のビルドのCitrix NetScaler ADCおよびNetScaler Gateway。

## 8. WordPressプラグイン/テーマの一群 — サイト乗っ取り・RCEに至る5つのCritical脆弱性(2026-08-27〜08-29開示)

**8a. CVE-2026-82222 — GiveWP寄付プラグイン:未認証PHPオブジェクトインジェクション → RCE(CVSS 10.0)。** GiveWPは、寄付ワークフロー中に取得された信頼できない、攻撃者が影響を及ぼせるデータを、十分な検証なしにデシリアライズします。安全でないデシリアライズ用ヘルパー、攻撃者が制御可能な直列化データを保存する寄付処理パス、バンドルされたライブラリ内に既に存在する「ガジェットチェーン」を連鎖させることで、未認証の攻撃者が任意のコマンド実行を達成できます。公開済みの寄付フォームと有効な決済ゲートウェイが必要です。4.16.7.2で修正済み。4.16.7.1以下が対象。

**8b. CVE-2026-18431 — Avadaテーマ + Fusion Builder:未認証の任意ファイル書き込み → RCE(CVSS 9.8)。** AvadaテーマとバンドルされたFusion Builderプラグインにわたる、権限チェック欠落(CWE-862)と入力検証の弱点の連鎖により、未認証の訪問者が攻撃者制御下のPHPファイルをサーバーに書き込める(操作を必要としない「ゼロクリック」攻撃)ため、完全なコード実行につながります。AvadaとFusion Builderの両方が有効であること、および特定の管理者作成コンテンツが存在することが条件です。Fusion Builder 3.16.1を伴うAvada 7.16.1で修正済み(両方を同時に更新する必要があります)。Avada 7.16以下 / Fusion Builder 3.16以下が対象。

## 9. WatchGuard Fireware OS — `iked`における未認証遠隔コード実行(3件のCritical CVE)

**原理・根本原因:** WatchGuard Fireboxアプライアンス上でIPsec VPNのネゴシエーション(IKEv1/IKEv2)を処理するInternet Key Exchangeデーモン`iked`における、3件のCritical・未認証遠隔から到達可能な不具合です:ヒープバッファオーバーフロー(CVE-2026-19313)、スタックベースのバッファオーバーフロー(CVE-2026-19318)、型混同の不具合(CVE-2026-19315)。いずれも認証が行われる前にIKEサービスへ送信された特殊に加工されたネットワークトラフィックによってトリガーされ、アプライアンス上での遠隔コード実行につながる可能性があります。

**対応(緩和策):** Fireware OS 2026.2.2、12.12.2、または12.5.20(およびDimension 2.3.1)以降に更新する。即時パッチが不可能な場合は、IKE/VPNサービスへの露出を、それを必要とするピアのみに制限する。

**対象:** 上記の修正済みリリースより前のバージョンのFireware OSを実行するWatchGuard Fireboxアプライアンス。3件すべてCVSS 9.3(Critical)。WatchGuardは開示時点で実悪用は確認していないとしています。

## 10. Google Chrome 152 — Critical Use-After-Free脆弱性

**原理・根本原因:** 2件のCritical重大度のuse-after-free不具合 — **CVE-2026-84353**(Shared Tab Groups)および**CVE-2026-84352**(WebGL)— は、既に解放されたメモリへ、解放後もブラウザがアクセスを継続してしまう問題です。攻撃者がその解放済みメモリに何が配置されるかを制御できる場合(例:悪意あるWebページ経由)、この種の不具合はメモリ破壊を招き、最悪の場合はブラウザのサンドボックス外でのコード実行につながる可能性があります。

**対応(緩和策):** Chromeをバージョン152.0.7977.64/.65(Windows/macOS)または152.0.7977.64(Linux)以降に更新する。ブラウザは通常自動更新されますが、適用には再起動が必要です。

**対象:** 上記バージョンより前のすべてのプラットフォームのGoogle Chrome。Chrome 152(2026-08-25リリース)では合計327件の脆弱性(Critical 10件を含む)が修正されました。Googleはこれらの不具合に対する実悪用の証拠を開示していないほか、大多数のユーザーが更新を完了するまで技術的詳細を非公開としています。

## 11. Mozilla Firefox 155 / Thunderbird 155 — 複数のHigh重大度脆弱性

**原理・根本原因:** Firefox 155(2026-09-01リリース)は、High重大度と評価されたものを含む約29件のセキュリティ上の不具合を修正しています。その中で、**CVE-2026-84121**および**CVE-2026-84119**は、それぞれDOM SecurityコンポーネントとDOM Navigationコンポーネントにおけるuse-after-free不具合で、Mozillaはサンドボックスエスケープを可能にする可能性があると分類しています。つまり、ブラウザの制限されたコンテンツプロセスのサンドボックス内で動作するコードが、別のエスケープ用プリミティブと組み合わされることで、ホストシステムへのより広範なアクセスを得る可能性があります。残りの修正は、通常のブラウザセキュリティ更新に典型的な、さらなるメモリ破壊やロジックの問題を対象としています。

**対応(緩和策):** Firefoxをバージョン155(または対応するESR系列:115.40、140.15、153.2)に、Thunderbirdをバージョン155(またはESR 140.15 / 153.2)に更新する。

**対象:** 上記バージョンより前のMozilla FirefoxおよびThunderbird。Mozillaはこれらの問題に対する実悪用は報告していません。

## 12. CISA KEVまとめ — 新たに実悪用が確認された既存の古い脆弱性

CISAは2026-08-26頃、新たな開示ではなく、実際に悪用されているという新たな証拠に基づき、既知悪用脆弱性カタログに6件を追加しました。対象の不具合自体は古いものですが、KEVの変化を追っている防御側向けに以下に記載します:

- **CVE-2019-1068** — Database Engineサービスを介したMicrosoft SQL Server RCE。
- **CVE-2022-0995** — ローカル権限昇格・DoSを可能にするLinuxカーネルの範囲外書き込み。
- **CVE-2026-21962** — Oracle HTTP ServerおよびWebLogic Server Proxy Plug-inにおける不適切なアクセス制御。
- **CVE-2015-3246** — Red Hat `libuser`の競合状態(レースコンディション)。
- **CVE-2015-5287** — Red Hat Automatic Bug Reporting Tool(ABRT)の権限昇格。
- **CVE-2026-8452** — Citrix NetScaler(上記項目7を参照。このKEV追加分にも含まれます)。

**対応(緩和策):** 未適用であれば各CVEに対応するベンダーパッチを適用する。数十年前のRed HatおよびMicrosoftの不具合については、新規の修正が必要というよりも、レガシーなパッチサイクルで対応漏れがなかったかを確認することが中心になります。
