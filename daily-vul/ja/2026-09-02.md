## 1. CVE-2026-0768 — Langflow 未認証リモートコード実行（RCE）

**原理・根本原因:** Langflow のカスタムコンポーネントエディタには、ユーザーが入力した Python コードを実行前に制限するためのコード検証機能がある。この検証処理が、送信された「コンポーネント」定義の挙動を十分に制限できていないため、細工したコンポーネント定義によって想定された制約を回避し、認証なしにサーバープロセス上で任意の Python コードが実行されてしまう。

**対策（ミティゲーション）:**
- Langflow をベンダーが提供する修正版に更新する。
- Langflow の管理／API インターフェースをインターネットに直接公開しない。認証および VPN やIP許可リストなどのネットワークレベルのアクセス制御の背後に置く。
- 未パッチのインターネット公開インスタンスは侵害されている可能性があるものとして扱う。Langflow プロセスからアクセス可能なシークレット・環境変数をローテーションし、コンポーネントの作成・実行に関する不審なアクセス元からのリクエストがないかログを確認する。

**影響を受ける対象:** ベンダー修正版より前のバージョンのセルフホスト型 Langflow デプロイ。脅威インテリジェンスの観測では、環境変数、Langflow のスーパーユーザー認証情報、AWS シークレット、OpenAI API キーを狙った大規模なスキャン・悪用の再燃が報告されており（主にロシア関連インフラを発信元とする）、2026-09-02時点でも報告が継続している。

## 2. CVE-2026-66066 — Ruby on Rails Active Storage: 任意ファイル読み取り → RCE

**原理・根本原因:** Active Storage が画像バリアント生成に libvips を使用する際、アップロードされたファイルが特定のレガシー／「unfuzzed」形式ローダーを無効化しないまま libvips に渡されている。細工したアップロードファイルにより、Rails/libvips/libmatio/HDF5 の処理チェーンにまたがるフォーマット混同を悪用でき、バリアント生成時に本来アクセスできないはずのファイル内容（`secret_key_base` などのシークレットを含むプロセス環境情報を含む）をサーバーが読み取って返してしまう。`secret_key_base` は Rails の署名付き・暗号化された Cookie の基盤となるため、これが漏洩すると信頼されたシリアライズデータの偽造が可能になり、さらにリモートコード実行にまでエスカレーションし得る。

**対策（ミティゲーション）:**
- Rails/Active Storage をベンダー修正版に、libvips を unfuzzed ローダーの無効化に対応したバージョンに更新する。
- パッチ適用後もシークレット漏洩インシデントとして扱う: `secret_key_base`、Rails マスターキーおよびそれで復号される認証情報、データベース認証情報、ストレージサービス認証情報、影響を受けたプロセスからアクセス可能なサードパーティ API トークンをすべてローテーションする。
- 不審なアップロード・バリアント生成リクエストや、偽造 Cookie に一致するセッション挙動がないかログを監査する。

**影響を受ける対象:** デフォルト構成で Active Storage と libvips による画像バリアント生成を使用している、ベンダー修正版より前のバージョンの Ruby on Rails アプリケーション。2026-09-01/02 の報告では、本脆弱性が上記の Langflow の脆弱性と組み合わせて日和見的にスキャンされている（同一キャンペーン内で異なるスタックを狙ったもの）とされている。

## 3. CVE-2026-82329 — JFrog Artifactory 認証バイパス → 管理者権限奪取

**原理・根本原因:** セルフホスト型 JFrog Artifactory の認証処理の不備（不適切な認証、CWE-287）により、デフォルト構成下でネットワークアクセス可能な未認証の攻撃者が管理者スコープのアクセストークンを取得できてしまう。実質的には、本人確認を一切行うことなく有効な管理者権限相当の認証情報を自ら生成できてしまう状態である。Artifactory は CI/CD パイプライン内でビルド成果物・パッケージリポジトリ・認証情報にアクセスできる位置に置かれることが多いため、管理者権限の奪取はソフトウェアサプライチェーンへの直接的な侵入経路となる。

**対策（ミティゲーション）:**
- セルフホスト型 Artifactory を修正版（7.161.20 以降）にアップグレードする。
- JFrog の SaaS／クラウドホスト版 Artifactory は影響を受けない（セルフホストインスタンスのみが対象）。
- パッチ適用後、開示時期の前後に作成された不審な管理者ユーザーや API トークンがないか監査し、侵害が疑われる場合は Artifactory の全トークンおよびプラットフォームがアクセスできたすべての認証情報・成果物をローテーションする。
- 多層防御として、Artifactory の管理インターフェースへのネットワークアクセスを信頼できるネットワークに制限する。

**影響を受ける対象:** 修正版より前の複数の 7.x 系セルフホスト型 JFrog Artifactory。現時点の報告によれば、開示から数日で悪用が始まり、2026-09-01 時点でも継続している。

## 4. CVE-2026-81578 / CVE-2026-82078 — PaperCut NG/MF 事前認証RCEチェーン（3回目の緊急パッチ）

**原理・根本原因:** PaperCut NG/MF の Web 管理インターフェースにおける2つの連鎖する脆弱性:
- **CVE-2026-81578**（認証バイパス）: 細工した未認証リクエストにより、アクセス制御チェックが完了する前に管理系バックエンド処理がトリガーされ、攻撃者が認証情報なしにシステム設定を変更できる。
- **CVE-2026-82078**（安全でない動的クラスロード）: 設定可能なデータベースドライバ名を十分な検証なしにクラスのインスタンス化に使用しているため、上記の脆弱性で当該設定に影響を与えられる攻撃者は、クラスパス上に存在する任意のクラスを指定させ、任意コード実行を達成できる。
これら2つを連鎖させることで、未認証の攻撃者による完全な事前認証リモートコード実行が可能になる。

**本日の新情報:** PaperCut は 2026-09-01 に3回目の緊急パッチ（「Release 3」）を公開した。これは過去2回の緊急パッチを置き換えるもので、それらが引き起こした2件の不具合（SAML ログインフローの破損、外部カード照会で使用するレガシー Microsoft SQL Server ドライバのサポート喪失）を修正し、関連する攻撃チェーンへの追加的な緩和策も含む。

**対策（ミティゲーション）:**
- 過去の緊急パッチを既に適用済みであっても Release 3 を適用する。累積パッチであるため、以前のパッチを先に適用しておく必要はない。
- パッチ適用まではPaperCutのWebインターフェースを信頼できる内部ネットワークのみに制限し、インターネットに直接公開しない。
- 本脆弱性チェーンは CISA の Known Exploited Vulnerabilities カタログに掲載されている。未パッチでインターネットに公開されているインスタンスは最優先のインシデントとして扱う。

**影響を受ける対象:** PaperCut NG および PaperCut MF のメジャーバージョン 24、25、26。

## 5. CVE-2026-84802 — Craft CMS 情報開示

**原理・根本原因:** Craft CMS の管理画面（コントロールパネル）にある `AssetsController::actionMoveInfo` エンドポイントが、ボリューム（アセットストレージ）単位の権限を正しく検証していない。認証済みのコントロールパネルユーザーは、本来アクセス権限を持たないボリュームに関する情報（アセット数、合計ストレージ容量）を取得できてしまう。

**対策（ミティゲーション）:** Craft CMS をバージョン 5.10.12 以降に更新する。

**影響を受ける対象:** Craft CMS のバージョン 5.7.0 以上 5.10.12 未満。CVSS 4.3（Medium）— 認証済みかつ低権限のコントロールパネルアカウントが前提であり、開示されるのはアセットの中身ではなくメタデータである。

## 6. CVE-2026-84780 — WP Go Maps 未認証サービス拒否（DoS）

**原理・根本原因:** CWE-770（リソース割り当てに対する制限・スロットリングの欠如）に分類される。認証なしでアクセス可能なプラグインのエンドポイントに対し、サーバーリソースを過剰に消費させることが可能で、未認証かつ低コストなリモートリクエストによってサイトの性能低下やダウンを引き起こし得る。

**対策（ミティゲーション）:** WP Go Maps（旧称 WP Google Maps）プラグインを WordPress プラグインリポジトリ経由でベンダー修正版に更新する。

**影響を受ける対象:** WordPress 用 WP Go Maps プラグインのバージョン 10.1.08 以下。CVSS 5.3（Medium）— ネットワーク経由の攻撃ベクトル、低い攻撃複雑度、権限・ユーザー操作不要。

## 7. Google Chrome 152 — Critical な Use-After-Free 脆弱性

**原理・根本原因:** 重大度 Critical の Use-After-Free（解放済みメモリの使用）バグが2件 — **CVE-2026-84353**（Shared Tab Groups）と **CVE-2026-84352**（WebGL） — 修正された。これは、解放済みのメモリ領域にブラウザが引き続きアクセスしてしまうという種類の不具合である。攻撃者が解放後のメモリ領域に配置される内容を制御できる場合（例えば細工した Web ページ経由）、この種のバグはメモリ破壊、最悪の場合はブラウザのサンドボックス外でのコード実行につながり得る。

**対策（ミティゲーション）:** Chrome をバージョン 152.0.7977.75/.76（Windows/macOS）または 152.0.7977.75（Linux/Android）以降に更新する。ブラウザは通常自動更新されるが、適用には再起動が必要。

**影響を受ける対象:** バージョン 152.0.7977.75 より前のすべてのプラットフォームの Google Chrome。今回のリリースでは重大度の低い他の24件の問題も修正されている。Google はいずれの Critical な脆弱性についても悪用の証拠は開示しておらず、大多数のユーザーが更新を適用するまで技術的詳細を非公開としている。

## 8. Mozilla Firefox 155 / Thunderbird 155 — 複数の High 重大度の脆弱性

**原理・根本原因:** Firefox 155 では約29件のセキュリティ上の不具合が修正され、そのうち複数が重大度 High に分類されている。その中で **CVE-2026-84121** と **CVE-2026-84119** は（それぞれ DOM Security コンポーネントと DOM Navigation コンポーネントにおける）Use-After-Free バグであり、Mozilla はサンドボックスエスケープを可能にし得るものと分類している。すなわち、ブラウザの制限されたコンテンツプロセスのサンドボックス内で実行されるコードが、別のエスケープ用の手法と組み合わさることで、より広範なホストシステムへのアクセスを得る可能性がある。その他の修正は、通常のブラウザセキュリティ更新に典型的な、さらなるメモリ破壊やロジック上の問題に対応するものである。

**対策（ミティゲーション）:** Firefox をバージョン 155（または対応する ESR 系列: 115.40、140.15、153.2）に、Thunderbird をバージョン 155（または ESR 140.15 / 153.2）に更新する。

**影響を受ける対象:** 上記バージョンより前の Mozilla Firefox および Thunderbird。Mozilla はこれらの問題について実際の悪用は報告していない。
