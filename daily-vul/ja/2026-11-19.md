## 1. CVE-2026-123890 — VMware vCenter Server 認証回避（VMware Directory Service）

**原理・根本原因：** vCenter が使用する VMware Directory Service（vmdir）コンポーネントに、代替経路・チャネルによる認証回避（CWE-288）があります。vCenter にネットワーク到達できる攻撃者は、通常の認証チェックが適用されない経路を通じて特権機能に到達できます。vCenter が侵害されると、その管理下にある仮想基盤全体を制御されます。

**緩和策：**
- VMSA-2026-0009 の修正を適用する：vCenter **9.1.1.0200**、**9.0.2.0200**、**8.0 U3m**、VMware Cloud Foundation **5.2.5**。
- Broadcom はワークアラウンドを提示していないため、修正はパッチ適用のみです。適用までは vCenter 管理インターフェースへのネットワークアクセスを専用の管理ネットワークに限定してください。
- vCenter 7.0 の修正は延長サポート契約の顧客にのみ提供されます。Broadcom は vSphere 6.5/6.7 を影響ありと見なすよう案内しているため、移行を計画してください。
- アップグレード経路の注意：8.0 U3m または 9.0.2.0200 を適用すると、その後 VCF 9.1.1 へアップグレードできなくなります。Broadcom は先に 9.1.1 へ上げるか、VCF 9.1.2 を待つことを提案しています。
- ゼロデイの報告を踏まえ、少なくとも 2026年9月まで遡って、vCenter のログに想定外のログインやアカウントがないか確認してください。

**影響対象：** VMware vCenter Server 9.1.x、9.0.x、8.0、7.0（および EOL の 6.x）、VMware Cloud Foundation 5.x、Telco Cloud Infrastructure。**公開日：** 2026-11-19。**悪用状況：** 中国系グループが 2026年9月上旬からゼロデイとして悪用していたとの報告があります（Mandiant の分析とされる）。一方で「悪用は未確認」とする追跡サービスもあるため、悪用されている可能性が高いものとして扱い、Broadcom のアドバイザリを確認してください。

## 2. CVE-2026-90436 — Apache Axis 1.x の SOAP フォールト処理における安全でないリフレクション

**原理・根本原因：** 安全でないリフレクション（CWE-470）です。Axis 1.x は SOAP フォールトを処理する際、メッセージに含まれるクラス名のクラスをロードし、正当なフォールト型かどうかを確認する*前に*インスタンス化することがあります。そのため、認証なしのリクエストでクラスパス上の任意のクラスをサーバーにロードさせることができます。直接の影響はホストするアプリケーションが同梱するクラスに依存し、Confluence や N-central などの実製品ではリモートコード実行に至ります。

**緩和策：**
- Axis 1.x はサポート終了（EOL）しており、修正版 1.x のリリースは見込まれていません。保守されている SOAP スタック（例：Apache Axis2/Java）へ移行するか、1.x を使い続ける必要がある場合は上流の修正コミットを適用してください。
- **Atlassian Confluence Data Center：** **9.2.28** 以降へアップグレードする（10.x は影響なし）。すぐにアップグレードできない場合は Remote API を無効化する。
- **N-able N-central：** ベンダーの修正版を適用する。
- `axis-1.x.jar` を同梱する Java アプリケーションを棚卸しする。

**影響対象：** Apache Axis 1.4 以下（1.x 全系列）、Remote API が有効な Confluence Data Center 1.x〜9.x、N-able N-central。**公開・KEV：** 2026-11-18 に CISA KEV へ追加。Rapid7 が悪用を観測しています。公開 PoC が存在します。

## 3. CVE-2026-90817 — REDCap の認証不要コードインジェクション

**原理・根本原因：** REDCap のアンケートのパススルー経路と Data Import ロジックにあるコードインジェクション（CWE-94、およびファイル名・パスの外部制御 CWE-73）です。攻撃者はアカウントなしで、有効な*公開アンケート*のリンクさえあれば、攻撃者が影響を与えた入力をサーバー側のコードとして処理させられます。その結果、Web サーバー / PHP ユーザー権限でコードが実行されます。

**緩和策：**
- 使用ブランチの修正版 REDCap へアップグレードする。情報源では **16.0.49**、**17.3.10**、**17.4.4** 以降が挙げられています。Vanderbilt の REDCap コミュニティ告知で確認してください。
- REDCap には研究・臨床データが置かれていることが多いため、パッチ適用後にサーバー上の想定外のファイルや Web シェルを調査し、資格情報をローテーションしてください。
- パッチ適用までは、WAF や許可リストで公開アンケートのエンドポイントを制限することを検討してください。

**影響対象：** REDCap 13.3.0 以降、上記の修正ビルドより前のもの。**公開・KEV：** 2026-11-18 に CISA KEV へ追加（連邦機関の期限 2026-11-21）。

## 4. CVE-2026-40217 — LiteLLM カスタムコードガードレールのサンドボックス脱出

**原理・根本原因：** LiteLLM プロキシでは、管理者が制限付きサンドボックス内で動く「カスタムコード」ガードレールを定義できます。このサンドボックスは代替チャネル経由で脱出可能なため、ガードレール機能を通じて渡されたコードがプロキシプロセスの全権限で実行されます。研究者は、低権限の仮想キー保持者が管理者に昇格し（CVE-2026-47101）、その後本脆弱性で RCE に至る連鎖も報告しています。

**緩和策：**
- **1.83.11** 以降へアップグレードする。報告された連鎖全体を塞ぐには **v1.83.14-stable** 以降へアップグレードする。
- プロキシに保存されている上流 LLM プロバイダの API キー、マスターキー、仮想キーをローテーションする。
- ガードレールを作成・編集できるユーザーを制限し、既存のカスタムコードガードレールを監査する。

**影響対象：** BerriAI LiteLLM 1.81.8 以上 1.83.10/1.83.11 未満（GHSA-wxxx-gvqv-xp7p）。**KEV：** 2026-11-18 追加（連邦機関の期限 2026-12-02）。

## 6. CVE-2026-132165 — Drupal core インストーラ経由のサイト乗っ取り / RCE（SA-CORE-2026-017）

**原理・根本原因：** 一定の条件下では、インストール済みのサイトでも匿名ユーザーが Drupal のインストーラ（`core/install.php`）に到達して操作できます。これにより攻撃者は、自身が制御する設定でインストールを再実行してサイトを乗っ取り、さらにコードを実行できます。

## 7. CVE-2026-123007 — NGINX HTTP/2 フロー制御の整数アンダーフロー

**原理・根本原因：** NGINX の HTTP/2 フロー制御ウィンドウ計算における整数アンダーフロー（CWE-191）です。細工された一連の HTTP/2 通信でサイズカウンタがラップアラウンドし、その結果生じるワーカーのヒープ上の範囲外読み書きが、認証不要の RCE につながる可能性があります。Rapid7 によると、悪用には非常に大量の HTTP/2 トラフィック（約 128 GB）が必要で、ハードルは上がるもののリスクがなくなるわけではありません。該当コードは 1.9.5（2015年）まで遡ります。F5 は関連する HTTP/2 の不具合 CVE-2026-123633 も同時に修正しました。

**緩和策：**
- NGINX Open Source は **1.31.9**（mainline）または **1.30.7**（stable）へ、NGINX Plus は **R37.3.0.1** または **R37.0.8.1** へアップグレードする。Plus R34〜R36 には修正版が示されていないため、リリース系列をアップグレードする。
- 暫定策：HTTP/2 を無効化する（listen から `http2` を外す）。HTTP/1.1 のみのサーバーは影響を受けません。
- ディストリビューションのパッケージやコンテナイメージは対応待ちの可能性があるため、各ディストリビューションのアドバイザリを注視する。

**影響対象：** HTTP/2 が有効な NGINX OSS 1.9.5 以降（現行サポート系列では 1.30.7 未満の 1.30.x、1.31.9 未満の 1.31.x）、修正ビルドより前の NGINX Plus R34〜R37。**公開日：** 2026-11-18（F5 K000163926、Rapid7）。悪用は未確認。

## 8. CVE-2026-129448 — Apache Roller の認証不要 XML-RPC デシリアライゼーション

**原理・根本原因：** 信頼できないデータのデシリアライゼーション（CWE-502）です。Roller の XML-RPC エンドポイントは「ベンダー拡張」の値型を受け付け、呼び出し元を認証する*前に* Java オブジェクトへデシリアライズします。そのため、認証なしの攻撃者が任意オブジェクトのデシリアライズを引き起こし、RCE に至ります。CVE-2026-82384 と同一の問題で、影響範囲が 4.0.0 まで拡大されました。

**緩和策：**
- 可能なら **6.1.7**、少なくとも **6.1.6** へアップグレードする。6.1.7 は関連するクライアント側の ping 応答デシリアライゼーション問題 CVE-2026-123374 も修正しています。
- 暫定策：`WEB-INF/web.xml` で `enabledForExtensions` を `false` に設定するか、`/roller-services/xmlrpc` のサーブレットマッピングを削除し、再起動する。管理画面で XML-RPC を無効化するだけでは不十分です。

**影響対象：** Apache Roller 4.0.0〜6.1.5。**公開日：** 2026-11-17。Apache が悪用を確認しています。

## 9. CVE-2026-114938 — 「Java4Shell」：OpenJDK HotSpot の AVX-512 Base64 デコーダにおけるメモリ破壊

**原理・根本原因：** HotSpot には、x86-64 CPU で AVX-512 VBMI 命令を使う `java.util.Base64` デコード用の JIT コンパイル済み高速経路（「イントリンシック」）があります。特定の不正なパディング付き入力に対し、この最適化デコーダが出力バッファの末尾を越えて書き込み、ヒープメモリ破壊を引き起こします。攻撃者が制御する入力を Base64 デコードするアプリケーションはすべて影響を受ける可能性があり、これは認証ヘッダ、トークン、API で非常に一般的です。影響は JVM のクラッシュやメモリ漏えいから、認証前 RCE の可能性まで及びます。到達できるのはデコーダが JIT コンパイルされた（「ホット」になった）後で、AVX-512 VBMI 対応 CPU に限られます。ARM や旧世代の x86 CPU は影響を受けないと報告されています。

**緩和策：**
- 2026年11月17日の Java 更新を適用する：Oracle Java SE **17.0.21.1** / **21.0.13.1**、対応する 25.x/27.x ビルド、Amazon Corretto **17.0.21.1.2**、Azul Zulu の11月ビルド、および各ベンダーの同等品。JDK を同梱する製品（Elastic、Jira、Jenkins、Keycloak など）も、各ベンダーの修正提供に合わせて更新する。
- 暫定（非公式）：JVM を `-XX:-UseBASE64Intrinsics` で起動し、脆弱なイントリンシックを無効化する。Oracle・OpenJDK のどちらもこのワークアラウンドを推奨していません。
- CISA はさらに、Base64 入力のサイズ制限と検証、Java サービスへの認証不要アクセスの制限を推奨しています。

**影響対象：** AVX-512 VBMI 対応 x86-64 上の Java 17（17.0.6 以降と報告）、21、25、27（全ディストリビューション）。Java 8 と 11 は影響なしと報告されていますが、Oracle によると Java 8 Enterprise Performance Pack と GraalVM は影響を受ける可能性があります。**公開・修正：** 2026-11-17（Oracle 11月 Critical Security Patch Update）。公開 PoC の報告あり。2026-11-18 時点で実環境での悪用は未確認。

## 10. CVE-2026-115731 — Puppet Enterprise のサーバー側コード実行

**原理・根本原因：** 認証済みの Puppet エージェントが Puppet サーバー上で任意のコードを実行させられるため、管理対象ノードと構成管理サーバーの間の信頼境界が破られます。証明書の**自動署名（autosigning）**が有効な場合、攻撃者は承認なしに証明書を得られるため、実質的に認証不要で悪用できる可能性があります。

**緩和策：**
- Puppet Enterprise **2026.0.1**、**2025.12.1**、または **2023.8.13** へアップグレードする。
- 自動署名を無効化するか厳しく制限し、最近署名された証明書を確認する。

**影響対象：** 上記より前の Puppet Enterprise。**修正リリース：** 2026-11-03。**KEV：** 2026-11-17。

### 11. PHP — CVE-2026-129474 を含む Critical 7件の修正
PHP が 18件の脆弱性を修正するセキュリティ更新をリリースしました。うち 7件は RCE の可能性があり Critical と評価されています。CVE-2026-129474 は認証なしの攻撃者が誘発できる可能性のある use-after-free で、致命的エラーを起こし、コード実行に至る可能性があります。**緩和策：** サポート中ブランチの最新 PHP ポイントリリースへ、ディストリビューションのパッケージとあわせて更新する。**公開日：** 今週（2026-11-18/19 頃）。

### 12. CVE-2026-114713 — UnrealIRCd のサーバー間コマンドインジェクション
2台以上のサーバーがリンクされたネットワークでは、ユーザーとサーバーのメッセージコンテキストの分離が不十分なため、任意のユーザーがサーバー間プロトコルのコマンドを注入でき、それがサーバー権限で実行されます。**緩和策：** **6.2.7.1**（2026-11-07 リリース）へアップグレードする。**KEV：** 2026-11-13。

### 13. CVE-2026-123039 — Check Point Quantum / Gaia OS のローカル権限昇格
Gaia OS の DynamicCLI デーモンが root で動作し、全ユーザーが書き込み可能なローカルソケットで待ち受けているため、ローカルの低権限ユーザーがリクエストを送って root 権限を得られます。Security Gateway、Security Management Server、Multi-Domain Management、Scalable Platforms が影響を受けます。Check Point は約20数社の顧客に対する悪用を観測しています。**緩和策：** 使用中の Gaia バージョン向けの Check Point ホットフィックスを適用する。**KEV：** 2026-11-13。

### 14. CVE-2026-125350 — Google Chrome の XML/XSLT use-after-free（悪用済みゼロデイ）
Chrome の XSLT 処理（同梱 libxslt のパターンキャッシュ）における use-after-free です。細工されたページによってレンダラーサンドボックス内でコードが実行されます。**緩和策：** Chrome **157.0.8103.50/.51** 以降（Extended Stable は **156.0.8078.96**）。Chromium ベースのブラウザも各ベンダーの修正提供に合わせて更新する。**修正：** 2026-11-09。**KEV 期限：** 2026-11-24。

### 15. CVE-2026-20320 — Cisco BroadWorks の OCI-P における XXE
OCI-P の XML パーサにある XML 外部実体（XXE）の脆弱性で、認証なしの攻撃者が機密ファイルを読み取れます。欧州の通信事業者とその顧客を狙ったキャンペーンでの悪用が報告されています。**緩和策：** **RI.2026.07** へアップグレードする。Cisco はワークアラウンドを提示していません。**KEV：** 2026-11-10（期限 2026-11-24）。
