## 1. CVE-2026-90436 — Apache Axis 1.x SOAP Fault デシリアライゼーションによる RCE（Confluence Data Center、N-able N-central）

**原理・根本原因:** 長期間サポートが終了している SOAP エンジン Apache Axis 1.x は、受信した SOAP *fault* メッセージに含まれるデータを、インスタンス化できるオブジェクト型を十分に制限せずにデシリアライズします（CWE-502、信頼できないデータのデシリアライゼーション）。Axis は他製品に組み込まれているため、Axis ベースの SOAP エンドポイントを信頼できないクライアントに公開している製品は、認証不要のリモートコード実行経路を引き継ぎます。本 CVE は「UNSUPPORTED WHEN ASSIGNED」タグ付きで採番されており、Axis 1.x 系はサポート終了済みです。

**緩和策:**
- **Confluence Data Center:** **9.2.28** または **10.x**（当該機能を削除済み）へアップグレード。パッチ適用までの間は管理コンソールで *Remote API (XML-RPC & SOAP)* 設定を無効化する（この設定が有効なインスタンスのみ影響を受ける）。
- **N-able N-central:** N-able のアドバイザリに従う。報道によれば悪用は *Legacy API* モードが有効なサーバーに関係しているため、可能な限り Legacy API を無効化し、N-central サーバーのネットワーク露出を制限する。
- **Axis 1.x を組み込むその他のソフトウェア:** **1.x 系の修正版リリースは存在しない**。サポートされている SOAP スタック（Axis2 など）へ移行するか、上流の修正コミットを適用してリビルドする。それ以外の場合は SOAP エンドポイントを信頼できないネットワークから切り離す。
- Confluence / N-central の Java プロセスからの想定外の子プロセスや、新規の Web シェル類似ファイルを調査する。

**影響範囲:** Apache Axis 1.x（1.4 まで）、Remote API 有効時の Atlassian Confluence Data Center 1.x〜9.x（9.2.28 で修正、10.x および Cloud は影響なし）、N-able N-central（Axis を同梱）。Rapid7 は **2026-11-13** に Confluence 顧客への悪用を観測し、N-central でも悪用があったと報告しています。

**公開日:** Atlassian アドバイザリおよび Apache の公開は 2026-11-09 の週。実環境での悪用は 2026-11-13 に確認され、2026-11-14〜16 に公表。

## 2. CVE-2026-123039 — Check Point Gaia DynamicCLI の認可欠如（PHP2Shell との連鎖）

**原理・根本原因:** Check Point Gaia OS の DynamicCLI プロセス間通信（IPC）インターフェースは、呼び出し元プロセスが特権操作を要求する権限を持つかを検証しません（認可の欠如、CWE-862）。そのため、アプライアンス上で低権限で動作するプロセスが root として処理を実行させることが可能です。単体ではローカル権限昇格（CVSS 7.8）ですが、攻撃者は Check Point の Web 公開機能（Mobile Access Portal、SSL Network Extender など）に同梱された PHP ランタイムの **PHP2Shell** 脆弱性（CVE-2026-109618 / CVE-2026-109619、CVSS 4.0 9.2）と連鎖させ、認証不要のネットワークアクセスから root 取得に至っています。Check Point Research は、侵害後に Web シェル、「TSGA」バックドア、VMware ESXi ホストを狙った破壊型ワイパーが使用されたと報告しています。

**緩和策:**
- 使用中の Gaia バージョン向けの **2026年11月 Jumbo Hotfix** を適用する（PHP2Shell と CVE-2026-123039 の両方に対応。SK1000302 および Check Point アドバイザリ CPAI-2026-15172 / CPAI-2026-15184 を参照）。
- Check Point による暫定回避策: Hotfix 適用まで `dynamic_server` プロセスを停止し、再起動しないようにする。
- Mobile Access / ポータル系インターフェースの露出を制限し、ゲートウェイ上の Web シェルや不明な常駐プロセスを確認する。ゲートウェイから到達可能な ESXi ホストも点検する。
- CISA の連邦機関向け対応期限は **2026-11-16（本日）**。

**影響範囲:** 脆弱な DynamicCLI コンポーネントを持つ Gaia OS 搭載の Check Point セキュリティゲートウェイ。PHP2Shell の影響は Mobile Access Portal、SSL Network Extender を用いた Remote Access VPN、Captive Portal / UserCheck などの Web 機能が有効な場合に該当。Check Point によれば約20数社の顧客が攻撃を受けました。

**公開日:** 2026-11-13 に CISA KEV へ追加（PHP2Shell の初回公開は 2026-10-23 頃）。

## 3. CVE-2026-114713 — UnrealIRCd labeled-response の区切り文字インジェクション

**原理・根本原因:** IRCv3 の `label` メッセージタグを応答に反映する `labeled-response` モジュールが、このタグ内の区切り文字をエスケープしません（CWE-140、区切り文字の不適切な無効化）。2台以上のサーバーがリンクされたネットワークでは、一般ユーザーが制御する内容がサーバー間プロトコルのコマンドとして解釈され、サーバー／IRC オペレーター権限で信頼されてしまいます。これにより強制切断（KILL）やネットワーク全体での BAN（GLINE）などの操作が可能になります。プロジェクトは UnrealIRCd 史上最も深刻な欠陥としています。

**緩和策:**
- **UnrealIRCd 6.2.7.1**（2026-11-07 リリース）へアップグレードするか、公式ホットパッチを適用する。
- 直ちにパッチ適用できない場合は、プロジェクトが公開した spamfilter による回避策を暫定的に適用する。
- UnrealIRCd 5 も同様に影響を受けるとされ、サポート終了済みのため移行する。

**影響範囲:** UnrealIRCd 6.0.0 以上 6.2.7.1 未満、UnrealIRCd 5.x（EOL）。公開の翌日から悪用が始まりました。

**公開日:** 2026-11-07（修正版リリース）。2026-11-13 に CISA KEV へ追加、期限は 2026-11-16。

## 4. CVE-2026-116606 & CVE-2026-111560 — Barracuda Email Security Gateway 認証前 root 取得チェーン

**原理・根本原因:** CVE-2026-116606 は ESG の設定バックアップ復元機能における認証バイパスで、認証されていない第三者が細工した設定を復元してグローバル設定を上書きでき、実質的に管理者権限を得られます（CVSS 4.0 9.3、一部機関は 9.8 と評価）。CVE-2026-111560 は複数の Barracuda アプライアンス製品群で共有される管理用コードの OS コマンドインジェクション（CWE-78）で、管理者レベルのユーザーが root としてコマンドを実行できます。連鎖させると、認証されていない攻撃者がアプライアンスの root を取得できます。

**緩和策:**
- ESG を **9.4.0.030 以降** にアップグレードする（両方を修正）。
- CVE-2026-111560 のコードを共有する他の Barracuda 製品（Load Balancer ADC、Web Application Firewall、Message Archiver）にも対応する更新を適用する。
- 管理インターフェースをインターネットに公開しない。想定外の設定変更や永続化の痕跡を確認する。

**影響範囲:** 9.4.0.030 より前の Barracuda Email Security Gateway（両 CVE）、Barracuda Load Balancer ADC、WAF、Message Archiver（CVE-2026-111560）。Barracuda は 2026-11-09 に少数の組織への悪用を確認、CISA KEV 追加は 2026-11-10、シンガポール CSA は **2026-11-16** に悪用警告を発出しました。

**公開日:** 2026年11月上旬（アドバイザリは 2026-11-03 以前）。悪用確認は 2026-11-09。

## 5. CVE-2026-124194 — Microsoft Outlook のなりすまし／NTLM ハッシュ漏えい（ゼロデイ）

**原理・根本原因:** Windows 版クラシック Outlook は、細工されたメッセージにより攻撃者が管理するリソースへの外向き認証を開始させられ、ユーザーの Net-NTLM ハッシュが漏えいします。盗まれたハッシュはオフラインで解析されたり、他サービスへのリレーに悪用されたりします。Microsoft はなりすまし（CVSS 6.5）に分類し、パッチ公開前の悪用を確認しています。

**緩和策:**
- 2026-11-10 の Office 更新を適用する（例: LTSC 2021 ビルド 16.0.14334.21048、LTSC 2024 ビルド 16.0.17932.21140、Microsoft 365 Apps Current Channel 2610 ビルド 20527.20196 以降。Microsoft のビルド表で確認すること）。
- インターネット向けの外向き SMB（TCP 445）を遮断する。重要ユーザーを *Protected Users* グループに追加し、SMB 署名／EPA を強制し、外向き NTLM の制限を検討する。

**影響範囲:** Microsoft 365 Apps for Enterprise、Office LTSC 2021、Office LTSC 2024（32/64 ビット）の Windows 版クラシック Outlook。新しい Outlook、Outlook on the web、Mac 版、モバイル版は対象外とされています。

**公開日:** 2026-11-10（Patch Tuesday）。同月の Patch Tuesday では約1,100件以上の CVE（Critical 約63〜64件、Exchange Server、Windows LDAP の RCE など）が修正されました。Exchange や LDAP を公開しているシステムを優先してください。

## 6. CVE-2026-125350 — Google Chrome XML の解放後使用（ゼロデイ）

**原理・根本原因:** Chrome の XML 処理における解放後使用（use-after-free、CWE-416）。オブジェクトが解放された後もそのポインタが使用され続けるため、細工された Web ページによりレンダラーが解放済みメモリを操作し、レンダラーサンドボックス内でのコード実行につながる可能性があります。Google は実環境での悪用を確認しており、2026年に悪用された Chrome ゼロデイとして8件目です。同じリリースで別の XML 解放後使用（CVE-2026-125346）も修正されました。

**緩和策:** Chrome を **157.0.8103.50/.51** 以降に更新し、ブラウザを再起動する。Chromium ベースのブラウザ（Edge、Brave、Opera、Vivaldi）も各ベンダーの修正版が出次第更新する。

**影響範囲:** 157.0.8103.50 より前の Windows、macOS、Linux 版 Google Chrome、およびパッチ未適用の Chromium ベースブラウザ。

**公開日:** 2026-11-09 に修正版リリース。2026-11-10 に CISA KEV 追加（連邦機関の期限は 2026-11-24）。

## 7. CVE-2026-119618 — Apache HTTP Server mod_http2 のヒープ破壊

**原理・根本原因:** mod_http2 のヘッダー割り当て処理におけるメモリ安全性の欠陥により、クライアントからの不正な HTTP/2 ヘッダーデータがヒープメモリを破壊し、サーバーワーカープロセスでのリモートコード実行につながる可能性があります。2.4.71 では CVE-2026-106023（Important、mod_md / ACME 証明書モジュール）と CVE-2026-109163（Low、mod_vhost_alias の1バイトのスタック上書き）も修正されています。

**緩和策:** **Apache HTTP Server 2.4.71**（またはディストリビューションのバックポート版）へアップグレードする。直ちに更新できない場合は、公開中のバーチャルホストで HTTP/2 を無効化する（`Protocols` から `h2`/`h2c` を除外）。

**影響範囲:** Apache 公式セキュリティページによれば httpd 2.4.69〜2.4.70（一部二次報道では 2.4.55〜2.4.70 とされる。広い範囲は未確認だが、HTTP/2 を有効にした古いビルドも確認を推奨）。

**公開日:** 2026-11-11。悪用は未確認。

## 8. SAP 11月パッチデー — ICM2SHELL（CVE-2026-76964 / CVE-2026-89126）、PROXYGATE（CVE-2026-89103）、CVE-2026-120017

**原理・根本原因:** ICM2SHELL は、Internet Communication Manager（ICM）および SAP Web Dispatcher で分割された WebSocket メッセージを再構成する SAP カーネルコードの単一の欠陥です。細工されたリクエスト内の不正な長さフィールドによりヒープ境界外書き込みが発生し、認証不要のリモートコード実行が可能になります。PROXYGATE（CVE-2026-89103）は SAP Gateway における認証前 RCE です。CVE-2026-120017 は SAML シングルサインオンを構成したシステムに影響する CVSS 10.0 の脆弱性です。

**緩和策:** 2026-11-10 のパッチデーで公開された SAP セキュリティノートを適用する（ICM / Web Dispatcher 向けカーネル更新、Gateway および SAML 関連ノート）。パッチ適用まで Web Dispatcher/ICM および Gateway ポートのインターネット露出を制限する。

**影響範囲:** SAP NetWeaver AS ABAP（ICM）、SAP Web Dispatcher、SAP Gateway、SAML SSO 構成システム。カーネルバージョンはノートごとに異なります。

**公開日:** 2026-11-10。悪用は未確認（別件の SAP Commerce Cloud の CVSS 10 脆弱性はパッチデー直後に悪用が報告されています）。

## 9. CVE-2026-20320（Cisco BroadWorks）& CVE-2026-111793（Openwave Webtop）

**原理・根本原因:** Cisco BroadWorks には認証不要の帯域外ブラインド XML 外部エンティティ（XXE）インジェクションがあり、XML パーサーが信頼できない入力内の外部エンティティを解決するため、リモート攻撃者が機密の設定情報を窃取できます。Openwave Webtop Media Transcoder には「領域間でのリソースの不正な移転」の欠陥があり、認証済みユーザーが Webmail のフロントエンドを迂回して想定外の文書形式を処理させることができます。

**緩和策:** Cisco BroadWorks — Application Delivery Platform および関連コンポーネントを **RI.2026.07** 以降に更新する。Openwave Webtop — ベンダーの指示に従い Media Transcoder を **1.1.22.0** 以降に更新する。

**影響範囲:** RI.2026.07 より前の Cisco BroadWorks（初回公開 2026-08-19）、1.1.22.0 より前の Openwave Webtop Media Transcoder。

**公開日:** 2026-11-10 に CISA KEV 追加（期限 2026-11-24）。

## 10. CVE-2026-123158 — OpenSSH「sshole」musl libc 環境でのパスワード認証バイパス

**原理・根本原因:** musl libc でビルドされ PAM を使用しない Linux システム（Alpine Linux が代表例）では、sshd にパスワードハッシュ処理における libc の挙動差異への回避処理が欠けており、アカウントのパスワードフィールドが特定の組み合わせの場合、正しいパスワードなしでパスワード認証が成功し得ます。パスワード認証が有効であることが前提条件です。公開から9時間以内に最初の悪用試行が観測され、ハニーポットで root 取得が確認されました。

**緩和策:** **OpenSSH 10.6p2** またはディストリビューションのバックポート版へ更新する（Alpine: edge 10.6_p2-r0、3.24 10.3_p1-r2、3.23 10.2_p1-r1、3.22 10.0_p1-r11、3.21 9.9_p2-r1、および 3.16〜3.20 のバックポート。バージョンバナーではなくパッケージのリリース番号で確認すること）。更新後は **sshd を再起動** する。可能な限りパスワード認証を無効化して鍵認証に切り替え、ロック済み／空のパスワードフィールドを持つアカウントを見直す。

**影響範囲:** PAM を使用しない musl ベース Linux 上の 10.6p2 より前の OpenSSH（主に Alpine Linux および Alpine ベースのコンテナ）。glibc + PAM のディストリビューションは一般に影響を受けません。

**公開日:** 2026-11-05。2026-11-09 に CISA KEV 追加。
