## 1. Fortinet FortiOS、FortiManager、FortiAnalyzer、FortiSASE — 11月のセキュリティ強化パッチ一括公開

**原理・根本原因:** Fortinetは10月下旬にパッチを配布していましたが、CVE番号や技術的詳細は2026-11-10の協調開示まで非公開としていました。今回の開示では89件のアドバイザリ（うち19件以上がCritical/High評価）が含まれます。特に影響の大きい項目は以下の通りです: FortiManager/FortiAnalyzerのJSON-RPC APIにおける未認証のJSONインジェクションにより、リモート攻撃者がバックエンドのオブジェクトを操作可能（CVE-2026-126170、インジェクション系のCWE）。FGFM（FortiGate-FortiManager間通信）プロトコルの処理不備により、管理対象のFortiGateになりすました機器がこれを悪用可能（CVE-2026-126261）。FortiAnalyzer/FortiManagerのOFTP（ログ転送）サービス経由で到達可能な未認証のSQLインジェクション（CVE-2026-126262）。設定済みのiBGPピアによってトリガー可能な、FortiOSのBGP実装における数値切り捨てのバグ（CVE-2026-126254）。FortiOSのOSPFルーティングデーモンにおける認証バイパスの脆弱性（CVE-2026-126253）。いずれも、ネットワークに面した管理機能やルーティングサービスにおける入力検証やトラストバウンダリのチェック不足に起因します。

**対策:**
- FortiOS 8.0.2 / 7.6.8 / 7.4.13 / 7.2.14以降、またはFortiManager/FortiAnalyzer 8.0.2 / 7.6.8 / 7.4.12 / 7.2.13以降にアップグレードしてください（パッチ自体は2026-10-22から提供されており、今回遅れたのはアドバイザリ公開のみです）。
- 管理プレーン（JSON-RPC、FGFM、OFTP）へのアクセスを信頼できるネットワークに限定し、多層防御としてBGP/OSPFのピアリングも認証済みの想定ネイバーのみに制限してください。

**対象:** 上記修正バージョンより前のFortiOS、FortiManager、FortiAnalyzer、FortiSASE。2026-11-10公開。Fortinetは公開時点で既知の悪用は確認されていないとしていますが、公開規模と深刻度の大きさから、インターネットに面した管理インターフェースは最優先でパッチ適用すべき対象です。

## 2. CVE-2026-102895 — GPUStackの未認証管理者権限奪取

**原理・根本原因:** GPUStackの認証レイヤーは、`localhost`から送信されたように見えるリクエストを暗黒的に信頼し、管理者権限を自動付与します。この判定はクライアント側から提示可能・偽装可能な発信元情報に依存しており、検証済みのネットワークレイヤーでのチェックではありません（不適切な発信元検証とIPスプーフィング類の過信、CWE-346/CWE-290）。リモートの未認証攻撃者がリクエストをループバックインターフェース発信に見せかけられれば、永続的な管理者APIキーを取得し、GPUワーカーノード上で任意コードを実行し、接続されたクラウドプロバイダーやワーカーのシークレットにアクセスできます。関連する脆弱性CVE-2026-102894は、同製品のSAML認証処理に関するものです。

**対策:**
- GPUStack 2.2.2以降にアップグレードしてください（2.2.0でCVE-2026-102895が修正済み、2.2.2ではCVE-2026-102894も追加で修正されています）。
- パッチ適用までは、`Host`/発信元情報が偽装される可能性のあるネットワーク経路からGPUStackの管理プレーンを分離し、漏洩の可能性があるAPIキーやクラウドプロバイダーの認証情報はローテーションしてください。

**対象:** 2.2.0より前のGPUStack（本番AIインフラ環境でバージョン2.1.1に対する悪用が確認されたとの報告あり）。2026-11-04に公開。2026-11-09にCISA KEVへ追加。

## 3. CVE-2026-116779 — SignalWire FreeSWITCHのSIP MESSAGEコマンドインジェクション

**原理・根本原因:** FreeSWITCHのSIP MESSAGEハンドラーは、宛先フィールドの一部を検査して、リクエストをどの内部「チャットプロトコル」ハンドラーで処理するかを判断します。このフィールドが内部API用プロトコルを指定していた場合、SIPメッセージに含まれる攻撃者制御下のコンテンツがFreeSWITCH自身のコマンドAPIにそのまま渡され、FreeSWITCHプロセスの権限で実行されてしまいます。信頼できない入力が権限を持つコマンド実行インターフェースへ転送される典型的なケースです（CWE-77/CWE-78系）。WebRTCやICEによる通話処理を有効にしている構成では、デフォルトでこの経路が露出します。

**対策:**
- FreeSWITCH 1.11.3以降にアップグレードしてください。
- 直ちにアップグレードできない場合は、SIPシグナリングの公開範囲を信頼できるネットワーク/ピアに限定し、不要なチャットプロトコルへのルーティングがないかSIP MESSAGEの処理設定を見直してください。

**対象:** FreeSWITCH 1.11.2以前。SignalWireのアドバイザリおよび複数の二次情報源が実環境での悪用を報告しています。2026-11-09にCISA KEVへ追加。

## 4. CVE-2026-123158（"SSHole"） — musl/PAM未使用ビルドにおけるOpenSSHのパスワード認証バイパス

**原理・根本原因:** PAMを使用せずmusl libcに対してビルドされたOpenSSH（Alpine Linuxなど軽量ディストリビューションのデフォルト構成）では、サーバーが特定の入力文字列を、検証すべきパスワードではなく事前計算済みのパスワードハッシュとして誤って解釈してしまう場合があります。このロジック上の誤りにより、認証制限が設定されたアカウントに対してもパスワード認証をバイパスできてしまい、本来通過させるべきではないチェックを巧妙な入力によって通過させてしまいます（CWE-287、不適切な認証）。

**対策:**
- OpenSSH（portable版）10.6p2以降、またはお使いのディストリビューションが提供する修正済みパッケージにアップグレードしてください（Alpineはサポート対象の各ブランチに修正を提供済みです）。
- インターネットに面したmusl系のコンテナ/VM（軽量コンテナイメージで多く見られる構成）のSSH公開状況を確認し、可能な範囲で多層防御としてPAMの有効化も検討してください。

**対象:** musl libcに対してPAMなしでビルドされた10.6p2より前のOpenSSH（Debian/Ubuntuのglibc+PAMビルドはこの経路の影響を受けません）。2026-11-05に修正。2026-11-09にCISA KEVへ追加。PoCの公開情報が存在するとの報告があります。

## 5. CVE-2026-123218 — IBM Aspera Faspex 5における認可バイパスから完全な管理者権限への昇格

**原理・根本原因:** すでに認証済みだが権限の低いFaspex 5ユーザーが、特定の形式に作り込んだメッセージ/リクエストを送信することで、サーバー側がリクエスト元の権限レベルを適切に再検証せずに処理してしまい、そのユーザーが完全な管理者権限へ昇格できてしまいます（CWE-863、不適切な認可）。メモリ破壊やインジェクションといった追加の手順は不要で、脆弱性は認可チェックのロジックそのものに存在します。

**対策:**
- Faspex 5.0.19 PL1（Linux）以降にアップグレードしてください。IBMは回避策を公開していないため、パッチ適用が唯一の対策です。
- Faspexの管理者アカウントの操作ログを確認し、元々権限の低いアカウントによる予期しない権限変更がないか監査してください。

**対象:** IBM Aspera Faspex 5.0.0から5.0.19まで。2026-11-07に公開。2026-11-09にCISA KEVへ追加。

## 6. CVE-2026-119977 — WordPress Coreの更新処理中の競合状態（レースコンディション）によるRCE

**原理・根本原因:** WordPress Coreの自己更新処理には、TOCTOU（Time-Of-Check-To-Time-Of-Use）型の競合状態（CWE-367）が存在します。Coreが更新パッケージをダウンロード・検証・展開する短い時間窓の間に、このプロセスに対して適切なタイミングで競合を発生させることができた攻撃者は、悪意のあるコンテンツを信頼済み・検証済みの更新コンテンツとして処理させることができ、最終的にサイト上での任意コード実行につながります。皮肉なことに、脆弱性を修正するための更新処理そのもの（脆弱なバージョンの更新ルーチンの実行）が、サイトをこの競合に晒す原因となります。

**対策:**
- できるだけ早くWordPress Core 7.1.4以降に更新してください（更新処理自体が脆弱な時間窓であることを踏まえ、アクセスの少ない時間帯に実施し、更新後にバージョンを確認することを推奨します）。
- 古い脆弱なバージョンでCoreの更新を実行した直後は、予期しないファイル変更や新規管理者アカウントの作成がないか監視してください。

**対象:** WordPress Core 4.7.0から7.1.3まで（実質的に7.1.4より前の、現在も使用されているほぼ全てのWordPressサイトが対象）。CISAは積極的な悪用の証拠があるとして2026-11-03にKEVカタログへ追加し、連邦機関の対応期限は2026-11-06でした（既に期限を過ぎています）。注: WordfenceはこれをCVSS 8.1（High）と評価していますが、WordPressプロジェクト自身のアドバイザリではLowと評価されています。評価の相違にかかわらず、実環境での悪用が確認されていることから優先度の高い対応が必要です。

## 7. CVE-2026-116606 および CVE-2026-111560 — root権限奪取に連鎖可能なBarracuda製品の脆弱性

**原理・根本原因:** CVE-2026-116606は、Barracudaの管理インターフェースにおける認可バイパスの脆弱性（報告されているCVSSは9.3）で、Email Security Gateway（ESG）に影響します。事前の認証が必要かどうかについては情報源によって見解が分かれていますが、管理インターフェースにネットワーク経路で到達可能である必要がある点は一致しています。CVE-2026-111560は、タイムゾーン設定フィールドにおけるOSコマンドインジェクションの脆弱性（CVSS 8.6）で、管理者権限でのアクセスを必要とし、ESGに加えてWAF、Load Balancer ADC、Message Archiver、Web Security Gateway、WAF Control Centerにも影響します。対象製品上でこれら2つを連鎖させることで、管理インターフェースへの到達からアプライアンス上での完全なroot権限でのコマンド実行まで権限を昇格させることが可能です。

**対策:**
- Barracudaが提供するパッチを適用してください（ESGの場合: ファームウェア9.4.017以降はBNSF-40425、それ以前はBNSF-40430。他の製品にも個別のパッチIDがあるため、お使いの機種に応じてBarracudaのアドバイザリを確認してください）。
- 影響を受ける全てのBarracuda製品において、管理インターフェースを信頼できる内部管理ネットワークのみに限定してください。

**対象:** パッチ未適用のファームウェアで稼働するBarracuda ESG、WAF、Load Balancer ADC、Message Archiver、Web Security Gateway、WAF Control Center。2026-11-02に公開（今週の7日間の対象期間からはわずかに外れますが、パッチ適用が現在も進行中であり、直近の確認時点では実環境での悪用は確認されていないため、文脈として掲載しています）。

## 8. CVE-2026-111793 — Openwave Messaging Webtop Media Transcoderにおけるファイル形式制限のバイパス

**原理・根本原因:** Webメールサービスがメール添付ファイルをブラウザ上でのプレビュー用に変換するために使用するWebtop Media Transcoderコンポーネントは、管理者が設定したファイル形式の制限を適切に適用できていません（CWE-669、スフィア間でのリソース転送の不適切な処理）。認証済みのWebメールユーザーが、管理者がブロックすることを意図した種類の文書の変換をリクエストすることで、本来許可されていないファイル形式を変換パイプラインに到達させることができます。

**対策:**
- Webtop Media Transcoder 1.1.22.0以降にアップグレード、またはサポート対象のMedia Server 2.0へ移行してください。Openwaveはこれ以外の回避策を示していません。
- アップグレードが遅れる場合は、Webメールの添付ファイル処理ログを確認し、予期しないファイル形式の変換がないか確認してください。

**対象:** Webメール/サービスプロバイダー向けメッセージングプラットフォームで使用される、1.1.22.0より前のOpenwave Messaging Webtop Media Transcoder。Openwave自身はこれをCVSS 4.3（Medium）と評価しており、本稿執筆時点でCISA KEVカタログには掲載されていません。ただし、JPCERT/CCは2026-11-09に積極的な悪用の試みを観測したと報告しており、さらなる確認が得られるまではベーススコアが示す以上に緊急性が高いものとして扱うべきです。
