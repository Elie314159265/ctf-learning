## 1. Plex2Shell — Plex Media Server のSSRF/ファイルパス連鎖(CVE-2026-96652, -96654, -96655, -96656)

**原理・根本原因:** 4件の脆弱性が連鎖することで重大な影響をもたらします。2件はtimeline / searchOne エンドポイントのSSRF・URL処理の不備(認証なしで到達可能)、1件はトランスコーダの認証後SSRF、1件はサーバーが後で読み込む共有ライブラリを攻撃者が配置できてしまうファイルパス処理の不備です。連鎖により、Plexプロセスの権限で認証なしのコード実行が可能になります。

**対策:**
- Plex Media Server を 1.43.3.10861 以降に更新(修正は2026-08-03に提供)。
- Plexをインターネットに直接公開せず、VPNまたは認証付きリバースプロキシ経由に制限。
- Plexホスト上の不審なマイナープロセス、未知の外部通信、見慣れないプロキシ/バックドアのバイナリを調査。

**影響範囲:** 1.43.3.10861 より前のPlex Media Server(全対応OS)。

**公開日:** 修正 2026-08-03、詳細解説公開 2026-10-16、数時間以内に悪用観測、CISA KEV追加 2026-10-20。

## 2. Arista VeloCloud Orchestrator — 悪用されたゼロデイ(CISA記載 CVE-2026-114625)

**原理・根本原因:** CISAの2026-10-23の通知はVeloCloud OrchestratorのSQLインジェクションとしています。二次情報は食い違っており、認証不要のOSコマンドインジェクション(CVE-2026-16812、深刻度10.0)がゼロデイとして悪用されたとするものと、別件の認証後SQLインジェクション(Flow Metrics API、CVE-2026-17191、8.5、悪用なし)とするものがあります。**正確なCVEの対応は未検証です。** いずれの場合も、信頼できない入力が適切に無害化されずバックエンドのクエリまたはコマンドに到達する問題です。

**対策:**
- Aristaが報告する修正版へ更新: 5.2.3.14、6.1.3.4、6.4.2.4、または 7.0.0.1。
- Orchestratorの管理インターフェースを信頼できるネットワークに限定し、異常なAPIアクティビティをログで確認。

**影響範囲:** オンプレミス版 VeloCloud Orchestrator 5.2.0〜5.2.3.13、6.1.0〜6.1.3.3、6.4.0〜6.4.2.3(二次情報による)。

**公開日:** CISA KEV 2026-10-23(ベンダーのパッチはそれ以前との報告、日付は要確認)。

## 3. PHP2Shell — PHP本体の脆弱性(CVE-2026-109618, CVE-2026-109619)

**原理・根本原因:** PHP本体の重大な2件。一方はリクエスト処理におけるメモリ枯渇(OOM)に関する挙動、もう一方はそれと組み合わさり(セッションのアップロード進捗処理を介して)リモートコード実行に至る問題です。mod_phpではアプリケーションコードが実行される前に認証なしのリクエストで発動し得るため、PHPチームは最もリスクが高いとしています。(別ID CVE-2026-115560 も一箇所で報告されましたが確認できませんでした。)

**対策:**
- PHP 8.5.12、8.4.27、8.3.36、8.2.35 のいずれかに更新。7.4、8.0、8.1向けには最小限のバックポートがあり、ディストリビューション独自のバックポートもあります。
- 暫定対策(部分的のみ): アプリから変更できない memory_limit の強制(php_admin_value 等)、post_max_size の縮小、session.upload_progress.enabled=0。これらでは安全になりません。
- 未パッチのサーバーの公開範囲を制限。

**影響範囲:** 上記修正版より前のPHP 7.x および 8.x。

**公開日:** 事前告知と緊急パッチは 2026-10-21〜10-23頃。エクスプロイトコードが出回っているとの報告があるが、実際の悪用は未確認。

## 4. CVE-2026-101809 — Oracle E-Business Suite Workflow Notification Mailer

**原理・根本原因:** Workflow Notification Mailer(承認メール処理)コンポーネントに、HTTP経由で認証なしに到達できる欠陥があり、Workflow製品の完全な乗っ取りに至ります。スコープ変更により他コンポーネントにも影響し得ます。CVSS 10.0。

**対策:** Oracleの2026年10月Critical Patch Updateを適用。EBSの外部公開を制限し、Workflow/メーラーへの異常なリクエストを監視。

**影響範囲:** Oracle E-Business Suite 12.2.3〜12.2.15。

**公開日:** 2026年10月CPU。執筆時点で悪用は未確認(パッチ詳細は単一の二次情報によるため、Oracleで要確認)。

## 6. CVE-2026-115927 — Tornado のチャンク転送エンコーディングによるリソース消費

**原理・根本原因:** チャンク転送エンコーディングの不適切な処理により、リモートの認証なしクライアントが過剰なリソース消費(サービス拒否)を引き起こせます。

**対策:** Tornado を 6.6.0 以降に更新。前段プロキシでリクエストサイズ/時間の制限を検討。

**影響範囲:** 6.6.0 より前の Tornado Webフレームワーク。**公開日:** 2026-10-26。
