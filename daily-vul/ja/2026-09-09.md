## 1. CVE-2026-85880・CVE-2026-81963 — Microsoft Windows ゼロデイ(2026年9月Patch Tuesday)

**原理・根本原因:** CVE-2026-85880は、システムサービスが多用するプロセス間通信機構であるWindows Advanced Local Procedure Call(ALPC)におけるヒープベースバッファオーバーフローです。ALPCの呼び出し元を信頼するサービスでヒープメモリを破壊することで、権限の低いローカルプロセスが隣接メモリを上書きし、最終的にSYSTEM権限でコードを実行できる可能性があります。CVE-2026-81963は、Windows Update Stackにおける「リンクフォロー」の欠陥(CWE-59)です。更新プロセスがファイルシステムのパス/リンクを解決する際、それが正当で信頼できる対象を指しているかを十分に検証しないため、ローカルの攻撃者が攻撃者制御下のファイル/リンクに差し替えることで、更新プロセスが本来意図しない(攻撃者提供の)オブジェクトを操作させられ、権限昇格に至ります。

**対策:**
- 2026年9月の累積更新プログラムを直ちに適用してください。Microsoftは、いずれの技術的詳細が公開される前から、両方の欠陥について実際の悪用を確認しています。
- インターネットに公開されたシステムや複数ユーザーが利用するWindowsシステムを優先してください。いずれもローカル権限昇格のプリミティブであり、通常は初期侵入後に連鎖利用されます。

**対象:** サポート対象の最新のWindowsクライアント/サーバーリリース(正確なバージョン範囲は各CVEに対応するMicrosoft MSRCアドバイザリを参照)。過去最大規模となった2026年9月Patch Tuesdayリリース(Microsoft製品CVE計約974件、うちCritical評価は約105〜119件)の一部として、2026-09-08にリリース。両ゼロデイは同日にCISA KEVへ追加されました。

## 2. CVE-2026-75650 — Adobe Commerce & Magento テンプレートエンジンRCE(「StyleSmuggler」、ゼロデイ)

**原理・根本原因:** Adobe Commerce/Magentoのテンプレートレンダリングエンジンは、信頼できない入力に埋め込まれた特殊なテンプレートディレクティブ構文を適切に無害化できません(CWE-1336、テンプレートエンジンで使用される特殊要素の不適切な無害化)。テンプレートエンジンが後で処理するフィールドに巧妙に作成されたディレクティブ構文を混入させることで、未認証の攻撃者はログインもユーザー操作も不要な状態で、エンジンに攻撃者提供のPHPコードをコンパイル・実行させることができます。

**対策:**
- セキュリティ情報APSB26-146で参照されているAdobeのホットフィックス(VULN-39341)を直ちに適用してください。適用対象はAdobe Commerce/Magento Open Source バージョン2.4.4〜2.4.7、および2.4.9-2026-augまでの以降のブランチです。
- 未パッチでインターネットに公開されたMagento/Adobe Commerceストアは「侵害済みである」との前提で扱い、想定外のPHP Webシェルや見慣れないLinuxバックドアのバイナリ/サービスを調査してください。

**対象:** Adobe Commerce、Adobe Commerce B2B、およびMagento Open Sourceの、2.4.9-2026-augまでの現在サポート対象のすべてのブランチ。実悪用は2026-09-04に開始され、Adobeがホットフィックスをリリースした2026-09-07より3日先行していました。攻撃者はこの期間を利用してRustベースのLinuxバックドアを展開し、別のケースではPHP Webシェルを展開しました。

## 3. CVE-2026-86218 — N-able N-central 静的コードインジェクション(認証前RCE)

**原理・根本原因:** マネージドサービスプロバイダーが利用するオンプレミス型リモート監視管理(RMM)コンソールであるN-centralは、一部のサーバーサイドスクリプト/設定を「静的に保存されたコード」として保持し、後にプラットフォームがそれを実行します。攻撃者提供の入力に埋め込まれたディレクティブが、その保存済みコードに書き込まれる前に適切に無害化されないため(CWE-96、静的コードインジェクション)、未認証の攻撃者は資格情報なしでN-centralに後で実行されるコードを注入できます。N-centralは管理下のすべてのエンドポイントへ変更をプッシュする設計であるため、コンソール自体が侵害されると、管理対象のすべてのクライアントネットワークに影響が伝播する可能性があります。

**対策:**
- N-central 2026.3 Hotfix 4(修正版 バージョン2026.3.1.14以降)へ直ちにアップグレードしてください。
- これはおよそ6週間の間に開示された3件目のN-centralゼロデイであるため、MSPはパッチ適用日以降だけでなく、2026年8月上旬まで遡ってN-centralサーバーログ上の想定外のスクリプト/設定変更を確認すべきです。

**対象:** バージョン2026.3.1.14より前のN-able N-central。実際に悪用されており、2つのWindowsゼロデイおよびAdobe Commerceの欠陥とともに2026-09-08にCISA KEVへ追加されました。ホットフィックスは2026-09-05にリリース。

## 4. CVE-2026-44756(「OVERPASS」) — SAP Kernel 未認証RCE

**原理・根本原因:** 多くのSAPコンポーネントで標準的に利用されているSAPカーネルレベルのExtended Passport Protocol(EPP)処理ライブラリには、典型的なバッファオーバーフローの弱点が存在します。一般的な導入環境ではEPPは認証なしにリモートから到達可能であるため、攻撃者は巧妙に作成したネットワーク入力を送信してEPP解析中のバッファをオーバーフローさせ、実行フローを乗っ取り、SAP管理アカウントの権限で任意のOSコマンドを実行できます(実質的にホストおよびアプリケーションの完全な侵害に相当)。

**対策:**
- SAPの2026年9月Security Patch Dayのカーネル更新を直ちに適用してください。これは最大深刻度(CVSS 10.0)であり、標準で有効化され、未認証でリモートから到達可能な欠陥です。
- 多層防御として、SAPアプリケーション/メッセージサーバーの直接的なインターネット公開を制限し、EPP/カーネルレベルの異常な通信を監視してください。

**対象:** 脆弱なカーネルを基盤とする広範なSAPテクノロジーコンポーネント(NetWeaverベースのスタック、S/4HANA、および脆弱なEPPライブラリを共有する他のコンポーネント)。2026-09-08にパッチ提供。Onapsis等の研究者によれば、脆弱なコンポーネントを稼働しているインターネット公開SAPシステムは1万台超と推定されています。本稿執筆時点で実悪用は未確認ですが、標準で公開状態・認証不要・完全侵害という組み合わせから、迅速な武器化が起こりやすいと考えられます。

## 5. CVE-2026-61410・CVE-2026-80238 — Dell Secure Connect Gateway の重大な欠陥

**原理・根本原因:** CVE-2026-61410は認可の欠落(CWE-862)であり、巧妙に作成したリクエストをSecure Connect Gatewayアプリケーションに送信することで、意図された制限を回避し、有効な資格情報なしでコード実行経路に到達できます。CVE-2026-80238は不必要な権限での実行(CWE-250)の問題であり、SCGホストへSSHアクセス権を持つ低権限の運用者、またはオーケストレーターコンテナ内のサービスを侵害した攻撃者が、公開されたDockerソケットに到達し、それを利用して基盤ホスト上でroot権限を取得し、コンテナ境界を完全に脱出できます。

**対策:**
- Secure Connect Gatewayアプライアンスをバージョン5.36.00.16以降、アプリケーションを5.36.00.00以降にアップグレードしてください。
- 多層防御として、SCGホストへのSSHアクセスを監査し、Dockerソケットへの不要なアクセスを制限・削除してください。

**対象:** Dell Secure Connect Gateway(SCG)5.0のアプリケーション版・仮想アプライアンス版の両方で、上記の修正版より前のバージョン。Dellアドバイザリ DSA-2026-382 にて2026-09-07/08に開示。

## 6. CVE-2026-19593 — OpenAI Codex Desktop Gitコンフィグによるコード実行

**原理・根本原因:** Codex Desktopは、ユーザーがワークスペースを開くたびにGitのメタデータと作業ツリーの状態を自動的に検査します。そのワークスペースに、`.git/config`に攻撃者制御下の設定(設定済みの`clean`/`smudge`フィルターや`attr.tree`設定など)を保持したリポジトリが含まれている場合、単にワークスペースを開くだけでGit自身が攻撃者指定のプログラムを実行してしまいます。これはCodexのコマンドサンドボックスの外側で、ワークスペース信頼確認やコマンド承認のステップもなく、AIモデルが関与することもなく発生します(CWE-15、システム/設定値の外部制御)。

**対策:**
- Codex Desktopを修正済みリリースに更新してください。
- 信頼できない、または見覚えのないリポジトリ(メール添付やダウンロードしたアーカイブなど)を、事前に`.git/config`を確認せずにCodex Desktopで直接開かないでください。通常の`git clone`では元リポジトリのローカル設定はコピーされないため、既にチェックアウトされた出自不明のフォルダを開くよりも、信頼できるURLから新規にクローンする方が安全です。

**対象:** 修正版より前のWindows/macOS版OpenAI Codex Desktop。2026-09-01に公開開示。AIコーディングアシスタントツール特有のサプライチェーン関連の欠陥として注目されます。

## 7. CVE-2026-85046 — Google Chrome V8 型混乱(ゼロデイ、継続情報)

**原理・根本原因:** V8の最適化コンパイラのロジックの欠陥により、本来`PACKED_ELEMENTS`型タグを持つべき配列に、代わりに`PACKED_SMI_ELEMENTS`マップが割り当てられることがあります。後続の最適化されたコードパスは、配列メモリの読み書き方法を決定する際にこの型タグを信頼しているため、この不一致(型混乱)はJavaScriptヒープ上の任意の読み書きに転用され、最終的には巧妙に作成されたWebページを介してChromeサンドボックス内での任意コード実行につながる可能性があります。

**対策:** Chrome(および Edge、Brave、Opera、VivaldiなどのChromiumベースブラウザ)をバージョン152.0.7977.82/.83以降に更新し、更新を適用するためブラウザを再起動してください。

**対象:** バージョン152.0.7977.82より前のChrome/Chromium。2026年にパッチが適用された、実際に悪用された6件目のChromeゼロデイ。2026-09-04にCISA KEVへ追加。

## 8. CVE-2026-85596 — Traefik Kubernetes Ingress クライアント証明書認証バイパス

**原理・根本原因:** Ingressリソースに`nginx.ingress.kubernetes.io/auth-tls-secret`アノテーションが付与されている場合、TraefikのKubernetes Ingress NGINX互換プロバイダは、Ingressの名前空間と名前に基づいて命名されたTLSオプションを生成します。命名/参照の不一致により、`nginx.ingress.kubernetes.io/auth-tls-verify-client: "on"`が設定されたルートが、ルート固有の設定ではなくエントリーポイントのデフォルトTLS設定に静かにフォールバックしてしまうことがあります。その結果、クライアント証明書の提示を必須とすべきルートが、証明書を提示せずに到達可能になります。

**対策:** Traefikをバージョン3.7.11以降にアップグレードしてください。多層防御として、パッチ適用後に(公開されている手順ではなく適切なテストツールを用いて)実際のリクエストで、クライアント証明書を要求すべきルートが未認証のTLSハンドシェイクを実際に拒否することを確認してください。

**対象:** Kubernetes Ingressコントローラーとして、NGINXアノテーションベースのクライアント証明書強制を利用しているTraefik v3、バージョン3.7.0〜3.7.10。2026-09-05頃に開示。

## 9. Mozilla Firefox / Thunderbird — 9月の継続的な修正

**原理・根本原因:** CVE-2026-84129(CVSS 9.8)は、DOM Navigationコンポーネントにおけるサイト分離の失敗であり、ブラウザの分離境界に違反して、あるサイトのコンテンツが別のサイトのコンテンツへ不適切にアクセスできる可能性があります。CVE-2026-84133(CVSS 9.8)は2026-09-08の更新サイクルで修正された、同系統のメモリ安全性・分離関連の修正の一つです。

**対策:** Firefox 155 / ESR 153.2、およびThunderbird 155 / 153.2以降に更新してください。

**対象:** 上記修正より前のFirefoxおよびThunderbirdのバージョン。CVE-2026-84129は2026-09-01に公開(MFSA 2026-82、2026-09-03のレポートでも取り上げ済み)。CVE-2026-84133は2026-09-08に修正。いずれもMozillaからの実悪用報告はありません。

## 10. CVE-2026-20349 — Cisco Secure Firewall ASA/FTD SSL VPN DoS(継続情報)

**原理・根本原因:** Cisco ASA/FTDのRemote Access SSL VPNサービスが巧妙に作成されたHTTPリクエストを処理する際のエラーチェックが不十分(CWE-244)であるため、未認証のリモート攻撃者がデバイスの予期しない再起動を引き起こすことができ、境界ファイアウォールの防御機能とリモートアクセスVPNの接続性の両方を同時に停止させることができます。

**対策:** Ciscoの修正済みソフトウェアを適用してください。回避策はありません。アドバイザリは2026-08-11に公開され、CISAはその後すぐに実悪用を確認しKEVへ追加しました。今週の対象期間中も悪用および対応活動が継続していたため、本レポートに含めています。

**対象:** Remote Access SSL VPNが有効化された、修正版より前のCisco Secure Firewall ASAおよびFTDソフトウェア。
