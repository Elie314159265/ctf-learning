## 1. CVE-2026-85046 — Google Chrome V8 型混同(実悪用中のゼロデイ)

**原理・根本原因:** ChromeのJavaScript/WebAssemblyエンジンであるV8における型混同(type confusion)の欠陥です。細工されたスクリプトコンテンツを処理する際、エンジンがメモリ上のオブジェクトの型を誤認識します。これにより、攻撃者が制御するWebページからヒープ上での範囲外読み書きを引き起こすことができ、ブラウザのレンダリングサンドボックス内で任意コード実行につなげられます。

**対策:**
- Chromeを152.0.7977.82/.83(Windows/macOS)または152.0.7977.82(Linux)以降に更新してください。自動更新されますが、管理端末では強制適用・確認を推奨します。
- Edge、Brave、Opera、Vivaldiなど他のChromiumベースブラウザも、対応するV8修正が提供され次第更新してください。

**対象:** 152.0.7977.82より前のGoogle Chrome(全プラットフォーム)、および脆弱なV8ビルドを含む他のChromiumベースブラウザ。外部研究者Salvatore Gulizia氏により報告され、開示時点でGoogleは既に実際の悪用が存在することを確認しています。修正は2026-09-03に公開、CISA KEVには2026-09-04に追加。2026年に修正された実悪用ChromeゼロデイとしてはCVE-2026-85046が6件目。

## 2. "GitSpawn" — CLI型AIコーディングエージェントにおけるGit設定起点のコード実行

**原理・根本原因:** Claude Code、OpenAI Codex、Cursor、Grok Build、Goose、Hermes Agent、Qwen Codeなど、複数のコマンドライン型AIコーディングエージェントは、リポジトリを開いた直後に定型的なバックグラウンドの`git`操作(`git status`、`git diff`など)を実行します。Gitにはリポジトリ単位の設定項目`core.fsmonitor`があり、ファイル状態確認を高速化するためにGitが呼び出す外部ヘルパープログラムを指定できます。この設定値はリポジトリ自身の`.git/config`から読み込まれるため、信頼できないリポジトリを開いた・クローンした場合、その内容は攻撃者が制御できます。エージェントがインデックスを更新するgitコマンドを自動的に(ユーザーがプロンプトを入力したり承認したりする前に、場合によっては)実行してしまうため、悪意あるリポジトリは設定されたコマンドをユーザー自身の権限で、エージェント本来のサンドボックス・承認フローの外側で実行させることができます。

**対策:**
- 利用しているコーディングエージェントを最新版に更新してください。Goose、Cursorには修正が提供済みで、Claude Codeも一部対応済みです。
- ご利用のツールで修正が確認できるまでは、信頼できない・未レビューのリポジトリに対してAIコーディングエージェントを開いたり実行したりしないでください。クローンしたリポジトリの`.git/config`は信頼できない入力として扱い、エージェントに作業ツリーをインデックスさせる前に内容を確認してください。
- サードパーティのリポジトリを扱う際は、ホストの広範な認証情報を持たないコンテナやVM内でコーディングエージェントを実行してください。

**対象:** Claude Code、OpenAI Codex、Cursor、Grok Build、Goose、Hermes Agent、Qwen Code — 各ベンダーの修正版より前のバージョン。Manifold Securityにより2026-09-01に「GitSpawn」として開示。CVE-2026-72718(Goose)、CVE-2026-71963(Hermes Agent)が採番され、OpenAI Codexにはさらに3件のCVEが割り当てられています。研究者による2026-09-01の再検証時点で、Hermes Agent、Qwen Code、Grok Build、およびClaude Codeの別経路が未パッチのままでした。実悪用の報告はなく、これは開示された脆弱性クラスであり、進行中の攻撃キャンペーンではありません。

## 3. CVE-2026-20274 〜 CVE-2026-20280 — Cisco IOS XR Software ハードニングリリース

**原理・根本原因:** 内部セキュリティレビューの結果、Cisco IOS XRの開発チームはIOS XRの各サブシステムにおけるメモリ安全性・入力処理関連の7件の脆弱性を特定・修正しました。これらはサービス拒否(DoS)や、より深刻なケースではコード実行・権限昇格に悪用されうるものです。外部研究者の報告や実際の悪用ではなく、内部テストにより発見されました。

**対策:**

**対象:** 修正版より前のCisco IOS XR Software全リリース(機器の設定内容を問わず対象)。アドバイザリは2026-09-02公開。実悪用は確認されていません。

## 4. CVE-2026-20354・CVE-2026-20355 — Cisco Secure Email S/MIME 暗号文復号の欠陥(未パッチ)

**原理・根本原因:** Cisco Secure Email(AsyncOS)のS/MIME復号機能は、暗号化されたメッセージの暗号文を処理する前に、その整合性を十分に検証していません。メールゲートウェイ間の通信を傍受・改ざんできる中間者(MitM)攻撃者は、S/MIME暗号化メッセージを細工することで、認証情報なしに本来暗号化されているはずのメール内容の平文を復元できる可能性があります。

**対策:**
- 現時点で修正・回避策は提供されていません。Ciscoは未パッチのままアドバイザリを公開しています。今後提供される更新プログラムの情報を継続的に確認してください。
- 暫定対策として、可能であればS/MIMEトラフィックが通過するメールゲートウェイ間の経路を制限・監視し、パッチが提供されるまではS/MIMEを唯一の機密性保証手段ではなく多層防御の一要素として扱ってください。

**対象:** S/MIMEを有効にしたAsyncOS 16.5.0以下で稼働するCisco Secure Email機器。2026-09-02に公開開示。実悪用の報告はありませんが、パッチが存在しないためリスクは高い状態です。

## 5. CVE-2026-60004 — Gitea 未認証経路によるリモートコード実行(実悪用継続中)

**原理・根本原因:** Giteaの`diffpatch` APIエンドポイントは、一時的なGitリポジトリ内でユーザー提供のパッチを適用しますが、そのパッチが何をインストールできるかを十分に制限していません。通常のリポジトリ書き込み権限を持つアカウント(オープン自己登録が有効なインスタンスでは容易に取得可能)は、これを利用して悪意あるGitフックを設置・発動させ、Giteaを実行しているOSユーザーとしてシェルコマンドを実行できます。

**対策:**
- 直ちにGitea 1.27.1以降にアップグレードしてください。
- 不要であればインターネットに公開されたGiteaインスタンスのオープン自己登録を無効化し、想定外の外向き通信やCPU使用率の急増(観測された攻撃では仮想通貨マイナー型のペイロードが投下されています)がないか監視してください。

**対象:** Gitea 1.17以降、1.27.1の修正版より前のバージョン。8月下旬にパッチ提供、CISAは2026-08-25にKEVカタログへ追加し、連邦機関向け対応期限を2026-08-28としました。今回の対象期間中も(マイナー投下キャンペーンを含め)悪用が継続しているため掲載しています。
