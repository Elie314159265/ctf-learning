## 1. CVE-2026-85102 & CVE-2026-93616 — Check Point Security Gateway / Management Server

**Principle / root cause:** CVE-2026-85102 is an improper certificate-validation flaw during VPN negotiation on Security Gateway and Spark Firewall products: when Site-to-Site or Remote Access VPN is enabled, the certificate-handling logic can be tricked into accepting attacker-supplied material, leading to unauthenticated remote code execution. CVE-2026-93616 is a separate, pre-authentication directory-traversal and arbitrary file-upload flaw in the Management web service, which lets an attacker write files outside the intended directory and trigger execution of an arbitrary script or Java class.

**Mitigation:**
- Apply Check Point's hotfixes released 2026-09-09 for CVE-2026-85102 immediately.
- Patch the Management web service for CVE-2026-93616; treat any internet-facing Management interface as high priority.
- CISA's federal remediation deadline for both is 2026-09-25 — patch now regardless of sector.

**Affected:** Check Point Security Gateway, Spark Firewall, and Management Server products using Site-to-Site/Remote Access VPN or an exposed Management web service. Check Point confirms CVE-2026-93616 has been exploited as a zero-day since 2026-07-23, and a wave of CVE-2026-85102 exploitation against Spark customers began 2026-09-12. Both added to CISA KEV on 2026-09-22.

## 2. CVE-2026-93952 — Arista VeloCloud Orchestrator Unauthenticated Privileged Access

**Principle / root cause:** An improper input-validation flaw (CWE-20) in on-premises VeloCloud Orchestrator (VCO) deployments allows a remote attacker to reach privileged internal functionality without valid credentials. Exploitation requires that certificate-based authentication between a VeloCloud Edge device and the Orchestrator be configured; an attacker with network access to the VCO web UI and the public portion of a legitimate Edge authentication certificate can impersonate trusted Edge-to-Orchestrator traffic to reach functionality that should require full authentication, potentially affecting confidentiality, integrity, and availability of the orchestrator and all edges it manages.

**Mitigation:**
- Apply Arista's patched VCO release immediately (see Arista Security Advisory 0183).
- Restrict network exposure of the VCO web UI and audit certificate-based Edge authentication configuration for anomalies.

**Affected:** Arista VeloCloud Orchestrator on-premises deployments using certificate-based Edge authentication. Disclosed and exploited as a zero-day; added to CISA KEV on 2026-09-22.

## 3. CVE-2026-94127 — F5 BIG-IP APM OAuth Heap Buffer Overflow

**Principle / root cause:** The BIG-IP Access Policy Manager (APM) OAuth UserInfo handler allocates a fixed-size heap buffer (0x4100 bytes) but copies an attacker-controlled `Authorization` header into it without enforcing that size limit — a classic missing-bounds-check heap overflow. The overflow can corrupt adjacent heap memory, including function-pointer-like structures, enabling an unauthenticated attacker to influence program control flow and achieve remote code execution.

**Mitigation:**
- Apply F5's fix described in K000162605 immediately.
- Exposure is limited to virtual servers with an APM access policy and an OAuth profile where APM acts as an OAuth Authorization Server; APM-as-client/resource-server deployments are not affected, but should still confirm posture.

**Affected:** F5 BIG-IP APM configured as an OAuth Authorization Server, versions prior to the fixed release. Exploited as a zero-day; added to CISA KEV on 2026-09-22.

## 4. CVE-2026-7273 — Zyxel GS1900 Series Switches Stack Buffer Overflow

**Principle / root cause:** The CGI web-management program on GS1900 switches contains a stack-based buffer overflow (CWE-121) reachable via a specially crafted HTTP request, with no authentication required. Overwriting stack memory in this way lets an attacker execute operating-system commands on the switch itself.

**Mitigation:**
- Upgrade to the firmware Zyxel released in June 2026 (fixes versions after 2.90(XXXX.1)C0).
- Restrict management-interface access to trusted networks; review switch configurations and credentials for signs of tampering.

**Affected:** Zyxel GS1900 series switches running firmware 2.90(XXXX.1)C0 or earlier. A suspected Chinese-speaking threat actor has exploited this flaw since 2026-08-17, compromising and exfiltrating configuration data and hashed credentials from nearly 1,000 devices across 48 countries. Added to CISA KEV on 2026-09-21; federal remediation deadline is 2026-09-24 (today).

## 5. CVE-2026-61674 — Fluent Bit `out_forward` Secure-Forward Stack Buffer Overflow

**Principle / root cause:** Fluent Bit's `out_forward` output plugin, when configured with Secure-Forward and a shared key, copies a server-controlled "PONG" handshake message into a fixed 32-byte stack buffer without validating the MessagePack type or length of the field. A malicious or impersonated forwarding destination can send an oversized reason value during the initial handshake to overwrite adjacent stack data; on builds without stack-canary protection this can lead to remote code execution as the Fluent Bit process user, while protected builds are at minimum crashed (denial of service).

**Mitigation:**
- Upgrade Fluent Bit to version 5.0.8 or later.
- Ensure `out_forward` destinations are trusted and reachable only over authenticated, network-restricted paths as defense in depth.

**Affected:** Fluent Bit versions 0.11.0 through 5.0.8 (exclusive) using the `out_forward` plugin with Secure-Forward and `Shared_Key`/`Empty_Shared_Key`. Technical write-up and PoC published 2026-09-23; no confirmed in-the-wild exploitation reported yet, but public PoC raises near-term risk given Fluent Bit's widespread use in cloud logging pipelines.

## 6. CVE-2026-89422 — Erlang/OTP TLS 1.3 Server Impersonation

**Principle / root cause:** Erlang/OTP's `ssl` application mishandles an unsolicited `pre_shared_key` extension in a TLS 1.3 `ServerHello` that the client never offered. This incorrectly routes the handshake state machine directly to the "wait_finished" resumption path, skipping certificate-based path validation entirely — including hostname verification, CRL checking, and OCSP stapling. As a result, a client can complete a handshake and believe it is talking to a trusted server even when the peer presents no certificate and no valid session (key exchange without entity authentication, CWE-322), enabling man-in-the-middle impersonation.

**Mitigation:**
- Upgrade to OTP 27.3.4.18, 28.5.0.7, 29.1.1, or later (`ssl` 11.2.12.13 / 11.6.0.6 / 11.7.7 or later).
- Applications that pin TLS 1.3 client behavior should audit for reliance on session resumption without independent certificate checks.

**Affected:** Erlang/OTP from OTP 22.2 up to the fixed versions above, any application making outbound TLS 1.3 client connections via `ssl:connect`. Disclosed 2026-09-22; not yet listed in CISA KEV.

## 7. CVE-2026-94301 — Apache MINA Allow-List Bypass (Incomplete Prior Fix)

**Principle / root cause:** A previous MINA fix (for CVE-2026-47065) added an `acceptMatchers` allow-list filter but only checked it against the declared class name of deserialized objects. `resolveProxyClass()` handling for `java.lang.reflect.Proxy` objects was never updated to enforce the same check, so an attacker can wrap a disallowed class inside a dynamic proxy to bypass the allow-list during Java object deserialization — potentially leading to arbitrary code execution or unauthorized resource access depending on what the host application does with deserialized objects.

**Mitigation:**
- The fix (`resolveProxyClass()` override) was committed only to the 2.2.x branch (e.g., 2.2.8); applications on the 2.0.x/2.1.x maintenance branches must migrate to 2.2.x, as no backport currently exists.
- Where migration isn't immediately possible, avoid deserializing untrusted MINA protocol objects, or wrap deserialization with an independent, proxy-aware allow-list check.

**Affected:** Apache MINA 2.0.x (through 2.0.30) and 2.1.x (through 2.1.14) branches that rely on Java object serialization/deserialization. Disclosed 2026-09-22; no confirmed in-the-wild exploitation reported yet.

## 8. CVE-2026-86473 — Apache Airflow Logout Fails to Revoke Bearer Tokens

**Principle / root cause:** Airflow's Core API logout endpoint only revokes the session credential when it is presented as a `_token` cookie. A client that instead authenticates using the same token as an `Authorization: Bearer` header receives a normal-looking successful logout response, but the underlying token is never invalidated and remains usable until its natural expiry (24 hours by default, configurable) — an incomplete session-termination flaw (CWE-613).

**Mitigation:** Upgrade to Apache Airflow 3.3.2 or later, which fixes token revocation regardless of how the token was presented.

**Affected:** Apache Airflow deployments prior to 3.3.2 whose clients or integrations authenticate via bearer tokens rather than cookies (common for CI/CD and API integrations). Published 2026-09-21; no confirmed in-the-wild exploitation reported.

## 9. CVE-2026-91710 & CVE-2026-93372 — Google Chrome Use-After-Free and WebGL Buffer Overflow

**Principle / root cause:** CVE-2026-91710 is a use-after-free in Chrome's WebAppInstalls component, reachable via a crafted HTML page, that can allow code execution outside the browser sandbox. CVE-2026-93372 is a buffer overflow in Chrome's WebGL implementation (initially flagged on Android) caused by insufficient bounds checking during specific WebGL operations, likewise reachable through a malicious web page and also capable of sandbox-escaping code execution.

**Mitigation:**
- Update to Chrome 153.0.8010.47 or later (Linux) / 153.0.8010.52-53 or later (Windows, macOS, Android) — applied automatically via the browser's update mechanism on most systems; restart the browser to complete the update.
- As a stopgap only, WebGL can be disabled via browser settings/flags, at the cost of breaking WebGL-dependent sites.

**Affected:** Google Chrome and Chromium-based browsers prior to the versions above. Fixed in the stable channel update released 2026-09-22; reporting indicates prior Chrome zero-days this year have been actively exploited, so treat promptly even though these two specific CVEs are not yet confirmed in CISA KEV.

## 10. CVE-2026-58491 — Warpgate SSO Endpoint XSS and Open Redirect

**Principle / root cause:** Warpgate (an SSH/HTTPS/MySQL bastion host used to gate access to backend infrastructure) fails to sanitize the `next` parameter accepted by its SSO callback endpoints (`/warpgate/api/sso/providers/:name/start` and related routes). An attacker-controlled value in this parameter is reflected without proper escaping, enabling reflected cross-site scripting that executes in the authenticated Warpgate origin — giving access to session data and administrative APIs — and the same unsanitized parameter also enables open-redirect abuse.

**Mitigation:** Upgrade Warpgate to version 0.25.5 or later.

**Affected:** Warpgate deployments prior to 0.25.5, particularly any exposing SSO login to end users. No confirmed in-the-wild exploitation reported, but the bastion-host role makes this a high-value target for credential/session theft.

## 11. CVE-2026-32996 — Veeam Agent for Microsoft Windows Local Privilege Escalation

**Principle / root cause:** The Veeam Endpoint Backup service caches an elevated administrator security principal against a client-supplied session UID over a local gRPC named pipe, without binding that UID to the requesting user or connection. Because elevated session UIDs are written to a log file readable by standard users, a low-privileged local user can read a valid UID from the log and reuse it to have the service execute commands as NT AUTHORITY\SYSTEM.

**Mitigation:** Upgrade to Veeam Backup & Replication 13.0.2.29 or later, which updates the Windows agent to build 13.0.3.1220.

**Affected:** Veeam Agent for Microsoft Windows 13.0.1.2067 and earlier 13.x builds. PoC and technical details went public 2026-09-14; Arctic Wolf subsequently reported active exploitation as part of post-compromise privilege-escalation chains.

## 12. CVE-2026-76460 — Cisco ISE Privileged API Authentication Bypass (Continuity Note)

**Principle / root cause:** Insufficient authentication control on an API endpoint in Cisco Identity Services Engine (ISE) and ISE-PIC lets an unauthenticated remote attacker bypass the web-based management interface entirely and reach privileged internal APIs, potentially resulting in root-level command execution and the ability to remove or hide on-device forensic evidence. There is no workaround; infrastructure ACLs on management/control-plane traffic are only a temporary mitigation.

**Mitigation:** Apply Cisco's fix without delay; there is no effective workaround.

**Affected:** Cisco ISE and ISE-PIC, versions prior to the fixed release. Added to CISA KEV on 2026-09-16 (federal deadline 2026-09-19, already passed) — included here because active exploitation and the elevated CVSS 10.0 severity make it relevant to any organization still unpatched this week.

## 13. CVE-2026-87886 — Acronis Backup Plugin Incorrect Default Permissions (Continuity Note)

**Principle / root cause:** The Acronis Backup plugin/extension for cPanel & WHM, Plesk, and DirectAdmin (all on Linux) ships with incorrect default file permissions (CWE-276). An attacker who already holds authenticated, low-privileged access to the hosting server can leverage the misconfigured permissions to cross a privilege boundary and gain substantially greater control on the host.

**Mitigation:** Update to Acronis Backup plugin for cPanel & WHM build 1.9.3.1021+, Plesk extension build 1.8.11.638+, or DirectAdmin plugin build 1.2.3.238+.

**Affected:** Shared-hosting servers running the affected Acronis Backup integrations below the fixed builds. Acronis confirmed in-the-wild exploitation against cPanel & WHM deployments specifically. Added to CISA KEV on 2026-09-16 (federal deadline 2026-09-19, already passed).
