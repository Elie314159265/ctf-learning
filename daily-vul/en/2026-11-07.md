## Priority: newest and actively exploited (last 24–72 hours)

### 1. Node-RED — Missing authentication on HTTP admin interface (CVE-2026-58115, CVSS 10.0)
- **Disclosure date:** Exploitation reported 2026-11-03 (VulnCheck)
- **Status:** Actively exploited in the wild
- **Principle / root cause:** Missing authentication for a critical function. Instances running without admin authentication (`adminAuth`) enabled expose management functionality over HTTP, allowing unauthenticated remote parties to cause the server to run attacker-supplied flows/code. Attackers are scanning the internet automatically and using the access to deploy webshells and botnet payloads.
- **Affected:** Node-RED instances (all platforms) with the editor/admin HTTP interface reachable and `adminAuth` not configured; exact affected/fixed version ranges: unverified.
- **Mitigation:** Upgrade to the vendor-fixed release once confirmed; enable `adminAuth`; never expose the editor/admin API to the internet (bind to localhost / restrict via firewall, VPN, reverse proxy with authentication); review hosts for unexpected flows, new processes, webshells and outbound connections; rotate credentials/secrets stored in flows.

### 2. WordPress Core — Race condition (TOCTOU) during software upgrade (CVE-2026-119977)
- **Disclosure date:** Added to CISA KEV 2026-11-03 (federal remediation due 2026-11-06)
- **Status:** Actively exploited
- **Principle / root cause:** Time-of-check/time-of-use race condition in the core upgrade process; state can change between validation and use, which can lead to arbitrary code execution on the server. Severity is reported inconsistently (CVSS 8.1 vs 9.5 across sources).
- **Affected:** WordPress core sites during/around upgrades; specific versions: unverified.
- **Mitigation:** Update to the latest WordPress core release; enable/verify auto-updates; CISA advises forensic review of potentially affected sites (not just patching): check for unexpected PHP files, modified core files, new admin users, and unusual scheduled tasks; restrict write access to the web root outside of upgrade windows.

### 3. Apple WebKit/OS — CVE-2024-27834 added to CISA KEV
- **Disclosure date:** Added to KEV 2026-11-04 (federal due date 2026-11-18); original CVE dates from 2024
- **Status:** Actively exploited (reported by a security blog as targeting older, unpatched devices; attribution unverified)
- **Principle / root cause:** Memory-safety flaw in Apple's browser engine/OS components, patched in 2024 releases.
- **Affected:** Safari, iOS, iPadOS, macOS, tvOS, watchOS versions prior to the 2024 fixed releases (e.g., devices that no longer receive updates).
- **Mitigation:** Update all Apple devices to the latest supported OS/Safari; replace end-of-support devices; consider Lockdown Mode for high-risk users.

### 4. Zyxel GS1900 series switches — Out-of-bounds write (CVE-2026-107441, CVSS 8.8)
- **Disclosure date:** Firmware fix reported ~2026-11-05/06
- **Status:** Reported as exploited (zero-day)
- **Principle / root cause:** Out-of-bounds write in the switch's firmware that can lead to execution of arbitrary system commands by an unauthenticated attacker.
- **Affected:** Zyxel GS1900 series switches (firmware versions: unverified).
- **Mitigation:** Apply Zyxel's fixed firmware; restrict management interfaces to trusted networks; do not expose web management to the internet; monitor for unexpected config changes.

### 5. Debian APT — Package-swap via man-in-the-middle (CVE-2026-109518, critical) and an OpenSSH-related Alpine bug
- **Disclosure date:** 2026-11-06 (daily digest)
- **Status:** Not reported as exploited
- **Principle / root cause:** Insufficient integrity/authenticity validation in APT's package retrieval allows a network-positioned attacker to substitute a different package than the one requested. Details of the Alpine/OpenSSH issue: unverified (no CVE ID found).
- **Affected:** Debian (and derivatives using the affected APT versions); Alpine OpenSSH packaging: unverified.
- **Mitigation:** Install updated `apt` packages from distribution security channels (via a trusted network); use HTTPS mirrors and verified repository keys; avoid untrusted networks for package operations until patched.
