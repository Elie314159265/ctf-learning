## 1. CVE-2026-0768 — Langflow Unauthenticated RCE

**Principle / root cause:** Langflow's custom component editor includes a code-validation step meant to constrain user-supplied Python before it runs. The validator does not adequately restrict what a submitted "component" definition can do, so a crafted component escapes the intended constraint and executes arbitrary Python in the server process context — without authentication.

**Mitigation:**
- Update Langflow to the vendor's patched release.
- Never expose the Langflow management/API interface directly to the internet; put it behind authentication and network-level access controls (VPN, IP allow-listing).
- Treat any unpatched internet-facing instance as potentially compromised: rotate secrets/environment variables reachable from the Langflow process and review logs for component-creation/execution requests from unrecognized sources.

**Affected:** Self-hosted Langflow deployments on versions prior to the vendor's fix. Threat-intel telemetry recorded renewed, high-volume scanning and exploitation attempts (originating largely from Russia-linked infrastructure) targeting environment variables, Langflow superuser credentials, AWS secrets, and OpenAI API keys, with reporting current as of 2026-09-02.

## 2. CVE-2026-66066 — Ruby on Rails Active Storage: Arbitrary File Read → RCE

**Principle / root cause:** When Active Storage uses the libvips image-processing library to generate image variants, uploaded files are handed to libvips without disabling certain legacy/"unfuzzed" file-format loaders. A crafted upload can abuse format confusion across the Rails/libvips/libmatio/HDF5 processing chain so that, when a variant is generated, the server reads and returns file content it should not — including process environment data that holds `secret_key_base` and other service credentials. Because `secret_key_base` underpins Rails' signed/encrypted cookies, its disclosure enables forging trusted serialized data, which can be escalated further toward remote code execution.

**Mitigation:**
- Update Rails/Active Storage to the vendor's fixed versions and update libvips to a release that supports disabling unfuzzed loaders.
- Treat this as a secrets-compromise event even after patching: rotate `secret_key_base`, the Rails master key and any credentials it decrypts, database credentials, storage-service credentials, and third-party API tokens reachable by the affected process.
- Audit logs for anomalous upload/variant-generation requests and for session activity consistent with forged cookies.

**Affected:** Ruby on Rails applications using Active Storage with libvips for image variants, in default configuration, on versions prior to the vendor's fix. Reporting as of 2026-09-01/02 describes opportunistic scanning that chains this bug with the Langflow issue above (same campaign, different stacks).

## 3. CVE-2026-82329 — JFrog Artifactory Authentication Bypass → Admin Takeover

**Principle / root cause:** An authentication-handling flaw (improper authentication, CWE-287) in self-hosted JFrog Artifactory lets an unauthenticated attacker with network access obtain an administrator-scoped access token under default configuration — effectively minting themselves valid admin credentials without ever proving identity. Because Artifactory commonly sits inside CI/CD pipelines with access to build artifacts, package repositories, and credentials, an admin-level compromise is a direct path into the software supply chain.

**Mitigation:**
- Upgrade self-hosted Artifactory to the patched release (7.161.20 or later).
- JFrog's SaaS/cloud-hosted Artifactory offering is not affected — only self-hosted instances.
- After patching, audit for unexpected admin users/API tokens created around or after the disclosure window, and rotate all Artifactory tokens and any credentials/artifacts the platform had access to if compromise is suspected.
- Restrict network exposure of the Artifactory management interface to trusted networks as defense in depth.

**Affected:** Self-hosted JFrog Artifactory, multiple 7.x releases prior to the fixed version. Exploitation began within days of disclosure and continued into 2026-09-01/02, per current reporting.

## 4. CVE-2026-81578 & CVE-2026-82078 — PaperCut NG/MF Pre-Auth RCE Chain (3rd emergency patch)

**Principle / root cause:** Two chained flaws in the PaperCut NG/MF web management interface:
- **CVE-2026-81578** (auth bypass): specially crafted unauthenticated requests can trigger administrative backend actions before access-control checks complete, letting an attacker alter system configuration without credentials.
- **CVE-2026-82078** (unsafe dynamic class loading): a configurable database-driver name is used to instantiate a class without adequate validation, so an attacker who can influence that configuration (via the bug above) can point it at an attacker-chosen class already present on the classpath, achieving arbitrary code execution.
Chained together, these give an unauthenticated attacker full pre-authentication remote code execution.

**What's new:** PaperCut shipped a third emergency patch ("Release 3") on 2026-09-01. It supersedes the two earlier emergency patches, fixes two regressions those introduced (broken SAML login flow; loss of support for legacy Microsoft SQL Server drivers used for external card lookup), and adds further hardening against related attack chains.

**Mitigation:**
- Install Release 3 even if an earlier emergency patch is already applied — it is cumulative and does not require the prior patches to be installed first.
- Until patched, restrict the PaperCut web interface to trusted/internal networks only; do not expose it directly to the internet.
- This vulnerability chain is on CISA's Known Exploited Vulnerabilities catalog; treat any unpatched internet-facing instance as a high-priority incident.

**Affected:** PaperCut NG and PaperCut MF, major versions 24, 25, and 26.

## 5. CVE-2026-84802 — Craft CMS Information Disclosure

**Principle / root cause:** The `AssetsController::actionMoveInfo` endpoint in Craft CMS's control panel does not correctly enforce per-volume (asset storage) permissions. An authenticated control-panel user can query information (asset counts, total storage size) about volumes they should not otherwise be able to access.

**Mitigation:** Update Craft CMS to version 5.10.12 or later.

**Affected:** Craft CMS versions from 5.7.0 up to (but not including) 5.10.12. CVSS 4.3 (Medium) — requires an authenticated, low-privileged control-panel account, and discloses metadata rather than asset contents.

## 6. CVE-2026-84780 — WP Go Maps Unauthenticated Denial of Service

**Principle / root cause:** Classified as CWE-770 (allocation of resources without limits or throttling). A plugin endpoint reachable without authentication can be driven to consume excessive server resources, allowing an unauthenticated, low-effort remote request to degrade or take down the site.

**Mitigation:** Update the WP Go Maps (formerly WP Google Maps) plugin to the vendor's patched version via the WordPress plugin repository.

**Affected:** WP Go Maps plugin for WordPress, versions up to 10.1.08. CVSS 5.3 (Medium); network attack vector, low complexity, no privileges or user interaction required.

## 7. CVE-2026-8452 — Citrix NetScaler ADC/Gateway: SAML Parsing Overflow → RCE (actively exploited, CISA KEV)

**Principle / root cause:** A pre-authentication heap memory overflow (CVSS v4.0 8.8) in the code that parses SAML single sign-on messages in the NetScaler AAA service. Citrix originally disclosed the bug on 2026-06-30 and described it only as a denial-of-service issue; in mid-August, researchers demonstrated that the same overflow can be driven to unauthenticated remote code execution rather than just a crash. No credentials or user interaction are required to reach the vulnerable code.

**What's new this week:** Exploitation in the wild followed publication of the RCE research, with defenders observing attackers dropping web shells and running basic discovery commands (e.g. `id`, `echo`) on compromised appliances. CISA added the flaw to its Known Exploited Vulnerabilities catalog and set a federal remediation deadline of 2026-08-29.

**Mitigation:**
- Update to a build that includes the fix: 14.1-73.32 or later, or 13.1-63.21 or later (and corresponding FIPS/NDcPP builds).
- Because this was originally patched as a DoS-only issue back in June, confirm you are on a build that specifically addresses the RCE-capable overflow, not just the original June advisory version.
- Review appliance filesystems and logs for unexpected web shells/scripts and unrecognized administrative activity if the appliance was internet-facing and unpatched.

**Affected:** Citrix NetScaler ADC and NetScaler Gateway, builds prior to the versions above.

## 8. WordPress Plugin/Theme Cluster — Five Critical Site-Takeover/RCE Flaws (disclosed 2026-08-27 to 08-29)

A batch of five unrelated critical WordPress plugin/theme vulnerabilities were disclosed within a few days of each other in the last week, together affecting well over a million site installs. None is currently reported as mass-exploited, but all are trivially weaponizable (CVSS 9.8–10.0) and should be patched promptly.

**8a. CVE-2026-82222 — GiveWP donation plugin: unauthenticated PHP Object Injection → RCE (CVSS 10.0).** GiveWP deserializes untrusted, attacker-influenced data captured during the donation workflow without adequate validation. Chaining an unsafe deserialization helper, a donation-processing path that stores attacker-controlled serialized data, and a "gadget chain" already present in bundled libraries lets an unauthenticated attacker achieve arbitrary command execution. Requires a published donation form with an active payment gateway. Fixed in 4.16.7.2; affects versions up to 4.16.7.1.

**8b. CVE-2026-18431 — Avada theme + Fusion Builder: unauthenticated arbitrary file write → RCE (CVSS 9.8).** A chain of missing-authorization (CWE-862) and input-validation weaknesses spanning the Avada theme and its bundled Fusion Builder plugin lets an unauthenticated visitor write an attacker-controlled PHP file to the server (a "zero-click" attack requiring no interaction), leading to full code execution. Requires both Avada and Fusion Builder active, plus certain admin-authored content present. Fixed in Avada 7.16.1 with Fusion Builder 3.16.1 (both must be updated together); affects Avada ≤ 7.16 / Fusion Builder ≤ 3.16.

**8c. CVE-2026-19632 — TranslatePress: unauthenticated account takeover via password-reset disclosure (CVSS 9.8).** The plugin's `trp_get_translations_regular` AJAX action is registered for unauthenticated requests and can be abused to read out plaintext admin password-reset keys that the plugin stores in a database table without restricting read access. Requires the plugin's automatic string-saving feature enabled (default) and the admin's locale set to a secondary published language. Fixed in 3.3.2; affects versions up to 3.3.1.

**8d. CVE-2026-19598 — Pods (Custom Content Types and Fields): unauthenticated privilege escalation to Administrator (CVSS 9.8).** The `pods_admin` AJAX router mishandles a specific request path (JSON meta-box loader) by routing it through an error-handling function that skips all access checks, capability gates, nonce verification, and login enforcement — letting an unauthenticated request perform administrator-level actions, including overwriting any user's password. Fixed in 3.3.9.1; affects versions up to 3.3.9.

**8e. CVE-2026-76581 — WPMU DEV Dashboard: SSO signature-replay authentication bypass (CVSS 9.8).** The plugin's Hub Single Sign-On implementation allows a valid HMAC signature obtained from one SSO step to be replayed against a second, differently-canonicalized SSO step, letting an unauthenticated attacker forge an authenticated administrator session. Fixed in 5.0.2 (a related but distinct auth-bypass, CVE-2026-15459, and RCE, CVE-2026-16051, were fixed in the same 5.0.x line); affects versions up to 5.0.1.

**Mitigation (all five):** Update each plugin/theme to the fixed version listed above via the WordPress plugin/theme repository or vendor channel. Where a site cannot update immediately, disable or restrict access to the affected plugin/theme, and for GiveWP specifically consider temporarily unpublishing donation forms until patched.

## 9. WatchGuard Fireware OS — Pre-Authentication RCE in `iked` (three critical CVEs)

**Principle / root cause:** Three critical, unauthenticated-remote flaws in `iked`, the Internet Key Exchange daemon that handles IPsec VPN negotiation (IKEv1/IKEv2) on WatchGuard Firebox appliances: a heap buffer overflow (CVE-2026-19313), a stack-based buffer overflow (CVE-2026-19318), and a type-confusion bug (CVE-2026-19315). Each can be triggered by specially crafted network traffic sent to the IKE service before any authentication occurs, potentially leading to remote code execution on the appliance.

**Mitigation:** Update to Fireware OS 2026.2.2, 12.12.2, or 12.5.20 (and Dimension 2.3.1) or later. Where immediate patching isn't possible, restrict exposure of the IKE/VPN service to only the peers that need it.

**Affected:** WatchGuard Firebox appliances running Fireware OS versions prior to the fixed releases above. CVSS 9.3 (Critical) for all three; WatchGuard states it is not aware of active exploitation as of disclosure.

## 10. Google Chrome 152 — Critical Use-After-Free Flaws

**Principle / root cause:** Two critical-severity use-after-free bugs — **CVE-2026-84353** (Shared Tab Groups) and **CVE-2026-84352** (WebGL) — involve the browser continuing to access memory after it has already been freed. If an attacker can control what gets placed in that freed memory (e.g. via a crafted web page), this class of bug can lead to memory corruption and, in the worst case, code execution outside the browser's sandbox.

**Mitigation:** Update Chrome to version 152.0.7977.64/.65 (Windows/macOS) or 152.0.7977.64 (Linux) or later; browsers generally auto-update, but a restart is required to apply it.

**Affected:** Google Chrome prior to the versions above, all platforms. Chrome 152 (released 2026-08-25) fixed 327 vulnerabilities in total, 10 rated critical. Google has not disclosed evidence of active exploitation for these flaws and is withholding technical detail until most users have updated.

## 11. Mozilla Firefox 155 / Thunderbird 155 — Multiple High-Severity Flaws

**Principle / root cause:** Firefox 155 (released 2026-09-01) fixes roughly 29 security defects, including several rated high severity. Among them, **CVE-2026-84121** and **CVE-2026-84119** are use-after-free bugs (in the DOM Security and DOM Navigation components respectively) that Mozilla classifies as capable of enabling a sandbox escape — i.e. code running inside the browser's restricted content-process sandbox could, in combination with a separate escape primitive, gain broader access to the host system. The remaining fixes cover further memory-corruption and logic issues typical of a routine browser security update.

**Mitigation:** Update Firefox to version 155 (or the corresponding ESR line: 115.40, 140.15, 153.2) and Thunderbird to 155 (or ESR 140.15 / 153.2).

**Affected:** Mozilla Firefox and Thunderbird prior to the versions above. Mozilla has not reported active exploitation of these issues in the wild.

## 12. CISA KEV Roundup — Older Bugs Newly Confirmed Under Active Exploitation

CISA added six entries to its Known Exploited Vulnerabilities catalog around 2026-08-26, based on fresh evidence of in-the-wild exploitation rather than new disclosures. Listing them here for defenders tracking KEV changes, even though the underlying bugs are old:

- **CVE-2019-1068** — Microsoft SQL Server RCE via the Database Engine service.
- **CVE-2022-0995** — Linux kernel out-of-bounds write allowing local privilege escalation/DoS.
- **CVE-2026-21962** — Improper access control in Oracle HTTP Server and the WebLogic Server Proxy Plug-in.
- **CVE-2015-3246** — Red Hat `libuser` race condition.
- **CVE-2015-5287** — Red Hat Automatic Bug Reporting Tool (ABRT) privilege escalation.
- **CVE-2026-8452** — Citrix NetScaler (see item 7 above; also part of this KEV batch).

**Mitigation:** Apply the vendor patches for each CVE if not already installed; for the decade-old Red Hat and Microsoft bugs, this usually means confirming a system was not missed by legacy patch cycles rather than needing a brand-new fix.
