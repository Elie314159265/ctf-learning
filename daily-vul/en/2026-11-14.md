## Most recent (last 24–48 hours)

## 1. CVE-2026-123039 — Check Point Gaia OS Local Privilege Escalation ("DynamicCLI")

**Principle / root cause:** The root-owned `dynamic_server` daemon in Gaia OS accepts commands over a local IPC socket (`/tmp/dynamic_socket`). The socket is created world-writable and the daemon does not authenticate who connects to it. Any local process, including a low-privileged web or portal process, can send commands that the daemon then runs as root (incorrect permission assignment for a critical resource, CWE-732). In the observed attacks it was the second stage of a chain. Attackers first got code execution through the PHP2Shell flaws (#13) in the Mobile Access portal, then used this bug to become root on the gateway.

**Mitigation:**
- Install the Check Point hotfix / Jumbo Hotfix for your release branch now. One report says R82.20 is fixed in Jumbo Take 14; check sk-level advisories for the other branches.
- If you cannot patch right away, stop `dynamic_server` and keep it from restarting, as Check Point advises. Some CLI functions may stop working while it is off.
- After patching, check that the socket is no longer world-writable. Reporting says it should be `0660` and owned by `root:config`.
- Put internet-facing gateways with Mobile Access / SSL VPN enabled first in line. Hunt for compromise on those gateways: unexpected root processes, new accounts, changed configuration.

**Affected:** Check Point Security Gateway, Firewall, Scalable Platforms, Security Management Server, and Multi-Domain Management on Gaia R81.20, R82, R82.10, R82.20. Some sources also list R81.10 and R81. Exploitation started around 2026-10-30, and Check Point says "a couple of dozen" customers were affected. **Disclosed:** 2026-11-12 (Check Point advisory); added to CISA KEV on 2026-11-13.

## 2. CVE-2026-114713 — UnrealIRCd Command Injection via Message Tags

**Principle / root cause:** UnrealIRCd does not properly neutralize delimiter characters in IRCv3 message-tag values (CWE-140, improper neutralization of delimiters). A remote client can craft tag content that the server forwards unescaped. Downstream parsing then treats that content as extra protocol data or commands, so the attacker crosses the boundary between untrusted user data and trusted server-to-server or command context. The maintainers call it the most serious UnrealIRCd issue in about 15 years and confirmed it was being exploited on the internet.

**Mitigation:**
- Upgrade to **UnrealIRCd 6.2.7.1** or later, or apply the official hot-patch released 2026-11-07.
- If neither can be done right away, apply the maintainers' interim spamfilter workaround first.
- UnrealIRCd 5 has been end-of-life since 2023-07-01. Migrate those servers to version 6.

**Affected:** UnrealIRCd 6.0.0 through 6.2.7 (all versions before 6.2.7.1). Distribution packages (Fedora, Gentoo, and others) are tracking it. **Disclosed:** 2026-11-07 (fix / hot-patch); added to CISA KEV on 2026-11-13; a public exploit was reported on 2026-11-14.

## 3. "4EverAble2Shell" — N-able N-central Unauthenticated RCE Chain (incl. CVE-2026-90436)

**Principle / root cause:** This is a pre-authentication exploit chain against N-central servers that have the **Legacy API** enabled. One step abuses a flaw in the bundled Apache Axis web-services component (CVE-2026-90436, CVSS 9.8). Unauthenticated requests reach SOAP functionality that should require authentication, and the chain ends in code execution as root. The new chain works even on servers running N-central 2026.4 Hotfix 2, released 2026-11-10 for the earlier "Able2Shell" disclosures. The researcher published it along with a set of about 33 alleged N-central vulnerabilities and PoC code, without coordinated disclosure.

**Mitigation:**
- **Disable Legacy API mode** wherever it isn't strictly needed. This removes the condition the chain depends on. N-able has also restricted Legacy API and Intune integration features.
- Install N-central 2026.4 Hotfix 2 (or later), and apply further hotfixes as soon as N-able publishes them.
- Keep the N-central web interface off the internet if you can, or allow only known IP addresses.
- Hunt for compromise: unexpected shell scripts, XMRig/Monero miner processes, and new scheduled tasks on N-central servers. Because N-central manages downstream Windows agents, check those agents for unexpected activity too.

**Affected:** Self-hosted N-central servers, including 2026.4.0.31 and 2026.4 Hotfix 2, with Legacy API enabled. N-able upgrades hosted instances. Researchers saw at least 21 compromised systems, 19 of them on the latest patch level. N-able's advisory reportedly said it had seen no compromise. **Disclosed:** 2026-11-12; exploitation followed within hours.

## 4. CVE-2026-119618 — Apache HTTP Server mod_http2 Race Condition (Heap Corruption → RCE)

**Principle / root cause:** `assign_headers()` in `mod_http2` reads and writes shared state across concurrently processed HTTP/2 streams without proper synchronization (CWE-362, race condition). Concurrent requests can corrupt heap memory, and Apache considers remote code execution possible. HTTP/2 multiplexes many streams over one connection, so a remote client can create that concurrency.

**Mitigation:**
- Upgrade to **Apache HTTP Server 2.4.71** (released 2026-11-11), or to a distribution package with the backported fix (e.g. Red Hat RHSA-2026:34355).
- If you can't upgrade right away, a temporary option is to disable HTTP/2 (remove `h2`/`h2c` from `Protocols` or unload `mod_http2`). This costs performance.
- Put internet-facing reverse proxies and TLS terminators running httpd first.

**Affected:** Apache HTTP Server 2.4.55 through 2.4.70 with mod_http2 enabled. One source also lists standalone mod_h2 2.0.8–2.0.42. Many internet-exposed servers are affected. No exploitation in the wild has been reported. **Disclosed:** 2026-11-11 (some sources say 2026-11-12).

## 5. CVE-2026-123710 — Red Hat Quay Registry Signing-Key Takeover

**Principle / root cause:** A broken authorization check lets an unauthenticated caller who has an anonymous token register a signing key that the registry then trusts and that never expires. With that key the attacker can mint tokens the registry accepts, so they effectively take over token signing and can reach private repositories. Red Hat notes that deleting a rogue key does not last until a fixed build is deployed.

**Mitigation:**
- Apply the Quay updates in Red Hat errata RHSA-2026:99023 / 99024 / 99026 (or later) for your release stream.
- After upgrading, review and remove any unexpected service keys, then rotate credentials and tokens.
- Limit network exposure of Quay instances, and turn off anonymous access where it isn't needed.

**Affected:** Red Hat Quay (multiple supported 3.x streams; see the errata for exact builds). **Disclosed:** 2026-11-11 (updated 2026-11-12). No known exploitation.

## Other notable items this week

## 6. CVE-2026-124194 — Microsoft Outlook Spoofing / NTLMv2 Hash Disclosure (Patch Tuesday Zero-Day)

**Principle / root cause:** Classic Outlook fails to show its usual external-content / unsafe-connection warning when it processes a specially crafted message file. Opening the file makes Outlook connect to an attacker-controlled network location, which automatically sends the user's NTLMv2 authentication material. Attackers can crack that material offline or relay it. The user has to open the file; the Preview Pane is not an attack vector.

**Mitigation:**
- Apply the November 2026 Office / Microsoft 365 Apps update, which ships through Click-to-Run channels. Reported fixed builds include Current Channel Version 2610 (Build 20527.20196), LTSC 2021 ≥ 16.0.14334.21048, and LTSC 2024 ≥ 16.0.17932.21140. Confirm these in the Microsoft Security Update Guide.
- Block outbound SMB (TCP 445) and WebDAV to the internet. Add users to the Protected Users group and/or restrict NTLM where you can.
- Office 2016/2019 reportedly will not receive a fix. Plan to migrate.

**Affected:** Microsoft 365 Apps for Enterprise, Office LTSC 2021, Office LTSC 2024 (classic Outlook for Windows). **Disclosed:** 2026-11-10; added to CISA KEV on 2026-11-10 (deadline 2026-11-24). The same Patch Tuesday fixed roughly 1,093–1,235 CVEs; counts differ by source.

## 7. CVE-2026-125350 — Google Chrome XML Use-After-Free (Zero-Day)

**Principle / root cause:** The XML-handling component frees memory and then reaches it again through a stale reference (use-after-free). A crafted web page can turn that into memory corruption and code execution inside the renderer. Google confirmed an exploit exists in the wild. It is the eighth exploited Chrome zero-day of 2026.

**Mitigation:**
- Update Chrome to **157.0.8103.50/.51** (Windows/macOS) or **157.0.8103.50** (Linux) or later, then relaunch the browser.
- Update other Chromium-based browsers (Edge, Brave, Opera, Vivaldi) as their vendors ship the fix.

**Affected:** Chrome before 157.0.8103.50, including the 157.0.8103.38/.39 builds that reached Stable on 2026-11-03. **Disclosed / patched:** 2026-11-09; added to CISA KEV on 2026-11-10 (deadline 2026-11-24).

## 8. CVE-2026-116606 & CVE-2026-111560 — Barracuda ESG Authentication Bypass + Command Injection

**Principle / root cause:** CVE-2026-116606 is a pre-authentication authorization bypass in Email Security Gateway. An unauthenticated caller can reach a configuration-backup import/restore function. CVE-2026-111560 is an OS command-injection flaw: a configuration value (for example a time-zone setting) reaches a shell command without sanitization. In the chain, the bypass is used to plant a malicious configuration value, and the injection then runs it as root.

**Mitigation:**
- Apply Barracuda's patches (BNSF-40425 for firmware 9.4.017 and later, BNSF-40430 for earlier firmware). Older appliances may need several upgrade steps.
- Make sure automatic security definitions/patches are enabled, and check appliances for signs of compromise.

**Affected:** ESG before 9.4.0.030 (bypass). The command injection also affects Barracuda Load Balancer ADC, WAF, Web Security Gateway, Message Archiver, and WCC (version tables differ by source; see the Barracuda advisory). **Disclosed / patched:** 2026-11-02; added to CISA KEV on 2026-11-10 with a 2026-11-13 deadline, which has passed.

## 9. CVE-2026-20320 — Cisco BroadWorks OCI-P XML External Entity (XXE)

**Principle / root cause:** The Open Client Interface (OCI-P) XML parser resolves external entities in untrusted XML input (CWE-611). An unauthenticated remote attacker can make the parser read local files or reach other resources, which exposes sensitive configuration data. Attacks have targeted BroadWorks Xtended Services Platform (XSP) deployments run by telecom providers.

**Mitigation:**
- Upgrade to **RI.2026.07** or later (Cisco advisory cisco-sa-bworks-xxe-uwUd7CEt). Cisco lists no workaround.
- Until you upgrade, allow only trusted client hosts and networks to reach OCI-P.

**Affected:** BroadWorks Application Delivery Platform, Application Server, Profile Server, and Xtended Services Platform before RI.2026.07. **Disclosed:** 2026-08-19 (advisory); added to CISA KEV on 2026-11-10 (deadline 2026-11-24).

## 10. CVE-2026-111793 — Openwave Messaging Webtop Media Transcoder Information Disclosure

**Principle / root cause:** An authenticated user can upload a specially crafted file to the media transcoder. Because the transcoder doesn't validate the file properly, its contents can make the service disclose sensitive information.

**Mitigation:** Apply the vendor fix, restrict access to the Webtop / transcoder service, and review upload logs. At least 13 organizations using the affected telecom provider's services may have been targeted.

**Affected:** Openwave Messaging Webtop Media Transcoder (see vendor advisory for versions). **Status:** Added to CISA KEV on 2026-11-10 (deadline 2026-11-24).

## 11. CVE-2026-123158 ("sshole") — OpenSSH Password Authentication Bypass on musl / non-PAM Builds

**Principle / root cause:** When portable OpenSSH is built against **musl libc without PAM**, `sshd` handles certain shadow-password fields wrongly. For accounts whose field marks them as disabled or key-only (for example a literal `*`), musl's `crypt()` behaves differently from glibc's, and `sshd` lacked a check for that difference. As a result it can accept an arbitrary, unusually long password for those accounts. The flaw had been in the code for about 10 years.

**Mitigation:**
- Upgrade to **OpenSSH 10.6p2** or later. Alpine fixed builds: edge 10.6_p2-r0, 3.24.4, 3.23.8.
- Stopgap: set `PasswordAuthentication no` (and `KbdInteractiveAuthentication no`) and use key-based authentication only.
- Check Alpine-based containers and appliances, which often run sshd with password authentication left on.

**Affected:** OpenSSH portable before 10.6p2 built with musl and without PAM (Alpine Linux default sshd, some embedded systems and containers). glibc/PAM builds are not affected. **Disclosed:** 2026-11-05; public PoC available; added to CISA KEV on 2026-11-09 (deadline 2026-11-12).

## 12. CISA KEV 2026-11-09 Batch — GPUStack, FreeSWITCH, IBM Aspera Faspex

- **CVE-2026-102895 — GPUStack (CVSS 9.8):** An authentication/authorization flaw gives a remote, unauthenticated attacker full administrator access. Attackers used it to register malicious inference backends and run code on the host. *Fix:* upgrade to **2.2.0**; do not expose the management API to the internet. *Affected:* 2.1.1 and earlier.
- **CVE-2026-116779 — SignalWire FreeSWITCH (CVSS 9.8):** Code injection. Content in a SIP MESSAGE could reach FreeSWITCH's internal API command handling, which can include OS-level commands. *Fix:* upgrade to **1.11.3**; filter or limit SIP MESSAGE from untrusted peers. *Affected:* versions before 1.11.3.
- **CVE-2026-123218 — IBM Aspera Faspex (CVSS 9.8):** Incorrect authorization. A crafted request can get past authorization checks. *Fix:* upgrade to **Aspera Faspex 5.0.19 PL1** or later. *Affected:* Faspex 5 before 5.0.19 PL1.

All three were added to CISA KEV on 2026-11-09 with a three-day deadline (2026-11-12).

## 13. CVE-2026-109618 & CVE-2026-109619 ("PHP2Shell") — PHP Runtime RCE (Context)

**Principle / root cause:** Two flaws in the PHP runtime's request handling. A crafted HTTP request can lead to code execution in any application running on an unpatched PHP, whatever the framework (WordPress, Drupal, Magento, and others). Exploitation in the wild has been confirmed, including against Apache mod_php. Attackers used these flaws for the initial access in the Check Point attacks (#1).

**Mitigation:** Upgrade PHP to **8.5.12, 8.4.27, 8.3.36, or 8.2.35** or later. Updating a CMS or its plugins does not fix this. Appliances that embed PHP need the vendor's hotfix.

**Affected:** PHP 8.2–8.5 branches before the versions above. **Disclosed:** around 2026-10-20 (pre-dates this window; listed here because it is still being exploited).

## 14. CVE-2026-19868 — SonicWall SonicOS SSL-VPN MFA Bypass (Context)
