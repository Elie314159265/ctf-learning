## 1. CVE-2026-85046 — Google Chrome / Chromium V8 Type Confusion (Actively Exploited Zero-Day)

**Principle / root cause:** A type-confusion bug in V8, Chrome's JavaScript/WebAssembly engine (CWE-843). During compiler optimization, an array holding `PACKED_ELEMENTS` can incorrectly be assigned a `PACKED_SMI_ELEMENTS` map — the engine's internal bookkeeping about what kind of data the array holds becomes wrong. A malicious web page can trigger this mismatch to turn the confusion into an arbitrary read/write primitive on the JavaScript heap, leading to code execution inside the renderer sandbox.

**Mitigation:**
- Update Chrome to 152.0.7977.82/.83 (Windows/macOS) or 152.0.7977.82 (Linux) or later; this applies automatically on browser restart but should be verified.
- Update Chromium-based browsers (Edge, Brave, Opera, etc.) once their vendors ship the corresponding fix.

**Affected:** Google Chrome prior to 152.0.7977.82. Reported by an external researcher on 2026-08-04; patched 2026-09-03; Google confirmed an exploit exists in the wild (the sixth actively exploited Chrome zero-day patched in 2026). Added to the CISA KEV catalog on 2026-09-04.

## 2. CVE-2026-85596 — Traefik Kubernetes Ingress Client-Certificate Authentication Bypass

**Principle / root cause:** When Traefik's Kubernetes Ingress provider translates an nginx-style Ingress annotation (`nginx.ingress.kubernetes.io/auth-tls-verify-client`) into its internal TLS options, the generated option name is derived from the Ingress object's namespace and name. If two Ingress resources share the same host, the same client-CA secret, and the same client-auth mode, Traefik can detect this as a conflicting TLS options definition for that host and silently falls back to the entry point's default TLS configuration — which does not request a client certificate at all. A route that was meant to require mutual TLS becomes reachable by anyone.

**Mitigation:**
- Upgrade to Traefik 3.7.11 or later.
- Until patched, audit Kubernetes Ingress objects for hosts that are configured more than once with client-certificate requirements, and confirm client-cert enforcement is actually being applied (e.g., via a test connection without a client cert).

**Affected:** Traefik v3.7.0 through v3.7.10 (only the 3.7 line). Publicly disclosed 2026-09-04; no known exploitation reported yet.

## 3. CVE-2026-11613 — Divi Ajax Filter (WordPress Plugin) Unauthenticated Local File Inclusion / RCE

**Principle / root cause:** The plugin's AJAX handler accepts a `custom_loop_template` parameter and, when the `loop_templates` option is set to `custom-template`, uses that user-supplied value directly in a PHP file-include operation without validating or restricting it to an allow-listed path (CWE-98). Because the include target is attacker-controlled and reachable pre-authentication, this can be combined with any means of placing attacker content on the server (e.g., log files, uploaded media) to achieve remote code execution.

**Mitigation:**
- Update the Divi Ajax Filter plugin to a version beyond 5.1.2 as soon as a fix is available; if no fix has shipped yet, deactivate the plugin.
- Restrict direct write access to upload/log directories and monitor web server logs for unusual `custom_loop_template` values in requests.

**Affected:** Divi Ajax Filter (Divi Engine) ≤ 5.1.2. Publicly disclosed 2026-09-03; no confirmed in-the-wild exploitation at time of writing, but the flaw is unauthenticated, network-reachable, and trivially scannable — treat as high-risk.

## 4. CVE-2026-85216 — MISP LDAP/LinOTP Authentication Bypass

**Principle / root cause:** MISP's custom `LdapAuthenticate` and `LinOTPAuthenticate` components were written to replace CakePHP's built-in `FormAuthenticate` logic but did not replicate its input-validation checks. As a result, empty or non-string credential values can reach the underlying authentication calls. On the LDAP path, an attacker who knows a valid user's identifier can submit an empty password; some LDAP server configurations that permit "unauthenticated bind" will return a successful bind for a valid distinguished name paired with an empty password, effectively granting a session without knowing any real password.

**Mitigation:**
- Apply the MISP patch that enforces strict type/non-empty checks on authentication identifiers and passwords.
- As defense in depth, disable unauthenticated/anonymous bind on any LDAP server used for MISP authentication.

**Affected:** MISP threat-intelligence platform installations using LDAP or LinOTP authentication, versions up to 2.5.45. Published 2026-09-03/2026-09-04.

## 5. CVE-2026-4644 — Google Cloud Integration Connectors HTTP Connector Missing Authorization

**Principle / root cause:** The HTTP Connector within Google Cloud's Integration Connectors service failed to verify that a caller was authorized to attach a given service account to a connection. An authenticated user could exploit this to attach a more privileged service account than they should have access to, escalating privileges and potentially taking over the wider Google Cloud project.

**Mitigation:** None required from customers — Google fixed this server-side on 2025-12-11, prior to public disclosure. This entry is included for awareness since the CVE record was only published this week (2026-09-04); confirm your audit logs show no anomalous service-account attachment activity from before the fix date if you want to close the loop.

**Affected:** Google Cloud Integration Connectors, HTTP Connector, prior to the 2025-12-11 server-side fix. CVSS 8.5 (High). No customer action needed.

## 6. CVE-2026-82538 — ILIAS Repository Trash Table SQL Injection

**Principle / root cause:** ILIAS's repository "trash" view accepts a table-sort parameter from the HTTP request and inserts it directly into the `ORDER BY` clause of a SQL query, instead of validating it against the actual list of sortable columns (CWE-89). Because the database layer has multi-statement execution enabled, an authenticated user with write permission on any container can use this to inject stacked SQL queries, giving full read/write access to the database and a path to administrator account takeover.

**Mitigation:**
- Upgrade to ILIAS 9.22, 10.10, 11.3, or later.
- Where an immediate upgrade isn't possible, restrict which users are granted write permission on repository containers, and monitor database logs for anomalous multi-statement queries from the application user.

**Affected:** ILIAS e-learning platform, versions prior to 9.22 / 10.10 / 11.3. Published 2026-09-04; no known in-the-wild exploitation yet, but the barrier to entry is low (requires only a low-privilege authenticated account with write access to one container).

## 7. CVE-2026-52767 — YesWiki Unauthenticated ActivityPub Signature-Verification Bypass

**Principle / root cause:** YesWiki's `HttpSignatureService::verifySignature()` checks the outcome of PHP's `openssl_verify()` using a loose boolean negation (`if (!openssl_verify(...))`). `openssl_verify()` can return `1` (valid), `0` (invalid), or `-1` (error) — and in PHP's truthiness rules, `-1` is treated as "truthy," so the negation incorrectly treats an *error* condition (such as a malformed or mismatched key/algorithm combination) the same as a successful signature check, letting the request through unauthenticated.

**Mitigation:**
- Upgrade YesWiki to version 4.6.6 or later, which checks the return value strictly (`=== 1`) rather than by loose negation.
- Related SSRF issue CVE-2026-52769 (ActivityPub `Signature.keyId` fetch) should be patched in the same update — apply both fixes together.

**Affected:** YesWiki versions 4.6.2 up to (but not including) 4.6.6.

## 8. CVE-2026-84642 — Mozilla Thunderbird Attachment-Hostname Filter Bypass

**Principle / root cause:** The `mail.allowed_attachment_hostnames` advanced setting is used to build a regular expression that decides which remote hosts Thunderbird is allowed to fetch attachments from. The configured hostname values were inserted into that regex without escaping special regex characters (e.g., `.`), so a hostname meant to allow only one specific domain could unintentionally also match other, unintended hostnames — weakening the attachment-source restriction.

**Mitigation:** Update to Thunderbird 155 or Thunderbird ESR 153.2 (same release train as the Firefox 155 / ESR 153.2 update covered in the 2026-09-03 report).

**Affected:** Thunderbird versions prior to 155 / ESR prior to 153.2. Released 2026-09-01; no known in-the-wild exploitation.
