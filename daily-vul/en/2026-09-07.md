## 1. CVE-2026-85046 — Google Chrome V8 Type Confusion Zero-Day

**Principle / root cause:** A type-confusion bug (CWE-843) in V8, Chrome's JavaScript/WebAssembly engine, causes the engine to misinterpret the type of an in-memory object. Specially crafted JavaScript or HTML content can trigger this mismatch, corrupting memory in a way that gives an attacker a read/write primitive inside the renderer process. That primitive can then be leveraged to execute arbitrary code inside the Chrome sandbox.

**Mitigation:**
- Update to Chrome 152.0.7977.82/.83 (Windows/macOS) or 152.0.7977.82 (Linux), or later; the update is rolling out automatically but should be verified/forced on managed fleets.
- Apply the same fix to Chromium-based browsers (Edge, Brave, Opera, etc.) once their downstream updates ship.

**Affected:** Google Chrome prior to 152.0.7977.82/.83. Reported to Google on 2026-08-04; patched and disclosed 2026-09-03/04; added to CISA KEV on 2026-09-04. This is the sixth actively exploited Chrome zero-day patched in 2026.

## 2. CVE-2026-67276 + CVE-2026-86060 ("MikroTrick") — MikroTik RouterOS SSH Auth Bypass Chain

**Principle / root cause:** CVE-2026-67276 is an incomplete public-key comparison in RouterOS's SSH authentication: the server checks only the key type and RSA modulus of an offered public key, not the exponent, so an attacker who already knows a valid authorized modulus (e.g., from a previously exposed key) can construct a different key pair that RouterOS still accepts as authorized — without ever possessing the real private key. CVE-2026-86060 is a separate argument-handling flaw in the SSH login helper: a username beginning with a prohibited character lets an attacker alter the trusted policy mask applied to the session, escalating the resulting shell's privileges. Chained together over an exposed SSH port, the two flaws let an unauthenticated remote attacker obtain full administrative control of a router.

**Mitigation:**
- Upgrade to RouterOS 6.49.21 (Long-term), 7.23.4 (Long-term), or 7.24.2 (Stable), or later.
- Disable SSH exposure to the internet; restrict SSH access to trusted management networks/VPNs.
- Audit devices for unexpected highly-privileged accounts (attackers have been observed creating an account named "ops").

**Affected:** MikroTik RouterOS versions prior to the fixed releases, with SSH service reachable. Active exploitation observed since at least 2026-09-02; confirmed and publicized by CERT Polska around 2026-09-06.

## 3. CVE-2026-18658 — IBM Operational Decision Manager Unauthenticated SQL Injection to RCE

**Principle / root cause:** An unauthenticated web endpoint in IBM Operational Decision Manager fails to neutralize special characters in user-supplied input before using it in backend SQL queries (CWE-89, SQL injection). Beyond typical data exfiltration, the injectable database context can be abused to write a web shell into the application's web root, turning the SQL injection into full remote code execution.

**Mitigation:**
- Apply IBM's fix for the affected Operational Decision Manager versions (9.6.0.0, 9.5.0.x, 9.0.0.1, 8.12.0.1, 8.11.1.0, 8.11.0.1, and earlier) per IBM's security bulletin.
- Restrict network access to ODM management/rule-execution interfaces to trusted networks pending patching.

**Affected:** IBM Operational Decision Manager versions 8.11.0.1, 8.11.1.0, 8.12.0.1, 9.0.0.1, 9.5.0.0, 9.5.0.1, 9.6.0.0. Published 2026-09-04 (reserved 2026-08-03); CVSS 9.8; no confirmed in-the-wild exploitation reported yet, but the pre-auth-to-RCE path warrants urgent patching.

## 4. CVE-2026-86206 / CVE-2026-86207 — N-able N-central Access-Control & Authentication Bypass

**Principle / root cause:** CVE-2026-86206 is an access-control filter bypass that exposes internal-only N-central APIs to requests that should have been blocked at the edge. CVE-2026-86207 is a related authentication bypass affecting APIs intended to be reachable only from within the application itself. Used together, the two flaws let an attacker who can reach the N-central web interface bypass access restrictions and create unauthorized administrative accounts, without needing valid credentials first.

**Mitigation:**
- Upgrade on-premises N-central deployments to 2026.3 HF3 (which fixes these two issues) — and note that N-able has since shipped HF4 for a separate, more severe pre-auth RCE (CVE-2026-86218, CVSS 10.0) discovered in the same review; apply the latest hotfix available.
- Restrict N-central web/management interfaces from direct internet exposure; monitor for unexpected new administrator accounts.

**Affected:** On-premises N-able N-central prior to 2026.3 HF3 (and HF4 for the separate RCE). Disclosed via responsible disclosure by Rapid7 Labs and Huntress; patched 2026-09-05. No confirmed exploitation of CVE-2026-86206/86207 at disclosure time, but this is the third/fourth N-central hotfix in five to six weeks — treat as high priority.

## 5. CVE-2026-10196 — Mail Mint (WordPress plugin) PHP Object Injection to RCE

**Principle / root cause:** The Mail Mint email-marketing plugin deserializes untrusted input inside its `handle_form_submission` handler without validation (CWE-502). Because a PHP "POP chain" (a sequence of existing classes whose magic methods can be chained together) is present in the plugin's or WordPress's loaded code, an attacker-supplied serialized object can trigger unintended method calls during deserialization, ultimately allowing arbitrary code execution on the server — all without authentication.

**Mitigation:**
- Update Mail Mint; note that version 1.23.1 only partially addressed the issue, so confirm you are on the latest release that fully closes the deserialization path.
- Until a complete fix is confirmed, disable the plugin or block direct access to the vulnerable form-submission endpoint via a WAF rule targeting serialized-object patterns in form submissions.

**Affected:** Mail Mint – Email Marketing, Newsletter, Email Automation & WooCommerce Emails, all versions up to and including 1.31.0. CVSS 9.8. Disclosed on or around 2026-09-06.

## 6. CVE-2026-83627 — Hummingbird Performance (WordPress plugin) Code Injection to RCE

**Principle / root cause:** Hummingbird's page-cache debug logging (`log_msg()` in `class-page-cache.php`) writes attacker-influenced data — including cookie values with a `wphb_cache_` prefix — into a log file that lives inside the web root. That log file is meant to be protected from direct execution, but a PHP namespace-resolution error breaks the intended protection, so a crafted cookie value written into the log can be executed as PHP code when the file is later requested.

**Mitigation:**
- Update to Hummingbird Performance 3.21.1 or later.
- As defense in depth, ensure debug/log directories under the web root are excluded from PHP execution at the web-server level.

**Affected:** Hummingbird – Speed Optimization plugin (wpmudev), versions up to and including 3.21.0. Disclosed on or around 2026-09-05.

## 7. CVE-2026-13447 — MStore API (WordPress plugin) Unauthenticated Account Creation

**Principle / root cause:** The MStore API plugin, used to bridge WordPress/WooCommerce sites with mobile apps, exposes an account-registration/edit API that is meant to be gated by a cryptographic signature check. The plugin fails to properly verify that signature, so a request can be crafted without a valid signature and still be accepted, letting an unauthenticated attacker create arbitrary new accounts — including ones with administrator privileges.

**Mitigation:**
- Update MStore API to the latest version that restores proper signature verification (confirm the fix version against the vendor's changelog, as this plugin family has had several related authentication-bypass CVEs).
- Audit WordPress user lists for unexpected administrator accounts if the plugin has been internet-exposed and unpatched.

**Affected:** MStore API – Create Native Android & iOS Apps On The Cloud, versions up to 4.20.0. Disclosed on or around 2026-09-05/06.
