## Newest items (last 24–48 hours)

## 1. CVE-2026-123890 — VMware vCenter Server Authentication Bypass (VMware Directory Service)

**Principle / root cause:** This is an authentication bypass through an alternate path or channel (CWE-288) in the VMware Directory Service (vmdir) component used by vCenter. An attacker with network access to vCenter can reach privileged functionality through a path that does not enforce the normal authentication checks. Compromising vCenter gives control over the whole virtual infrastructure it manages.

**Mitigation:**
- Apply the fixes from VMSA-2026-0009: vCenter **9.1.1.0200**, **9.0.2.0200**, **8.0 U3m**, and VMware Cloud Foundation **5.2.5**.
- Broadcom lists no workaround, so patching is the only fix. Until you patch, limit network access to vCenter management interfaces to dedicated admin networks.
- vCenter 7.0 fixes go only to customers with extended support. Broadcom says to presume vSphere 6.5/6.7 are affected, so plan to migrate.
- Upgrade-path caveat: installing 8.0 U3m or 9.0.2.0200 blocks a later upgrade to VCF 9.1.1. Broadcom suggests upgrading to 9.1.1 first, or waiting for VCF 9.1.2.
- Given the zero-day reports, review vCenter logs for unexpected logins or accounts going back to at least September 2026.

**Affected:** VMware vCenter Server 9.1.x, 9.0.x, 8.0, 7.0 (and EOL 6.x); VMware Cloud Foundation 5.x; Telco Cloud Infrastructure. **Disclosed:** 2026-11-19. **Exploitation:** Reports attribute zero-day exploitation since early September 2026 to a China-nexus group (attributed to Mandiant). At least one tracker lists it as not known exploited, so treat it as likely exploited and check Broadcom's advisory.

## 2. CVE-2026-90436 — Apache Axis 1.x Unsafe Reflection in SOAP Fault Handling

**Principle / root cause:** This is unsafe reflection (CWE-470). When Axis 1.x processes a SOAP fault, it takes a class name from the message and loads, and can instantiate, that class *before* checking that it is a legitimate fault type. An unauthenticated request can therefore make the server load arbitrary classes on its classpath. The direct impact depends on which classes the hosting application ships. In real products such as Confluence and N-central, this leads to remote code execution.

**Mitigation:**
- Axis 1.x is end-of-life, and no fixed 1.x release is expected. Migrate to a maintained SOAP stack (for example Apache Axis2/Java), or apply the upstream patch commit if you must keep 1.x.
- **Atlassian Confluence Data Center:** upgrade to **9.2.28** or later (10.x is not affected). If you cannot upgrade yet, disable the Remote API.
- **N-able N-central:** apply the vendor's fixed release.
- Inventory Java applications that bundle `axis-1.x.jar`.

**Affected:** Apache Axis ≤ 1.4 (all 1.x); Confluence Data Center 1.x–9.x when the Remote API is enabled; N-able N-central. **Disclosed / KEV:** added to CISA KEV on 2026-11-18. Rapid7 has observed exploitation. Public PoCs exist.

## 3. CVE-2026-90817 — REDCap Unauthenticated Code Injection

**Principle / root cause:** This is a code injection flaw (CWE-94, with CWE-73 external control of file name/path) in REDCap's survey passthrough routing and Data Import logic. An attacker needs only a valid *public survey* link, with no account, to get attacker-influenced input processed as server-side code. The result is code execution as the web server / PHP user.

**Mitigation:**
- Upgrade to a fixed REDCap release for your branch. Sources cite **16.0.49**, **17.3.10**, and **17.4.4** or later; confirm with Vanderbilt's REDCap community notice.
- Research and clinical data often sit in REDCap. After patching, review the server for unexpected files or web shells and rotate credentials.
- Consider restricting public survey endpoints with a WAF or allow-list until you patch.

**Affected:** REDCap 13.3.0 and later, up to the fixed builds listed above. **Disclosed / KEV:** added to CISA KEV on 2026-11-18 (federal deadline 2026-11-21).

## 4. CVE-2026-40217 — LiteLLM Custom-Code Guardrail Sandbox Escape

**Principle / root cause:** The LiteLLM proxy lets administrators define "custom code" guardrails that run inside a restricted sandbox. The sandbox can be escaped through an alternate channel, so code supplied through the guardrail feature runs with the full privileges of the proxy process. Researchers also describe a chain in which a low-privilege virtual-key holder escalates to admin (CVE-2026-47101) and then uses this flaw for RCE.

**Mitigation:**
- Upgrade to **1.83.11** or later. To close the full reported chain, upgrade to **v1.83.14-stable** or later.
- Rotate the upstream LLM provider API keys and master/virtual keys stored in the proxy.
- Restrict who can create or edit guardrails, and audit existing custom-code guardrails.

**Affected:** BerriAI LiteLLM ≥ 1.81.8 and < 1.83.10/1.83.11 (GHSA-wxxx-gvqv-xp7p). **KEV:** added 2026-11-18 (federal deadline 2026-12-02).

## 5. CVE-2024-10441 — Synology DSM Improper Output Encoding Leading to RCE

**Principle / root cause:** This is an improper encoding/escaping of output in a DSM system-plugin daemon. Data that is not properly escaped can be interpreted in a privileged context, which lets a remote attacker execute code on the NAS. The flaw was first disclosed in 2024. It was added to KEV this week after evidence of exploitation.

**Mitigation:**
- Update to the minimum fixed build for your branch (Synology-SA-24:20 / SA-24:23): DSM **7.2.2-72806-1**, **7.2.1-69057-6**, **7.2-64570-4**, **7.1.1-42962-7**, **6.2.4-25556-8**; BeeStation Manager **1.1-65374**; Unified Controller **3.1.4-23079**.
- Do not expose DSM management directly to the internet. Use VPN access instead.

**Affected:** Synology DSM 6.2.4–7.2.x before the builds listed above; BeeStation; Unified Controller. **Original disclosure:** 2024. **KEV:** 2026-11-18 (federal deadline 2026-11-21).

## 6. CVE-2026-132165 — Drupal Core Installer Takeover / RCE (SA-CORE-2026-017)

**Principle / root cause:** Drupal's installer (`core/install.php`) can be reached and driven by an anonymous user on an already-installed site under certain conditions. This lets the attacker re-run installation against attacker-controlled settings, take over the site, and in turn execute code.

**Mitigation:**
- Upgrade to **11.4.13**, **11.3.22**, or **10.6.22**.
- If you cannot upgrade right away, block public access to `/core/install.php` and make sure `settings.php` and its directory are not writable by the web server.
- Older branches (11.2.x and below, 10.5.x and below, 8, 9) are EOL and get no fix, so upgrade.

**Affected:** Drupal 10.x < 10.6.22; 11.0–11.3.x < 11.3.22; 11.4.x < 11.4.13. **Disclosed:** 2026-11-18. No confirmed exploitation yet, but Drupal warns that exploits may surface within hours or days.

## 7. CVE-2026-123007 — NGINX HTTP/2 Flow-Control Integer Underflow

**Principle / root cause:** This is an integer underflow (CWE-191) in NGINX's HTTP/2 flow-control window accounting. A crafted sequence of HTTP/2 activity can wrap a size counter, and the resulting out-of-bounds read/write on the worker's heap can potentially lead to unauthenticated RCE. Rapid7 notes that exploitation requires a very large amount of HTTP/2 traffic (about 128 GB), which raises the bar but does not remove the risk. The code dates back to 1.9.5 (2015). F5 also fixed a related HTTP/2 bug, CVE-2026-123633, at the same time.

**Mitigation:**
- Upgrade NGINX Open Source to **1.31.9** (mainline) or **1.30.7** (stable). Upgrade NGINX Plus to **R37.3.0.1** or **R37.0.8.1**. Plus R34–R36 have no listed fix, so upgrade the release line.
- Interim: disable HTTP/2 (remove `http2` from listeners). HTTP/1.1-only servers are not affected.
- Distribution packages and container images may still be pending, so watch your distro's advisory.

**Affected:** NGINX OSS ≥ 1.9.5 with HTTP/2 enabled (currently supported lines 1.30.x < 1.30.7, 1.31.x < 1.31.9); NGINX Plus R34–R37 before the fixed builds. **Disclosed:** 2026-11-18 (F5 K000163926, Rapid7). No known exploitation.

## 8. CVE-2026-129448 — Apache Roller Unauthenticated XML-RPC Deserialization

**Principle / root cause:** This is deserialization of untrusted data (CWE-502). Roller's XML-RPC endpoint accepts "vendor extension" value types and deserializes them into Java objects *before* authenticating the caller. An unauthenticated attacker can therefore cause arbitrary object deserialization and RCE. It is the same issue as CVE-2026-82384, with the affected range widened back to 4.0.0.

**Mitigation:**
- Upgrade to **6.1.7** if possible, or at least **6.1.6**. Version 6.1.7 also fixes the related client-side ping-response deserialization issue, CVE-2026-123374.
- Interim: set `enabledForExtensions` to `false` in `WEB-INF/web.xml`, or remove the `/roller-services/xmlrpc` servlet mapping, then restart. Disabling XML-RPC in the admin UI alone is not sufficient.

**Affected:** Apache Roller 4.0.0 through 6.1.5. **Disclosed:** 2026-11-17, with active exploitation confirmed by Apache.

## 9. CVE-2026-114938 — "Java4Shell": OpenJDK HotSpot AVX-512 Base64 Decoder Memory Corruption

**Principle / root cause:** HotSpot has a JIT-compiled fast path (an "intrinsic") for `java.util.Base64` decoding that uses AVX-512 VBMI instructions on x86-64 CPUs. For certain malformed padded input, this optimized decoder writes past the end of its output buffer, which causes heap memory corruption. Any application that Base64-decodes attacker-controlled input can be exposed, and this is very common in authentication headers, tokens and APIs. The impact ranges from JVM crash or memory disclosure to possible pre-auth RCE. It is reachable only once the decoder has been JIT-compiled ("hot"), and only on CPUs with AVX-512 VBMI. ARM and older x86 CPUs are reportedly not affected.

**Mitigation:**
- Apply the November 17, 2026 Java updates: Oracle Java SE **17.0.21.1** / **21.0.13.1**, the corresponding 25.x/27.x builds, Amazon Corretto **17.0.21.1.2**, Azul Zulu November builds, and your vendor's equivalents. Also update products that bundle a JDK (Elastic, Jira, Jenkins, Keycloak, and others) as their vendors ship fixes.
- Interim, unofficial: start the JVM with `-XX:-UseBASE64Intrinsics` to disable the vulnerable intrinsic. Neither Oracle nor OpenJDK has endorsed this workaround.
- CISA additionally recommends limiting the size of Base64 input, validating it, and limiting unauthenticated access to Java services.

**Affected:** Java 17 (reported from 17.0.6), 21, 25 and 27 on x86-64 with AVX-512 VBMI, across distributions. Java 8 and 11 are reportedly not affected, except possibly Oracle's Java 8 Enterprise Performance Pack and GraalVM per Oracle. **Disclosed / patched:** 2026-11-17 (Oracle November Critical Security Patch Update). Public PoC reported; no confirmed in-the-wild exploitation as of 2026-11-18.

## 10. CVE-2026-115731 — Puppet Enterprise Server-Side Code Execution

**Principle / root cause:** An authenticated Puppet agent can cause the Puppet server to execute arbitrary code, which breaks the trust boundary between managed nodes and the configuration-management server. If certificate **autosigning** is enabled, an attacker can get a certificate without approval, so exploitation may effectively be unauthenticated.

**Mitigation:**
- Upgrade to Puppet Enterprise **2026.0.1**, **2025.12.1**, or **2023.8.13**.
- Disable or tightly restrict autosigning, and review recently signed certificates.

**Affected:** Puppet Enterprise before the versions listed above. **Fix released:** 2026-11-03. **KEV:** 2026-11-17.

## Other notable items this week (context)

### 11. PHP — seven critical fixes, including CVE-2026-129474
PHP released security updates fixing 18 vulnerabilities, seven of them rated critical for RCE potential. CVE-2026-129474 is a use-after-free that an unauthenticated attacker may be able to trigger, causing a fatal error and possibly code execution. **Mitigation:** update to the latest PHP point release for your supported branch, along with your distribution's packages. **Disclosed:** this week (around 2026-11-18/19).

### 12. CVE-2026-114713 — UnrealIRCd server-to-server command injection
On networks with two or more linked servers, any user can inject server-to-server protocol commands that are executed with server authority, because of insufficient separation between user and server message contexts. **Mitigation:** upgrade to **6.2.7.1** (released 2026-11-07). **KEV:** 2026-11-13.

### 13. CVE-2026-123039 — Check Point Quantum / Gaia OS local privilege escalation
The Gaia OS DynamicCLI daemon runs as root and listens on a world-writable local socket, so a local low-privilege user can send it requests and gain root. Affects Security Gateway, Security Management Server, Multi-Domain Management and Scalable Platforms. Check Point observed exploitation against about two dozen customers. **Mitigation:** apply the Check Point hotfix for your Gaia version. **KEV:** 2026-11-13.

### 14. CVE-2026-125350 — Google Chrome XML/XSLT use-after-free (exploited zero-day)
This is a use-after-free in Chrome's XSLT handling (bundled libxslt pattern cache). A crafted page can execute code inside the renderer sandbox. **Mitigation:** Chrome **157.0.8103.50/.51** or later (Extended Stable **156.0.8078.96**), and update Chromium-based browsers when their vendors ship fixes. **Patched:** 2026-11-09. **KEV deadline:** 2026-11-24.

### 15. CVE-2026-20320 — Cisco BroadWorks XXE in OCI-P
This is an XML external entity flaw in the OCI-P XML parser that lets an unauthenticated attacker read sensitive files. It was reported exploited in a campaign against a European telecom provider and its customers. **Mitigation:** upgrade to **RI.2026.07**; Cisco lists no workaround. **KEV:** 2026-11-10 (deadline 2026-11-24).

Also this week, for reference: CISA's 2026-11-09 KEV batch (OpenSSH CVE-2026-123158, GPUStack CVE-2026-102895, FreeSWITCH CVE-2026-116779, IBM Aspera Faspex CVE-2026-123218) and Microsoft's November Patch Tuesday (2026-11-10), which includes the exploited Outlook flaw CVE-2026-124194.
