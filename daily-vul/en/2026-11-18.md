## 1. CVE-2026-114938 — "Java4Shell": OpenJDK HotSpot Base64 Decoder Heap Overflow

**Principle / root cause:** A heap buffer overflow in the HotSpot JVM's hardware-accelerated (intrinsic) Base64 decoder. On x86-64 CPUs that support the AVX-512 VBMI instruction set extension, the JIT-generated vectorized decode routine mishandles buffer bounds for certain inputs, so decoding attacker-supplied Base64 data can write beyond the destination buffer. Because Base64 decoding of untrusted input is ubiquitous (HTTP auth headers, JWTs, SAML, API payloads), many Java server applications — reports name Jira, Jenkins and Keycloak among others — can reach the vulnerable code path before authentication, creating a pre-auth remote code execution risk. The upstream fix is small (tracked as JDK-8393212).

**Mitigation:**
- Upgrade the JDK/JRE to a fixed build: upstream OpenJDK **17.0.21.1, 21.0.13.1, 25.0.5.1, 27.0.1.1** (or later), or your vendor's build that explicitly lists CVE-2026-114938 (e.g. Amazon Corretto 17.0.21.1.2 / 21.0.13.1.2 / 25.0.5.1.2 / 27.0.1.1.4; Azul Zulu November 2026 update; Oracle Java SE 8 Enterprise Performance Pack 8u513-perf).
- Rebuild and redeploy container images and applications that bundle their own JRE — updating the host JDK alone does not fix embedded runtimes.
- Track distribution packages: at time of writing Red Hat (RHSB-2026-018) and Debian stable fixes were still pending and Eclipse Temurin builds were rolling out; prioritize internet-facing Java services on AVX-512-capable hardware until vendor builds land.
- CISA (alert 2026-11-17) urges immediate patching.

**Affected:** OpenJDK-based runtimes **17.0.6 and later, 21, 25 and 27** prior to the fixed builds, running on x86-64 Intel/AMD CPUs with AVX-512 VBMI. Reported as not affected: Java 8 (standard), Java 11, 17.0.0–17.0.5, and ARM64. Disclosed and patched 2026-11-17; no confirmed in-the-wild exploitation as of 2026-11-18.

## 2. CVE-2026-129448 — Apache Roller Unauthenticated XML-RPC Deserialization RCE

**Principle / root cause:** Roller's XML-RPC endpoint (`/roller-services/xmlrpc`) was configured to accept vendor "extension" types and deserializes them into Java objects **before** checking whether the requester is authenticated (CWE-502, deserialization of untrusted data). An unauthenticated remote attacker can therefore cause attacker-influenced object graphs to be instantiated on the server, leading to code execution. Disabling XML-RPC in the admin UI is not sufficient on vulnerable versions, because deserialization happens before that setting is consulted.

**Mitigation:**
- Upgrade to **Apache Roller 6.1.6 or later** (6.1.7 is the current release).
- If you cannot upgrade immediately: set `enabledForExtensions` to `false` in `WEB-INF/web.xml`, or remove the XML-RPC servlet mapping, then restart Roller.
- Review servers for signs of compromise (unexpected processes, web shells, outbound connections) given confirmed exploitation.

**Affected:** Apache Roller 4.0.0 through 6.1.4 (the same issue in 6.1.5 was tracked separately as CVE-2026-82384). Apache confirmed active exploitation on 2026-11-18.

## 3. CVE-2026-115731 — Puppet Server Report-Processing Deserialization RCE

**Principle / root cause:** Improper deserialization of untrusted data in Puppet Server's report-processing component. Agents submit run reports that may include "rich data" types; the server reconstructs these types without sufficiently restricting which ones are allowed. A client holding any CA-signed agent certificate can submit a report that causes code to execute on the Puppet Server as the Puppet service account — effectively a full compromise of the configuration-management control plane and, by extension, the managed fleet. Environments with permissive certificate autosigning are at elevated risk, since obtaining a signed certificate becomes trivial.

**Mitigation:**
- Upgrade to **Puppet Enterprise 2023.8.13 (LTS), 2025.12.1, or 2026.0.1**; open-source **Puppet Core 8.22.2 / 9.1.3**; OpenVox Server **8.18.0 / 9.2.0** or later. Restart Puppet Server after upgrading so the fix loads.
- Audit and tighten certificate autosigning; review the list of signed agent certificates and revoke unexpected ones.
- Hunt for anomalous activity by the Puppet service account. CISA federal deadline: 2026-12-01.

**Affected:** Puppet Enterprise 2023.8.0–2023.8.12, 2025.0.0–2025.12.0, 2026.0.0; Puppet Core 8.22.1 and earlier, 9.1.2 and earlier. Patched by Perforce 2026-11-03; added to CISA KEV 2026-11-17 after confirmed exploitation.

## 4. CVE-2026-123039 — Check Point DynamicCLI Local Privilege Escalation

**Principle / root cause:** An incorrect permission assignment for a critical resource (CWE-732) in the DynamicCLI daemon on Check Point Security Gateways and Security Management servers. A low-privileged local process can interact with a privileged resource it should not have access to and escalate to root. In observed attacks it is the second stage of a chain: initial access is obtained via the "PHP2Shell" Mobile Access portal flaws (CVE-2026-109618 / CVE-2026-109619), then this bug is used to gain root on the appliance.

**Mitigation:**
- Apply Check Point's hotfix / Jumbo Hotfix Accumulator that addresses CVE-2026-123039, and ensure the PHP2Shell fixes are also installed.
- If Mobile Access is not needed, disable it; otherwise restrict portal exposure.
- Treat appliances that were exposed and unpatched since late October as potentially compromised and investigate.

**Affected:** Check Point Security Gateway and Security Management products (see vendor advisory for exact versions). Exploitation observed from 2026-10-30; added to CISA KEV 2026-11-13.

## 5. CVE-2026-114713 — UnrealIRCd labeled-response Command Injection

**Principle / root cause:** Improper neutralization of delimiters (CWE-140) in the labeled-response module. Message data relayed between linked servers is not correctly delimited, so content originating from an ordinary, unprivileged user can be interpreted by a peer server as server-level protocol commands. On networks with at least two linked servers, this lets a normal user act with server authority.

**Mitigation:**
- Upgrade to **UnrealIRCd 6.2.7.1 or later**.
- If you cannot upgrade immediately, consider disabling the labeled-response module and review whether your servers are linked to others.

**Affected:** UnrealIRCd 6.0.0 up to (not including) 6.2.7.1. Added to CISA KEV 2026-11-13.

## 6. VSA-2026-062 — Vates Xen Orchestra Authentication Bypass

**Principle / root cause:** A flaw in session-cookie handling: the authentication cookie value is parsed into an object, and a malformed value can produce an empty object that is then passed to the token provider, which fails open and returns a privileged (admin) token. The result is unauthenticated administrator access to Xen Orchestra, from which an attacker can control managed pools and reach root on XCP-ng hosts. A separate advisory, VSA-2026-063 (privilege issue in the VM import path), has reportedly been combined with it in attacks.

**Mitigation:**
- Upgrade to **Xen Orchestra 6.9.2 (stable) or 6.10.1 (latest)** or later, including Xen Orchestra Appliance (XOA) deployments.
- Keep Xen Orchestra off the public internet, on a dedicated management network; block the IOCs (IPs/domains) published by Vates.
- Review audit logs and hypervisor hosts for unauthorized admin activity.

**Affected:** Xen Orchestra before 6.9.2 (stable channel) and before 6.10.1 (latest channel). Disclosed 2026-11-10/11 as actively exploited; no CVE assigned at time of writing.

## 7. CVE-2026-125350 — Google Chrome XML Use-After-Free (Zero-Day)

**Principle / root cause:** A use-after-free in Chrome's XML processing component: memory belonging to an XML-related object is freed while still referenced, and later accessed. A crafted web page can leverage this for memory corruption and potentially code execution inside the renderer. Google confirmed an exploit exists in the wild (the eighth exploited Chrome zero-day of 2026).

**Mitigation:**
- Update to **Chrome 157.0.8103.50/.51** (Windows/macOS), **157.0.8103.50** (Linux/Android), or Extended Stable **156.0.8078.96**; relaunch the browser.
- Update other Chromium-based browsers (Edge, Brave, Opera, Vivaldi) as their vendors ship the fix. CISA federal deadline: 2026-11-24.

**Affected:** Chrome desktop and Android prior to the versions above. Patched 2026-11-09.

## 8. CVE-2026-124194 — Microsoft Outlook Spoofing / NTLM Hash Disclosure (Zero-Day)

**Principle / root cause:** A spoofing vulnerability in Outlook: when a victim opens a specially crafted message file, Outlook can be induced to initiate an authentication attempt to an attacker-controlled resource, leaking the user's NTLM(v2) authentication hash. Leaked hashes can be cracked offline or relayed to other services.

**Mitigation:**
- Install the November 2026 Office/Outlook security updates (Patch Tuesday, 2026-11-10).
- Block outbound SMB (TCP 445) to the internet; consider adding high-value users to the Protected Users group and enforcing SMB/LDAP signing and EPA to reduce relay value.

**Affected:** Microsoft 365 Apps for Enterprise, Office LTSC 2021 and 2024 (see Microsoft Security Update Guide for builds). Exploited in the wild; part of a record Patch Tuesday (1,200+ CVEs).

## 9. CVE-2026-116606 & CVE-2026-111560 — Barracuda ESG Pre-Auth Bypass + Command Injection

**Principle / root cause:** CVE-2026-116606 is an authentication bypass via an alternate path (CWE-288) in Barracuda Email Security Gateway: a configuration-backup import function can be reached without logging in. CVE-2026-111560 is an OS command-injection flaw shared across several Barracuda products. Chained, an unauthenticated attacker can achieve root on the appliance.

**Mitigation:**
- ESG: upgrade to **9.4.0.030 or later** (fixes both CVEs).
- ADC, Backup/Message Archiver (BMA), WCC, WAF and Web Security Gateway: apply the patches listed in Barracuda's advisory.
- Restrict management interfaces to trusted networks and check for signs of compromise.

**Affected:** ESG before 9.4.0.030; for CVE-2026-111560 also ADC ≤ 6.4.0, BMA ≤ 5.5.4.0, WCC ≤ 2.2.1, WAF ≤ 11.0.1, WSG ≤ 16.1.100.100. Added to CISA KEV 2026-11-10.

## 10. CVE-2026-20320 — Cisco BroadWorks OCI XXE; CVE-2026-111793 — Openwave Webtop

**Principle / root cause:** CVE-2026-20320 is an XML external entity (XXE) flaw in the BroadWorks Open Client Interface (OCI) XML parser: external entity resolution is not disabled, so unauthenticated XML input can cause the server to disclose sensitive configuration data. CVE-2026-111793 is a missing enforcement of administrator-defined file-type restrictions in Openwave Messaging Webtop Media Transcoder, letting authenticated users convert unintended file types.

**Mitigation:**
- BroadWorks: upgrade to **RI.2026.07 or later** (no workaround). Restrict OCI exposure to trusted networks.
- Openwave Webtop Media Transcoder: upgrade to **1.1.22.0 or later**.
- CISA federal deadline: 2026-11-24.

**Affected:** Cisco BroadWorks prior to RI.2026.07; Openwave Webtop Media Transcoder prior to 1.1.22.0. Added to CISA KEV 2026-11-10 (exploitation reportedly linked to attacks on telecom operators).

## 11. (Continuity) CVE-2026-111357 & CVE-2026-118527 — Ivanti Connect Secure Chained Zero-Days

**Principle / root cause:** CVE-2026-111357 is missing authentication for a critical function, allowing privilege escalation; CVE-2026-118527 is predictable identifier generation that lets an authenticated user upload files to known locations. Chained with the earlier authentication bypass CVE-2026-104935, attackers (tracked as UTA0576) achieved unauthenticated root code execution, in attacks since at least 2026-10-01.

**Mitigation:** Upgrade to **Ivanti Connect Secure 25.1.1.3 or 22.8R2.6** (no workaround); run Ivanti's integrity checker and investigate exposed appliances.

**Affected:** Connect Secure 25.1.1.2 and earlier, 22.8R2.5 and earlier. Patched 2026-11-02.

## 12. (Continuity) CVE-2026-107441 — Zyxel GS1900 Pre-Auth Out-of-Bounds Write

**Principle / root cause:** An unauthenticated out-of-bounds write in the switch firmware's web CGI program, reachable before login. It sits in the same code as the earlier CVE-2026-7273, which is why switches with the June fix remained exploitable; ~1,000 devices were reportedly compromised.

**Mitigation:** Upgrade every GS1900 model to the matching **V2.90 Patch 3 (".3C0") firmware**, e.g. GS1900-8 → 2.90(AAHH.3)C0. Do not expose switch management to untrusted networks.

**Affected:** Ten Zyxel GS1900-series models on firmware prior to Patch 3. Disclosed 2026-11-03.
