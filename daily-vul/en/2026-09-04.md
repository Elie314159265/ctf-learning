## 1. CVE-2026-85046 — Google Chrome V8 Type Confusion (Actively Exploited Zero-Day)

**Principle / root cause:** A type-confusion bug in V8, Chrome's JavaScript/WebAssembly engine, causes the engine to misinterpret the type of an in-memory object while processing crafted script content. This lets an attacker-controlled web page cause out-of-bounds reads and writes on the heap, which can be leveraged to execute arbitrary code inside the browser's rendering sandbox.

**Mitigation:**
- Update Chrome to 152.0.7977.82/.83 (Windows/macOS) or 152.0.7977.82 (Linux) or later; the update rolls out automatically but should be verified/forced on managed fleets.
- Other Chromium-based browsers (Edge, Brave, Opera, Vivaldi) should be updated as soon as their vendors ship the corresponding V8 fix.

**Affected:** Google Chrome prior to 152.0.7977.82 (all platforms); other Chromium-based browsers bundling the vulnerable V8 build. Reported by external researcher Salvatore Gulizia; Google confirmed an exploit already existed in the wild at time of disclosure. Fix released 2026-09-03; added to CISA KEV on 2026-09-04. This is the 6th actively-exploited Chrome zero-day patched in 2026.

## 2. "GitSpawn" — Git-Config-Triggered Code Execution in CLI AI Coding Agents

**Principle / root cause:** Several command-line AI coding agents (including Claude Code, OpenAI Codex, Cursor, Grok Build, Goose, Hermes Agent, and Qwen Code) run routine background `git` operations (e.g., `git status`, `git diff`) against a repository the moment it is opened. Git supports a repository-local setting, `core.fsmonitor`, that names an external helper program Git invokes to speed up file-status checks; this setting is read from the repository's own `.git/config`, which is attacker-controlled content when a user opens or clones an untrusted repository. Because the agents trigger index-refreshing git commands automatically — sometimes before the user has typed a prompt or granted any approval — a malicious repository can get its configured command executed with the user's own privileges, outside the agent's intended sandbox/approval flow.

**Mitigation:**
- Update affected coding agents to the latest release; fixes have shipped for Goose, Cursor, and (partially) Claude Code.
- Until a fix is confirmed for your specific tool, avoid opening or running an AI coding agent against untrusted/unreviewed repositories, and treat `.git/config` in cloned repos as untrusted input — inspect it (or clone with `git clone --config core.fsmonitor=` disabled defaults reviewed) before letting an agent index the working tree.
- Run coding agents in a container or VM with no broader host credentials when working with third-party repositories.

**Affected:** Claude Code, OpenAI Codex, Cursor, Grok Build, Goose, Hermes Agent, and Qwen Code — versions prior to each vendor's fix. Disclosed by Manifold Security ("GitSpawn") on 2026-09-01; assigned CVE-2026-72718 (Goose) and CVE-2026-71963 (Hermes Agent), plus three additional CVEs for OpenAI Codex. As of the researchers' 2026-09-01 retest, Hermes Agent, Qwen Code, Grok Build, and a second code path in Claude Code remained unpatched. No in-the-wild exploitation has been reported; this is a disclosed vulnerability class, not an active campaign.

## 3. CVE-2026-20274 through CVE-2026-20280 — Cisco IOS XR Software Hardening Release

**Principle / root cause:** Following an internal security review, Cisco's IOS XR engineering team identified and fixed seven separate vulnerabilities (memory-safety and input-handling issues in various IOS XR subsystems) that could be leveraged for denial of service or, in the more severe cases, code execution or privilege escalation on affected routing platforms. These were found through internal testing, not external researcher reports or exploitation.

**Mitigation:**
- Apply the IOS XR software updates identified in Cisco's September 2026 hardening advisory; no workarounds are available.
- Prioritize devices with the CVEs scoring 8.2–8.8 first, then complete the remaining hardening updates.

**Affected:** Cisco IOS XR Software, all releases regardless of device configuration, prior to the fixed versions. Advisory published 2026-09-02. Not known to be exploited in the wild.

## 4. CVE-2026-20354 & CVE-2026-20355 — Cisco Secure Email S/MIME Ciphertext Decryption Flaws (Unpatched)

**Principle / root cause:** The S/MIME decryption functionality in Cisco Secure Email (AsyncOS) does not sufficiently validate the integrity of encrypted message ciphertext before processing it. An attacker positioned to intercept and modify traffic between mail gateways (a man-in-the-middle position) can tamper with S/MIME-encrypted messages in ways that let them recover plaintext content from otherwise-encrypted email, without needing any credentials.

**Mitigation:**
- No fix or workaround is currently available; Cisco has published the advisory as unpatched guidance. Track Cisco's advisory for the forthcoming update.
- Interim mitigation: where feasible, restrict or monitor mail-gateway-to-mail-gateway paths carrying S/MIME traffic, and treat S/MIME as a defense-in-depth layer rather than a sole confidentiality guarantee until patched.

**Affected:** Cisco Secure Email devices running AsyncOS 16.5.0 or earlier with S/MIME enabled. Publicly disclosed 2026-09-02. No reports of active exploitation; risk is elevated by the absence of a patch.

## 5. CVE-2026-60004 — Gitea Unauthenticated-Path Remote Code Execution (Continued Active Exploitation)

**Principle / root cause:** Gitea's `diffpatch` API endpoint applies a user-supplied patch inside a temporary Git repository without adequately restricting what that patch can install. An account with ordinary repository-write access — trivially obtainable on instances with open self-registration — can use this to plant and trigger a malicious Git hook, resulting in shell command execution as the Gitea OS user.

**Mitigation:**
- Upgrade to Gitea 1.27.1 or later immediately.
- Disable open self-registration on internet-facing Gitea instances that don't require it, and audit for unexpected outbound network activity or high CPU usage (observed campaigns have dropped cryptocurrency-miner-style payloads).

**Affected:** Gitea versions from 1.17 up to the fix in 1.27.1. Patched in late August; CISA added it to the KEV catalog on 2026-08-25 with a federal remediation deadline of 2026-08-28. Included here as exploitation (including miner-dropper campaigns) has continued into this reporting window.
