## Most recent (last 24–48 hours)

## 1. CVE-2026-90436 — Apache Axis 1.x Unsafe Reflection (Confluence Data Center, N-able N-central)

**Principle / root cause:** Apache Axis 1.x, a legacy SOAP library, processes SOAP fault messages that can name an exception class. Axis loads the named class and may instantiate it *before* validating that it is a legitimate fault type (CWE-470, use of externally-controlled input to select classes or code). Simply loading a class can run its static initializer, so an attacker who controls the class name can trigger code paths that were never meant to be reachable. Because the fault is parsed while Axis is still resolving which service is being called — before any per-service authentication handlers run — service-level authentication does not protect against it, making it effectively pre-authentication RCE in products that expose Axis endpoints.

**Mitigation:**
- **Confluence Data Center:** upgrade to 9.2.28 or later (or 10.x, where the Remote API was removed entirely). If you cannot upgrade immediately, **disable the Remote API (XML-RPC & SOAP)** feature — instances are only vulnerable when it is enabled.
- **N-able N-central:** follow N-able's advisory for the fixed build; restrict network access to the console until patched.
- **Other software bundling Axis 1.x:** Axis 1.x is end-of-life and Apache does not plan a new 1.x release; apply the upstream patch commit or migrate to Axis2/Java.
- Hunt for Java application processes spawning shells or download tools (e.g. `bash`, `curl`) and unusual HTTP 500 responses on SOAP endpoints.

**Affected:** Apache Axis 1.x through 1.4 and products embedding it, including Atlassian Confluence Data Center versions before 9.2.28 (with Remote API enabled) and affected N-able N-central versions. Disclosed 2026-11-06; Rapid7 observed in-the-wild exploitation against Confluence on 2026-11-13, and further reports of exploitation against Confluence and N-central continued on 2026-11-17. Public exploit code is reported to exist.

## 2. CVE-2026-125160 & CVE-2026-125163 — TYPO3 CMS Form Framework (Upload Path Disclosure + Unrestricted Upload)

**Principle / root cause:**
- **CVE-2026-125160 (information disclosure, CVSS 6.3):** when a form file upload failed, the resulting error message revealed the server-side storage path of the upload folder. That path is normally treated as unguessable, so leaking it lets an attacker determine the public URL of files uploaded through forms.
- **CVE-2026-125163 (unrestricted file upload):** the MIME-type allow list configured on FileUpload/ImageUpload form elements was not actually enforced, so unauthenticated visitors could upload browser-executable file types (e.g. HTML, SVG).
- Combined, an attacker can place active content in public storage and know its URL, enabling stored cross-site scripting on sites that do not apply a restrictive Content-Security-Policy to that folder.

**Mitigation:**
- Update to TYPO3 14.3.12 LTS, 13.4.40 LTS, 12.4.52 ELTS, 11.5.57 ELTS, or 10.4.63 ELTS.
- Apply a restrictive Content-Security-Policy to the form upload target folder (TYPO3's shipped `fileadmin/.htaccess` does this on Apache for default storage — verify it is present on nginx/other setups).
- Explicitly configure allowed MIME types on every form upload field; review form upload folders for unexpected HTML/SVG files.

**Affected:** TYPO3 CMS with the Form Framework (`ext:form`), versions before the fixed releases above. Disclosed 2026-11-17 (advisories TYPO3-CORE-SA-2026-029 and -032, part of a batch of ~10 fixes). TYPO3 reports CVE-2026-125160 as actively exploited (one aggregator disagrees). A separate installer-related flaw in the same batch is reportedly rated CVSS 9.4 — check the TYPO3 advisory list for details.

## 3. N-able N-central "4EverAble2Shell" / "Agent2Shell" Zero-Days (no CVE assigned yet)

**Principle / root cause:** A security researcher publicly released two exploit chains against N-able N-central, the remote monitoring and management (RMM) platform: one yielding root-level access on the N-central appliance, the other SYSTEM-level access on managed Windows agents. Detailed root causes have not been published by the vendor. This follows a series of N-central vulnerabilities disclosed by the same researcher earlier in the year.

**Mitigation:**
- Follow N-able's latest security updates and guidance closely. N-able reportedly took hosted N-central environments offline and urged on-premises customers to shut down servers while fixes are prepared.
- Do not expose the N-central console to the internet; restrict access to VPN/trusted IP ranges.
- Hunt for cryptocurrency miners, new services, and unexpected outbound connections on N-central servers; because RMM compromise reaches every managed endpoint, review agent-issued tasks and scripts.
- Note that this is separate from (but overlaps in timing with) CVE-2026-90436 exploitation of N-central via Apache Axis (item 1).

**Affected:** N-able N-central on-premises appliances and managed Windows agents; reportedly including systems on the latest security update at the time. Exploitation began within hours of the PoC release (reported 2026-11-12); at least 21 compromised servers were observed with cryptominers deployed. No CVE or CISA KEV entry yet.

## 4. CVE-2026-123039 — Check Point Gaia OS Local Privilege Escalation (chained with PHP2Shell)

**Principle / root cause:** A local privilege-escalation flaw in Check Point Gaia OS, reportedly in the `dynamic_server` component, allows a low-privileged process to obtain root. In observed attacks, initial access was gained through the PHP2Shell vulnerabilities (CVE-2026-109618 / CVE-2026-109619 — flaws in the PHP runtime where an interrupted request leaves internal state half-updated and later trusts it, leading to unauthenticated RCE) on the Mobile Access portal, then CVE-2026-123039 was used to escalate to root. Attackers deployed destructive wiper malware, including against a VMware ESXi host.

**Mitigation:**
- Install the November Jumbo Hotfix (reported takes: R82.20 Take 14+, R82.10 Take 52+, R82 Take 132+, R81.20 Take 174+ — confirm in Check Point sk1000362).
- Confirm the PHP2Shell fix (sk1000302) is installed; prioritize internet-facing Mobile Access gateways.
- If you cannot patch immediately: stop the `dynamic_server` process and prevent it from restarting (vendor interim mitigation). R81.10 (end of support) has no jumbo take listed — upgrade or apply the vendor's mitigation.
- For PHP elsewhere in your estate: upgrade to PHP 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 or later.

**Affected:** Check Point Security Gateway, Firewall, Security Management Server, Multi-Domain Security Management Server, and Scalable Platforms running Gaia OS without the November hotfix. Exploited against "a couple of dozen" customers; added to CISA KEV on 2026-11-13 with a federal due date of 2026-11-16 (now passed).

## 5. CVE-2026-114713 — UnrealIRCd Command Injection via Unescaped Message Tag

**Principle / root cause:** The IRCv3 `labeled-response` module echoes a client-supplied `label` message tag back in replies without properly escaping it. Because the IRC protocol is line-delimited, a user who can inject line breaks into that tag can smuggle additional protocol lines — including server-to-server commands on linked networks — effectively a command/protocol injection (CRLF-injection class). The maintainer called it the worst UnrealIRCd issue in 15 years.

**Mitigation:**
- Upgrade to UnrealIRCd 6.2.7.1 (released 2026-11-07, fixes nine issues), or apply the maintainer's hot-patch bundle (bundle-20261107) to **every** server on the network for 6.0.0–6.2.7.
- UnrealIRCd 5 (EOL since 2023) is also affected: disable (blacklist) the `labeled-response` module and restart, then plan an upgrade.

**Affected:** UnrealIRCd 6.0.0 through 6.2.7 (and EOL version 5). Fixed 2026-11-07; actively exploited; added to CISA KEV on 2026-11-13 with a federal due date of 2026-11-16 (now passed).

## 6. CVE-2026-119618 — Apache HTTP Server mod_http2 Race Condition (RCE)

**Principle / root cause:** A race condition in mod_http2's header handling (reported as the `assign_headers()` function) can let concurrent HTTP/2 stream processing corrupt heap memory. Heap corruption reachable by a remote, unauthenticated client can potentially be leveraged for remote code execution in the httpd worker process. Credited to Anthropic's OSS scanner and Google Cloud Vulnerability Research.

**Mitigation:**
- Upgrade to Apache HTTP Server 2.4.71 (released 2026-11-11), which also fixes lower-severity CVE-2026-106023 (mod_md) and CVE-2026-109163 (mod_vhost_alias).
- Distribution packages may lag; on RHEL-family systems the fix may be in AppStream — verify the installed package version rather than relying on CVE-filtered update commands.
- If you cannot patch, disable HTTP/2 (remove `h2`/`h2c` from `Protocols` or unload mod_http2) as a temporary mitigation.
- The standalone `mod_h2` GitHub project is archived and has no official fixed release — move to the in-tree module of 2.4.71.

**Affected:** Apache HTTP Server 2.4.55 through 2.4.70 with HTTP/2 enabled. Patched 2026-11-11. **Exploitation status is conflicting:** some reports this week claim active exploitation and public PoC, while other sources (and the CISA KEV catalog at time of writing) do not confirm it. Treat as high priority regardless given the severity and exposure.

## 8. CVE-2026-125350 — Google Chrome XML Use-After-Free (Zero-Day)

**Principle / root cause:** A use-after-free in Chrome's XML handling: an object is freed while a reference to it remains and is later used, letting crafted web content corrupt memory and execute code inside the renderer sandbox. Google confirmed an exploit exists in the wild — the eighth exploited Chrome zero-day of 2026. A separate XML use-after-free, CVE-2026-125346, was fixed in the same release (not reported exploited).

**Mitigation:** Update Chrome to 157.0.8103.50/.51 or later and relaunch; update Microsoft Edge and other Chromium-based browsers to their corresponding builds.

**Affected:** Google Chrome desktop before 157.0.8103.50; Chromium-based browsers. Patched 2026-11-09; CISA KEV 2026-11-10 (due 2026-11-24).

## 9. CVE-2026-124194 — Microsoft Outlook NTLM Hash Disclosure (Zero-Day)

**Principle / root cause:** Classified as spoofing / missing user interaction for a potentially unsafe action (CWE-356). Opening a specially crafted message file causes Outlook to connect to an attacker-controlled server without the usual external-content warning, leaking the user's NTLMv2 authentication material. That can be cracked offline or relayed to other services (NTLM relay).

**Mitigation:**
- Install the November 2026 Office/Microsoft 365 security updates (released 2026-11-10).
- Block outbound SMB (TCP 445) to the internet; add high-value users to the Protected Users group; enforce SMB/LDAP signing and Extended Protection for Authentication to limit relay.

**Affected:** Microsoft 365 Apps for Enterprise, Office LTSC 2021, Office LTSC 2024 (32/64-bit). Exploited as a zero-day; CISA KEV 2026-11-10, due 2026-11-24. This was the only exploited zero-day in a very large November Patch Tuesday (source counts range from ~1,090 to over 1,200 CVEs, ~63 Critical).

## 10. CVE-2026-20320 — Cisco BroadWorks XXE; CVE-2026-111793 — Openwave Webtop

**Principle / root cause:** CVE-2026-20320 is an XML External Entity (XXE) flaw in BroadWorks' Open Client Interface XML parser: the parser resolves external entities in attacker-supplied XML, letting an unauthenticated remote attacker read sensitive files from the server. CVE-2026-111793 in Openwave Webtop was added to KEV the same day (details limited).

**Mitigation:** Upgrade affected BroadWorks products to RI.2026.07 or later (Cisco lists no workaround); restrict OCI exposure to trusted networks. Apply the Openwave vendor fix.

**Affected:** Cisco BroadWorks (four listed products) before RI.2026.07; Openwave Webtop. Both added to CISA KEV 2026-11-10, due 2026-11-24. Exploitation of BroadWorks has been attributed (unconfirmed) to a telecom-targeting actor.

## 11. CVE-2026-123158 ("SSHole") — OpenSSH Password Authentication Bypass

**Principle / root cause:** When portable OpenSSH's sshd is built **without PAM** on **musl libc** systems (e.g. Alpine Linux), sshd verifies passwords itself, and a flaw in that path lets an oversized password input bypass the check, enabling login to accounts that should be password-disabled.

**Mitigation:** Upgrade to OpenSSH 10.6p2 or later (on Alpine: update packages and restart sshd); disable password authentication in favor of keys where possible.

**Affected:** Portable OpenSSH before 10.6p2 on Linux with musl libc and non-PAM password authentication. Fixed 2026-11-05; exploited from 2026-11-07; CISA KEV 2026-11-09 (due 2026-11-12).
