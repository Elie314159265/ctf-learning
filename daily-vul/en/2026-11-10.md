## 1. CVE-2026-125350 — Google Chrome XML Use-After-Free (Zero-Day)

**Principle / root cause:** A use-after-free (CWE-416) in Chrome's XML-handling component. When an object involved in parsing or rendering XML content is freed but a dangling reference to it is used afterward, an attacker who can influence the freed memory's reuse may be able to corrupt program state and ultimately execute arbitrary code inside the renderer sandbox.

**Mitigation:**
- Update Chrome to the latest stable version immediately (Google ships this through the normal auto-update channel; verify via `chrome://settings/help`).
- Restart the browser after updating — the fix only takes effect once the new binary is loaded.
- Users of Chromium-based browsers (Edge, Brave, Opera, Vivaldi, etc.) should watch for equivalent downstream patches.

**Affected:** Google Chrome prior to the fixed build released 2026-11-09. This is the eighth actively-exploited Chrome zero-day disclosed in 2026. Google has, as is standard practice, withheld technical exploitation details until a majority of users have updated.

## 2. CVE-2026-124194 — Microsoft Outlook Spoofing (Exploited, November Patch Tuesday)

**Principle / root cause:** A spoofing flaw (CVSS 6.5) that lets a crafted message file cause Outlook to connect to an attacker-controlled location without surfacing the usual external-content/security warning. Multiple reports indicate this behavior can be abused to coerce the client into leaking NTLM authentication material to an attacker-controlled endpoint, which could then be relayed or cracked.

**Mitigation:**
- Apply November 2026 cumulative/security updates for Outlook and Office.
- As defense in depth, block outbound SMB/NTLM authentication to untrusted external hosts at the network perimeter, and consider disabling NTLM in favor of Kerberos where feasible.

**Affected:** Supported Microsoft Outlook / Office builds prior to the November 2026 update. Confirmed as "Exploitation Detected" by Microsoft; it is the only entry in this month's release flagged as actively exploited.

**Context — November 2026 Patch Tuesday:** This was a record-breaking release, with totals reported between roughly 1,093 and 1,094 CVEs (sources vary slightly depending on whether Edge/Azure Linux advisories are counted separately), including 63–64 rated Critical. Other notable critical RCEs patched this cycle include flaws in Active Directory Domain Services, Exchange Server, Windows NAT, Outlook, and Microsoft Defender — organizations should prioritize patching internet-facing Exchange and AD-adjacent systems first. Exact CVE-to-product mapping for the full critical list should be confirmed against Microsoft's own Security Update Guide, since third-party counts disagree slightly.

## 3–6. CISA KEV Additions — 2026-11-09 (GPUStack, FreeSWITCH, OpenSSH, IBM Aspera Faspex)

CISA added four vulnerabilities to its Known Exploited Vulnerabilities (KEV) catalog on 2026-11-09, each confirmed as under active exploitation, with a federal remediation deadline of **2026-11-12** under BOD 26-04.

**CVE-2026-102895 — GPUStack improper authentication.** GPUStack (an open-source GPU cluster manager for serving LLMs) fails to properly validate a caller's authentication state on sensitive endpoints, allowing an attacker to reach privileged functionality without valid credentials. *Mitigation:* upgrade to GPUStack 2.2.0 or later.

**CVE-2026-116779 — SignalWire FreeSWITCH code injection (CVSS 9.8).** User-supplied input reaching FreeSWITCH's call-control/scripting logic is insufficiently sanitized before being evaluated, allowing an unauthenticated or low-privileged caller to inject and execute arbitrary code on the telephony server. *Mitigation:* upgrade to FreeSWITCH 1.11.3 or later; restrict management/SIP interfaces to trusted networks.

**CVE-2026-123158 — OpenSSH privilege/handling flaw on musl-based Linux without PAM.** Affects OpenSSH builds prior to 10.6p2 running on musl libc systems that do not use PAM (e.g., Alpine Linux prior to 3.24.4) — a configuration common in minimal container base images. *Mitigation:* upgrade OpenSSH to 10.6p2+ and update affected Alpine images to 3.24.4 or later; container maintainers should rebuild and redeploy images rather than patching in place.

**CVE-2026-123218 — IBM Aspera Faspex incorrect authorization (CVSS 9.8).** Classed as CWE-863 (Incorrect Authorization): an authenticated user can submit a crafted request/message that bypasses an authorization check and is granted full administrator privileges, affecting versions 5.0.0 through 5.0.19. *Mitigation:* upgrade to Faspex 5.0.19 PL1 (Linux hosts should also confirm the `faspex-core` container image is rebuilt from the patched base). **Caveat:** CISA's alert and most press coverage (The Hacker News, SecurityOnline, eSecurityPlanet) describe this as actively exploited and KEV-listed on 2026-11-09, while at least one vulnerability-tracking aggregator (OpenCVE) still shows it as not in KEV with a low EPSS score as of this writing — treat the exploitation status as credible but not universally confirmed, and patch regardless given the severity.

## 7. Fortinet FortiOS / FortiManager / FortiAnalyzer — Advisories Due Today (Watch Item)

**Principle / root cause:** Fortinet silently shipped fixes for a batch of critical- and high-severity vulnerabilities in FortiOS (branches 7.2–8.0), FortiManager, and FortiAnalyzer on 2026-10-22, attributing discovery to its internal AI-assisted security testing program, but deliberately withheld CVE identifiers, vulnerability classes, and CVSS scores until the next scheduled Patch Tuesday — 2026-11-10 — to reduce the window where a patch diff could be reverse-engineered into an exploit before most devices update. Security researchers have warned this delay itself creates risk: sophisticated attackers can patch-diff the October binaries against prior releases to infer the bugs well before public advisories exist.

**Mitigation:**
- Apply the 2026-10-22 hardening-release builds now if not already done, even without full advisory text.
- Restrict administrative interfaces (FortiOS, FortiManager, FortiAnalyzer) to trusted management networks only; never expose admin GUIs to the internet.
- Enforce MFA for all administrative accounts and use unique, strong credentials.
- Once Fortinet's formal advisories and CVE IDs are published, re-check applied builds against the fixed-version list.

**Affected:** FortiOS 7.2/7.4/7.6/8.0 branches, FortiManager, FortiAnalyzer (same branches) prior to the October 22 hardening builds. **Caveat:** at the time of writing, no CVE numbers, CVSS scores, or detailed advisory text had appeared in public tracking sources — this entry is included because of today's scheduled disclosure and the unusual pre-disclosure patching pattern, not because full technical details are yet confirmable. Re-verify against FortiGuard PSIRT once published.

## 8. CVE-2026-119977 — WordPress Core TOCTOU Race Condition (Continuity)

**Principle / root cause:** A time-of-check-to-time-of-use (TOCTOU) race condition in WordPress Core's self-update mechanism. Because the check that validates an update package and the step that actually applies it are not atomic, an attacker able to race the update process can get unauthorized code executed on the server during a legitimate core upgrade — with no authentication or user interaction required.

**Mitigation:** Update to WordPress 7.1.4 or later. Hosts that queue core updates automatically should confirm the update completed cleanly on the patched version rather than assuming success.

**Affected:** WordPress Core 4.7 through 7.1.3 (a huge share of the installed base). Added to CISA KEV on 2026-11-03 with an FCEB deadline of 2026-11-06 (already passed for federal agencies); Wordfence reported blocking over 13,000 exploitation attempts in a single 24-hour window shortly after disclosure. This is the fourth WordPress Core KEV entry since July 2026.

## 9. Ivanti Connect Secure Chain — CVE-2026-111357 & CVE-2026-118527 (Continuity)

Covered in detail in earlier reporting cycles: these two flaws (privilege escalation and authenticated arbitrary file upload, respectively) were chained together with an authentication-bypass bug (CVE-2026-104935, patched in October) to achieve pre-authentication compromise of Connect Secure appliances. Both were added to CISA KEV on 2026-10-30. Included again here because the FCEB remediation deadline for CVE-2026-118527 falls on **2026-11-13**, just after this report's window — organizations that have not yet applied Ivanti's fixed builds (25.1.1.3 / 22.8R2.6 per vendor guidance) should treat this as urgent and not wait for the deadline.

**Mitigation:** Apply the fixed Connect Secure builds; audit for indicators of compromise predating the patch, since the bypass component (CVE-2026-104935) was exploited as a zero-day before any of the three CVEs were public.

## 10. Palo Alto Networks PAN-OS "PHP2Shell" Chain + Linux Kernel "Fragnesia" (Continuity)

**Principle / root cause:** CVE-2026-109618 and CVE-2026-109619 are a pair of unauthenticated, pre-authentication remote-code-execution flaws (CVSS 4.0: 9.2) in PAN-OS's management-interface web stack, collectively nicknamed "PHP2Shell" because they allow an attacker to turn a crafted request into server-side script execution without credentials. Once a foothold is established, attackers have been observed chaining it with CVE-2026-46300 ("Fragnesia"), a Linux kernel privilege-escalation bug, to escalate from the PAN-OS management process to root on the underlying appliance.

**Mitigation:** Apply Palo Alto's fixed PAN-OS builds; never expose firewall/Panorama management interfaces to the internet; restrict management access to dedicated out-of-band networks; apply the corresponding kernel fix where applicable.

**Affected:** PAN-OS and Panorama management interfaces; confirmed under active exploitation since late October 2026, with Singapore's CSA reissuing a public alert on 2026-11-03 covering this and the broader "PHP2Shell" vulnerability class affecting multiple vendors' network/security appliances (reported to also affect some Cisco, Citrix, F5, and Siemens products — confirm per-vendor advisories).
