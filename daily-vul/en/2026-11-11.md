## 1. Fortinet FortiOS, FortiManager, FortiAnalyzer, FortiSASE — November Security Hardening Batch

**Principle / root cause:** Fortinet shipped patches in late October but withheld CVE identifiers and technical detail until a coordinated disclosure on 2026-11-10, covering 89 advisories (19+ rated critical/high). The highest-impact issues include: an unauthenticated JSON injection in the FortiManager/FortiAnalyzer JSON-RPC API that lets a remote attacker manipulate backend objects (CVE-2026-126170, CWE-type injection); a flaw in the FGFM (FortiGate-to-FortiManager) protocol handling that can be abused by a device claiming to be a managed FortiGate (CVE-2026-126261); an unauthenticated SQL injection reachable via the OFTP (log-forwarding) service on FortiAnalyzer/FortiManager (CVE-2026-126262); a numeric-truncation bug in FortiOS's BGP implementation triggerable by a configured iBGP peer (CVE-2026-126254); and an authentication-bypass weakness in FortiOS's OSPF routing daemon (CVE-2026-126253). Each stems from insufficient input validation or trust-boundary checks in network-facing management or routing services.

**Mitigation:**
- Upgrade to FortiOS 8.0.2 / 7.6.8 / 7.4.13 / 7.2.14 or later, and FortiManager/FortiAnalyzer 8.0.2 / 7.6.8 / 7.4.12 / 7.2.13 or later (patches have been available since 2026-10-22; only the advisories were delayed).
- Restrict management-plane access (JSON-RPC, FGFM, OFTP) to trusted networks, and limit BGP/OSPF peering to authenticated, expected neighbors as defense in depth.

**Affected:** FortiOS, FortiManager, FortiAnalyzer, and FortiSASE releases prior to the fixed versions above. Disclosed 2026-11-10; Fortinet reports no known in-the-wild exploitation at time of disclosure, but given the scale and severity of the batch, treat internet-facing management interfaces as priority-1 for patching.

## 2. CVE-2026-102895 — GPUStack Unauthenticated Admin Takeover

**Principle / root cause:** GPUStack's authentication layer treats requests that appear to originate from `localhost` as implicitly trusted and auto-grants administrator privileges, relying on a client-supplied/spoofable indication of origin rather than a verified network-layer check (improper origin validation combined with IP-spoofing-style trust, CWE-346/CWE-290). A remote, unauthenticated attacker able to make the request appear to come from the loopback interface can obtain a persistent administrator API key, execute arbitrary code on GPU worker nodes, and access connected cloud-provider and worker secrets. A related flaw, CVE-2026-102894, involves SAML-based authentication handling in the same product.

**Mitigation:**
- Upgrade to GPUStack 2.2.2 or later (2.2.0 fixes CVE-2026-102895; 2.2.2 additionally fixes CVE-2026-102894).
- Until patched, isolate the GPUStack management plane from any network path where the `Host`/origin indication could be forged, and rotate any API keys and cloud-provider credentials that may have been exposed.

**Affected:** GPUStack versions prior to 2.2.0 (confirmed exploitation reported against 2.1.1 in production AI-infrastructure deployments). Published 2026-11-04; added to CISA KEV on 2026-11-09.

## 3. CVE-2026-116779 — SignalWire FreeSWITCH SIP MESSAGE Command Injection

**Principle / root cause:** FreeSWITCH's SIP MESSAGE handler inspects a portion of the message recipient field to decide which internal "chat protocol" handler should process the request. When that field names the internal API protocol, attacker-controlled content from the SIP message is passed through to FreeSWITCH's own command API and executed with the privileges of the FreeSWITCH process — a classic case of untrusted input being forwarded into a privileged command-execution interface (CWE-77/CWE-78 class). Any deployment with WebRTC or ICE call handling enabled exposes this path by default.

**Mitigation:**
- Upgrade to FreeSWITCH 1.11.3 or later.
- Restrict SIP signaling exposure to trusted networks/peers where upgrading is not immediately possible, and review SIP MESSAGE handling configuration for unnecessary chat-protocol routing.

**Affected:** FreeSWITCH 1.11.2 and earlier. SignalWire's advisory and multiple secondary reports describe in-the-wild exploitation; added to CISA KEV on 2026-11-09.

## 4. CVE-2026-123158 ("SSHole") — OpenSSH Password Authentication Bypass on musl/no-PAM Builds

**Principle / root cause:** On OpenSSH builds compiled against musl libc without PAM support (the default configuration on Alpine Linux and similar lightweight distributions), the server can misinterpret certain input strings as pre-computed password hashes rather than as a password to be verified. This logic error allows an attacker to bypass password authentication for accounts that were configured with authentication restrictions, effectively letting crafted input satisfy a check it was never meant to pass (CWE-287, improper authentication).

**Mitigation:**
- Upgrade to OpenSSH (portable) 10.6p2 or later, or your distribution's patched package (Alpine has shipped fixes for its supported branches).
- Audit internet-facing musl-based containers/VMs (common in minimal container images) for SSH exposure and confirm PAM is enabled where feasible as additional defense in depth.

**Affected:** OpenSSH prior to 10.6p2 when built against musl libc without PAM — Debian/Ubuntu's glibc+PAM builds are not affected by this specific path. Fixed 2026-11-05; added to CISA KEV on 2026-11-09. Public proof-of-concept references are reported to exist.

## 5. CVE-2026-123218 — IBM Aspera Faspex 5 Authorization Bypass to Full Admin

**Principle / root cause:** An already-authenticated (but low-privileged) Faspex 5 user can craft a specially formed message/request that the server processes without correctly re-checking the requester's authorization level, allowing that user to escalate to full administrative rights (CWE-863, incorrect authorization). No additional memory-corruption or injection step is required — the flaw is purely in the authorization-check logic.

**Mitigation:**
- Upgrade to Faspex 5.0.19 PL1 (Linux) or later; IBM has not published a workaround, so patching is the only remediation.
- Audit Faspex admin-account activity logs for unexpected privilege changes performed by previously low-privileged accounts.

**Affected:** IBM Aspera Faspex 5.0.0 through 5.0.19. Published 2026-11-07; added to CISA KEV on 2026-11-09.

## 6. CVE-2026-119977 — WordPress Core Upgrade-Window Race Condition to RCE

**Principle / root cause:** WordPress Core's self-update routine has a time-of-check-to-time-of-use (TOCTOU) race condition (CWE-367): during the narrow window while Core downloads, verifies, and extracts an update package, an attacker who can win a timing race against that process can get malicious content treated as trusted, verified update content — ultimately leading to remote code execution on the site. Ironically, the act of patching (running the vulnerable update routine itself) is what exposes a site to the race.

**Mitigation:**
- Update to WordPress Core 7.1.4 or later as soon as possible (recognizing the update process itself is the exposed window — apply during low-traffic periods and verify the resulting version afterward).
- Monitor for unexpected file changes or new admin accounts immediately following any Core update performed on an older, still-vulnerable version.

**Affected:** WordPress Core 4.7.0 through 7.1.3 (effectively all actively used WordPress sites prior to 7.1.4). CISA added this to the KEV catalog on 2026-11-03 citing evidence of active exploitation, with a federal remediation deadline of 2026-11-06 (already passed). Note: Wordfence rates this CVSS 8.1 (High) while the WordPress project's own advisory rates it Low — treat it as high-priority given confirmed in-the-wild exploitation regardless of the scoring disagreement.

## 7. CVE-2026-116606 & CVE-2026-111560 — Barracuda Products Chainable to Root

**Principle / root cause:** CVE-2026-116606 is an authorization-bypass flaw in Barracuda's administrative interface (reported CVSS 9.3) affecting the Email Security Gateway (ESG); sources differ on whether it requires any prior authentication, but agree the admin interface must be network-reachable. CVE-2026-111560 is an OS command-injection flaw (CVSS 8.6) in a timezone-configuration field, requiring administrative access, affecting ESG as well as the WAF, Load Balancer ADC, Message Archiver, Web Security Gateway, and WAF Control Center. Chained together on affected products, the two can escalate from reaching the admin interface to full root-level command execution on the appliance.

**Mitigation:**
- Apply Barracuda's vendor patches (ESG: BNSF-40425 for firmware 9.4.017+, BNSF-40430 for earlier; other products have their own patch IDs — consult Barracuda's advisory for your model).
- Restrict administrative interfaces on all affected Barracuda products to trusted internal management networks only.

**Affected:** Barracuda ESG, WAF, Load Balancer ADC, Message Archiver, Web Security Gateway, and WAF Control Center running pre-patch firmware. Disclosed 2026-11-02 (just outside this week's 7-day window, included for continuity since patching remains in progress and no confirmed in-the-wild exploitation had been reported as of the most recent check).

## 8. CVE-2026-111793 — Openwave Messaging Webtop Media Transcoder File-Type Restriction Bypass

**Principle / root cause:** The Webtop Media Transcoder component, used by webmail providers to convert email attachments for in-browser preview, fails to enforce administrator-configured file-type restrictions (CWE-669, incorrect resource transfer between spheres). An authenticated webmail user can request conversion of a document type the administrator intended to block, allowing disallowed file types to reach the conversion pipeline.

**Mitigation:**
- Upgrade to Webtop Media Transcoder 1.1.22.0 or later, or migrate to a supported Media Server 2.0 release — Openwave has not described additional workarounds.
- Where upgrading is delayed, review webmail attachment-handling logs for unexpected file-type conversions.

**Affected:** Openwave Messaging Webtop Media Transcoder prior to 1.1.22.0, used in webmail/service-provider messaging platforms. Openwave itself rates this CVSS 4.3 (Medium) and it is not listed in the CISA KEV catalog as of this writing; however, JPCERT/CC reported observing active exploitation attempts on 2026-11-09, so treat it as higher-urgency than the base score suggests pending further confirmation.
