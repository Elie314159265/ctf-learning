## 1. CVE-2026-65660 — Microsoft SharePoint Server Code Injection (Relabeled to RCE)

**Principle / root cause:** SharePoint fails to properly control the generation of code from certain input, allowing an authenticated attacker to submit crafted input that SharePoint compiles and executes as server-side code (CWE: improper control of code generation / code injection). Microsoft's original advisory categorized the issue as a "spoofing" bug, but researchers subsequently confirmed the real impact is authenticated remote code execution, and attackers have been observed chaining it with a separate, unauthenticated delivery flaw to drop encrypted loader payloads.

**Mitigation:**
- Apply Microsoft's SharePoint Server security update (shipped in the August 2026 cumulative update) if not already installed.
- Treat any internet-facing on-premises SharePoint farm as high priority; restrict anonymous/low-privilege account creation and monitor for anomalous w3wp.exe child processes.

**Affected:** On-premises Microsoft SharePoint Server 2016, 2019, and Subscription Edition (SharePoint Online / Microsoft 365 is not affected). Patch available since August 2026; added to CISA KEV on 2026-09-25 following confirmed active exploitation.

## 2. CVE-2026-67279 & CVE-2026-86060 — MikroTik RouterOS "MikroTrick" Unauthenticated Admin Takeover

**Principle / root cause:** RouterOS's SSH server can be driven into the post-authentication connection protocol after a client-initiated rekey, even though the client never actually completed user authentication. This lets an unauthenticated client open a session channel and issue an exec request that the server processes as if it came from a logged-in user, enabling creation, overwrite, and reconstruction of files inside RouterOS's managed file namespace (including configuration and diagnostic data). Chained with a separate argument-injection flaw in the RouterOS login process (CVE-2026-86060), the combination — dubbed "MikroTrick" — yields full administrative console access with no password, SSH key, or completed authentication at all.

**Mitigation:**
- Upgrade to RouterOS 6.49.21 (Long-term), 7.23.4 (Long-term), or 7.24.2 (Stable) or later.
- Restrict SSH/management-plane exposure of RouterOS devices to trusted networks; audit for unexpected configuration changes or new admin accounts.

**Affected:** MikroTik RouterOS up to 6.49.20 / 7.23.3 / 7.24.1. Vendor patches published 2026-09-03; earliest known attack traffic observed by CERT.pl predates the patch (from around 2026-09-02); added to CISA KEV on 2026-09-25.

## 3. CVE-2026-94127 — F5 BIG-IP APM Heap-Based Buffer Overflow (Unauthenticated RCE)

**Principle / root cause:** When a BIG-IP virtual server has both an Access Policy Manager (APM) access policy and an OAuth profile attached, with APM acting as the OAuth Authorization Server, specially crafted traffic reaching that virtual server triggers unsafe memory handling (a heap-based buffer overflow, CWE-122) in the request-processing path — allowing an unauthenticated network attacker to corrupt memory and achieve remote code execution.

**Mitigation:**
- Apply F5's patch for the affected BIG-IP APM branches (17.1.x, 17.5.x, 21.1.0) per F5 advisory K000162605.
- If immediate patching isn't possible, contact F5 support for the interim iRule-based mitigation for affected virtual servers.

**Affected:** F5 BIG-IP APM deployments on the 17.1.x, 17.5.x, and 21.1.0 branches where an APM access policy and OAuth profile are combined on the same virtual server. Disclosed and added to CISA KEV on 2026-09-22; F5 confirmed active in-the-wild exploitation at disclosure.

## 4. CVE-2026-85102 & CVE-2026-93616 — Check Point Security Gateway & Security Management Pre-Auth Flaws

**Principle / root cause:** CVE-2026-85102 is an improper-certificate-validation flaw (CWE-295) in Check Point Security Gateway / Spark Firewall VPN certificate handling — a malformed certificate presented during Site-to-Site or Remote Access VPN negotiation can be used by an unauthenticated attacker to achieve code execution. CVE-2026-93616 is a pre-authentication path-traversal flaw in Check Point Security Management that lets an attacker reach and execute a script from an arbitrary filesystem path and load an arbitrary Java class, again without credentials.

**Mitigation:**
- Apply Check Point's fixes (available since 2026-09-09 for CVE-2026-85102) immediately across all Security Gateway, Spark, and Security Management deployments.
- Restrict management-interface and VPN-endpoint exposure to trusted networks; review VPN and management logs for anomalous certificate or path-based requests since mid-September.

**Affected:** Check Point Security Gateway, Spark Firewall, and Security Management Server deployments prior to the fixed builds. Exploitation of CVE-2026-85102 against Spark customers observed globally from around 2026-09-12 (originating from anonymization/VPN-proxy infrastructure); CVE-2026-93616 exploitation observed in limited targeted attacks earlier in the summer. Both added to CISA KEV on 2026-09-22.

## 5. CVE-2026-93952 — Arista VeloCloud Orchestrator Improper Input Validation (Max Severity)

**Principle / root cause:** In VeloCloud Orchestrator (VCO) deployments configured for certificate-based authentication between VeloCloud Edge devices and the Orchestrator, improper input validation lets a remote attacker who can reach the VCO web UI and who holds only the *public* portion of a VeloCloud Edge authentication certificate (no VCO tenant or operator credentials needed) reach privileged internal VCO host functionality. A compromised VCO can, in turn, be used to reach and manage all Edge devices it controls.

**Mitigation:**
- Upgrade on-premises VCO to 5.2.3.16 or 6.4.2.8 (or later).
- Where certificate-based Edge→VCO authentication is enabled, review edge/VCO logs for unexpected administrative operations since the disclosure window.

**Affected:** On-premises Arista VeloCloud Orchestrator deployments (5.2.x and 6.4.x trains) with certificate-based Edge authentication enabled. Discovered via external report and confirmed under active exploitation; added to CISA KEV on 2026-09-22 with a federal remediation deadline of 2026-09-25.

## 6. CVE-2026-7273 — Zyxel GS1900 Series Switches Stack-Based Buffer Overflow

**Principle / root cause:** The CGI web-management program on Zyxel GS1900 switches fails to bound-check attacker-supplied input, resulting in a stack-based buffer overflow (CWE-121) reachable via a specially crafted HTTP request from an unauthenticated attacker on the local network. Successful exploitation allows execution of arbitrary operating-system commands on the switch.

**Mitigation:**
- Apply Zyxel's firmware update (available since June 2026) across all ten affected GS1900 models.
- Restrict management-interface access to trusted management VLANs/networks and rotate any credentials that may have been exposed.

**Affected:** Zyxel GS1900 series switches on firmware 2.90(XXXX.1)C0 and earlier. A suspected China-linked threat actor has compromised and exfiltrated configuration data and hashed root credentials from an estimated ~1,000 internet-exposed switches across 48 countries since August 2026. Added to CISA KEV on 2026-09-21 with a federal remediation deadline of 2026-09-24.

## 7. CVE-2026-32996 — Veeam Agent for Microsoft Windows Local Privilege Escalation

**Principle / root cause:** Veeam's Endpoint Backup service brokers privileged operations for its agent over a local gRPC named pipe. The service associates an elevated, administrator-equivalent identity with a client-supplied session UID without securely binding that UID to the actual requesting process or pipe connection — allowing a low-privileged local user to hijack a privileged session context and run commands as NT AUTHORITY\SYSTEM.

**Mitigation:**
- Upgrade Veeam Backup & Replication to 13.0.2.29 or later (updates the bundled Veeam Agent for Windows to build 13.0.3.1220, which contains the fix). No reliable workaround exists short of upgrading.

**Affected:** Veeam Agent for Microsoft Windows 13.0.1.2067 and earlier 13.x builds. Technical details and working exploit code were publicly released on 2026-09-14; active in-the-wild exploitation (used in post-compromise privilege-escalation chains) was subsequently confirmed by independent researchers.

## 8. CVE-2026-82843 — WP OAuth Server ("Login with WordPress") OpenID Identity-Assertion Misbinding

**Principle / root cause:** The plugin's OpenID Connect implementation fails to bind the identity assertion it issues to the specific authorization grant being redeemed. Instead, it returns the assertion belonging to whichever user most recently authenticated on the site — allowing any authenticated user (Subscriber role or above) to obtain a validly signed identity assertion for a different user, including a site administrator, and use it to log in as that user at any downstream application relying on the site for single sign-on.

**Mitigation:**
- Update to version 6.4.0 or later.
- Sites using this plugin for SSO into other applications should review recent SSO login events for anomalies and consider rotating session tokens after updating.

**Affected:** WP OAuth Server / "Login with WordPress" WordPress plugin, versions prior to 6.4.0. Disclosed this week; no confirmed mass exploitation reported yet, but the low bar for exploitation (any authenticated subscriber account) makes prompt patching important.

## 9. CVE-2026-67409 & CVE-2026-67404 — RabbitMQ OAuth2/JWKS Handling Flaws

**Principle / root cause:** CVE-2026-67409: RabbitMQ's JWKS key-fetching code does not validate the HTTP status code returned by the OAuth2 provider's JWKS endpoint. A non-200 response whose body still parses as valid JSON without a `keys` field causes RabbitMQ to discard all previously cached signing keys, so a single malformed response can trigger a persistent authentication denial-of-service for every OAuth2/JWT-authenticated user on the broker. CVE-2026-67404 is a related improper-certificate-validation issue that lets a man-in-the-middle attacker forge JWKS responses, causing the broker to accept attacker-controlled JWTs as valid.

**Mitigation:**
- Upgrade RabbitMQ to 4.3.3, 4.2.9, 4.1.14, 4.0.23, or 3.13.18 (or later), which fix both issues.
- Ensure TLS certificate validation is properly enforced for JWKS endpoint connections as defense in depth.

**Affected:** RabbitMQ Server 3.13.0 through versions prior to the fixed releases above, where OAuth2/JWT authentication with remote JWKS fetching is configured. Disclosed this week via GitHub security advisory.

## 10. CVE-2026-100589 — OpenClaw AI Agent Sandbox Bypass via Paired Nodes

**Principle / root cause:** OpenClaw's browser tool is meant to prevent a sandboxed agent session from controlling the host's connected ("paired") browser when `allowHostControl=false` is configured. The sandbox boundary does not correctly enforce this restriction for paired-node browser actions, so an attacker who controls input fed to a sandboxed agent session can select a paired node and issue host-browser operations anyway — inspecting or manipulating the connected browser's authenticated sessions.

**Mitigation:**
- Upgrade OpenClaw to version 2026.7.1 or later.
- Until upgraded, avoid pairing host browsers with agent sessions that process untrusted input.

**Affected:** OpenClaw versions prior to 2026.7.1. Disclosed this week as part of a broader set of OpenClaw sandbox-related findings; no confirmed in-the-wild exploitation reported yet.
