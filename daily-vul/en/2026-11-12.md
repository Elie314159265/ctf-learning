## 1. CVE-2026-124194 — Microsoft Outlook Zero-Day (Actively Exploited)

**Principle / root cause:** Outlook for Windows fails to adequately warn the user before completing a certain action when processing a specially crafted item, and in doing so can be induced to leak the user's NTLMv2 authentication material to a location of the attacker's choosing. An attacker who captures that material can attempt to relay it or crack it offline to impersonate the victim against other services.

**Mitigation:**
- Apply Microsoft's November 2026 updates for Microsoft 365 Apps and Office LTSC 2021/2024 immediately.
- As defense in depth, block outbound SMB/WebDAV traffic to the internet and enforce NTLM-relay protections (SMB signing, Extended Protection for Authentication), since hash-leak issues like this are typically weaponized through relay attacks.

**Affected:** Outlook for Windows within Microsoft 365 Apps and Office LTSC 2021/2024, prior to the November 2026 updates. Disclosed and patched 2026-11-10 as part of Microsoft's November Patch Tuesday, which addressed roughly 1,000+ CVEs across Microsoft products this cycle (exact totals differ by source: ~1,093–1,094 is most commonly cited). Microsoft confirms detection of in-the-wild exploitation but has not published technical indicators of compromise.

## 2. CVE-2026-123218 — IBM Aspera Faspex 5 Authorization Bypass (Federal Deadline Today)

**Principle / root cause:** An incorrect-authorization flaw (CWE-863) in Aspera Faspex 5 allows requests to reach functionality or data that should require stricter authorization checks, which the application fails to enforce consistently.

**Mitigation:**
- Update to Faspex 5.0.19 PL1 or later immediately; IBM states no workaround exists.
- Treat any internet-facing, unpatched Faspex instance as a priority incident.

**Affected:** IBM Aspera Faspex 5.0.0 through 5.0.19. IBM's advisory was published 2026-11-07; CISA added the flaw to its Known Exploited Vulnerabilities (KEV) catalog on 2026-11-09 citing active exploitation; the federal civilian remediation deadline is today, 2026-11-12.

## 3. CISA KEV Batch (2026-11-09): OpenSSH "sshole", GPUStack, FreeSWITCH

**3a. CVE-2026-123158 — OpenSSH Password-Authentication Bypass on musl-based Linux ("sshole")**

**Principle / root cause:** On Linux systems built against musl libc without PAM, musl's `crypt()` function rejects passwords longer than 256 bytes by returning the literal string `"*"` instead of signalling an error through its normal return convention. Because a shadow-file password hash of `"*"` conventionally means "password login is disabled" for that account, sshd can misinterpret the returned `"*"` as a valid match — letting an attacker log into an account whose password login was supposed to be disabled, simply by supplying an overlong password string. The bug has existed for roughly a decade and is most prominent on Alpine Linux.

**Mitigation:** Upgrade to OpenSSH 10.6p2 or later (released 2026-11-05). Where immediate upgrade is not possible, enable PAM for authentication or restrict affected hosts to key-based authentication only.

**Affected:** OpenSSH built against musl libc without PAM, prior to 10.6p2 (notably Alpine Linux). CISA KEV added 2026-11-09; exploitation attempts reported since 2026-11-06. MITRE rates it 8.1 High; the OpenSSH project itself rates it Critical.

**3b. CVE-2026-102895 — GPUStack Improper Authentication**

**Principle / root cause:** An improper-authentication flaw allows an attacker to reach administrative functionality without properly authenticating, enabling creation of rogue admin API keys, substitution of malicious AI-inference backends, and exposure of connected cloud credentials — which can in turn be used to execute commands on worker nodes (for example, by configuring a malicious inference backend that launches a reverse shell when invoked).

**Mitigation:** Upgrade to GPUStack 2.2.0 or later. Audit existing API keys and configured inference backends for unauthorized changes, and rotate any cloud credentials accessible from GPUStack workers.

**Affected:** GPUStack AI-infrastructure orchestration deployments prior to 2.2.0. Added to CISA KEV 2026-11-09 as actively exploited.

**3c. CVE-2026-116779 — FreeSWITCH SIP MESSAGE Command Injection**

**Principle / root cause:** FreeSWITCH's handling of SIP `MESSAGE` requests fails to properly neutralize attacker-controlled input before it is used in a command-execution context, allowing OS command injection from a specially crafted SIP message.

**Mitigation:** Upgrade to FreeSWITCH 1.11.3 or later. Restrict SIP signaling exposure to trusted networks.

**Affected:** FreeSWITCH (SignalWire), prior to 1.11.3. CVSS 9.8 Critical. The fix predates the KEV listing, so systems that delayed updating may already have been compromised. Added to CISA KEV 2026-11-09.

All three of the above share the same CISA federal remediation deadline, 2026-11-12 (today).

## 4. CVE-2026-19868 — SonicWall SonicOS SSLVPN SAML/MFA Bypass

**Principle / root cause:** An authentication-enforcement flaw in the SonicOS SSLVPN service allows someone holding valid credentials for one authentication method to bypass the separate checks that should be enforced when SAML-based single sign-on is configured — including SAML-enforced multi-factor authentication — effectively letting them skip an MFA step that is supposed to be enforced by the identity provider.

**Mitigation:**
- Update SonicOS: Gen7 to 7.3.4-7013 or later, Gen8 to 8.2.3-8015 or later. SonicWall states no configuration workaround exists.
- Review SSLVPN authentication logs for SAML-configured accounts completing logins (event ID 1080) without a corresponding sign-in event at the identity provider.

**Affected:** SonicWall SonicOS Gen7/Gen8 firewalls with SSLVPN and SAML enabled, versions prior to the fixes above. SonicWall advisory SNWLID-2026-0014 published 2026-11-06; CISA added it to KEV the same day; federal remediation deadline is 2026-11-20.

## 5. CVE-2026-98432 — Linux Kernel IPv4 TCP Use-After-Free (Re-rated Critical)

**Principle / root cause:** A race condition in the Linux kernel's TCP handshake handling allows a socket-related structure to be freed while another code path still holds a reference to it, resulting in a use-after-free (CWE-416) in networking code that is reachable from unauthenticated, remote network traffic. The most consistently reported impact is a crash or memory corruption; some reporting flags remote code execution as a possible, harder-to-achieve outcome.

**Mitigation:**
- Apply vendor kernel updates — Red Hat shipped fixed kernels for RHEL 8, 9, and 10 on 2026-11-01 (bulletin RHSB-2026-016); check your distribution's equivalent advisory.
- Where an immediate kernel update isn't possible, Red Hat's documented interim mitigation is an nftables filter dropping inbound IPv4 TCP packets that carry TCP header options.

**Affected:** Linux kernel since version 4.4, prior to the upstream fix (landed 2026-10-15); RHEL 8/9/10 and OpenShift. Red Hat initially rated the issue Moderate (5.9) and later re-rated it Critical (9.8); the Linux kernel's own CVE team also rates it 9.8. No confirmed in-the-wild exploitation at time of writing.

## 6. CVE-2026-109518 — APT (Debian/Ubuntu) On-Path MITM Root Code Execution

**Principle / root cause:** A time-of-check-to-time-of-use (TOCTOU) flaw in how the APT package manager handles HTTP redirects and retries after transient server errors allows an attacker positioned to tamper with the HTTP traffic between an APT client and a package archive (an on-path/man-in-the-middle position) to substitute an unverified, attacker-controlled package during a retried download — resulting in that package being installed and executed with root privileges.

**Mitigation:**
- Update `apt` to the fixed version for your release (Debian bookworm 2.6.2 / trixie 3.0.4 or later, via DSA-6607-1 / DLA-4880-1; check Ubuntu's security tracker for the equivalent fixed version).
- As an interim step, set `Acquire::Retries "0"` and avoid installing packages over untrusted or unencrypted networks until patched.

**Affected:** APT versions prior to the fixes above, on Debian, Ubuntu, and derivatives — most relevant where package downloads traverse plain HTTP or networks an attacker could be positioned on. Published 2026-11-04; CVSS 7.7; no known in-the-wild exploitation reported; not currently in CISA KEV.

## 7. CVE-2026-102703 & CVE-2026-102704 — Xen Hypervisor Grant-Copy Guest Isolation Break (XSA-523)

**Principle / root cause:** Xen's "grant copy" mechanism lets a guest VM ask the hypervisor to copy memory on its behalf. CVE-2026-102703 stems from the hypervisor confusing a grant reference with a raw memory frame number under certain re-validation conditions. CVE-2026-102704 stems from a check that should restrict frame-number-based copies to the caller's own memory being missing or misplaced. Combined, a malicious guest VM can read and write memory belonging to other guests — or to the privileged dom0 — breaking the memory isolation hypervisors are meant to guarantee between tenants.

**Mitigation:** Apply your distribution's or vendor's Xen security update (e.g., Debian trixie package 4.20.4+63-g7abfd2bce2-0+deb13u1 or later); no workaround is available, so patching the hypervisor and rebooting affected hosts is required.

**Affected:** Xen 4.6 and later (4.5 and earlier are not affected). Advisory XSA-523 published 2026-11-03. Vendors (Citrix, Vates) rate it Critical; NVD had not assigned a CVSS score at time of writing. Discovered through security research rather than observed attacks; no known in-the-wild exploitation.

## 8. CVE-2026-81648 — WordPress CryptoPayment Gateway Plugin Missing Authorization (No Fix Available)

**Principle / root cause:** An AJAX endpoint in the plugin, exposed through WordPress's shared `admin-ajax.php` handler, is missing an authorization check. As a result, any visitor — authenticated or not — can invoke privileged plugin functionality directly, including actions that touch stored cryptocurrency-payment configuration and site files.

**Mitigation:**
- No official fix currently exists. Remove or disable the CryptoPayment Gateway plugin immediately.
- As a stop-gap only, block requests targeting the vulnerable `admin-ajax.php` action at the web application firewall layer.

**Affected:** CryptoPayment Gateway WordPress plugin, versions 1.2.1–1.2.2 (already removed from the WordPress.org plugin directory in late August 2026 for an unrelated/unspecified security issue). CVSS 10.0 Critical. Reports of in-the-wild exploitation attempts exist; not currently listed in CISA KEV.

## 9. cPGuard / OpsShield Update-Channel Supply-Chain Compromise (No CVE Assigned)

**Principle / root cause:** Attackers gained unauthorized access to OpsShield's software update distribution infrastructure (reportedly via compromised credentials) and used that access to push a malicious update script through cPGuard's trusted auto-update channel. Because servers running cPGuard automatically trust and apply updates delivered through that channel, the malicious script executed with root privileges on each target, installing a backdoor and harvesting credentials — a classic supply-chain compromise rather than a flaw in the software's own code.

**Mitigation:**
- Update cPGuard to 5.88.25 or later to remove the malicious payload.
- Treat any server that ran an affected version as potentially compromised regardless of current version: rotate root/SSH credentials, database credentials, and any cloud secrets reachable from that host, and check for persistence mechanisms independent of the cPGuard package itself.

**Affected:** cPGuard (a Linux web-server security agent published by OpsShield), versions 5.88.12 through 5.88.19. OpsShield's advisory was published 2026-11-03; an estimated ~2,950 Linux servers were backdoored before the malicious update was withdrawn.

## 10. Continuity — CVE-2026-111497 "Node2Shell" (Brotli / Node.js): Federal Deadline Fell This Week

**Principle / root cause:** An out-of-bounds write in Google's Brotli decompression library (bundled by Node.js and several other runtimes), caused by the combination of an unchecked return value and a missing bounds check in the decoder. Feeding the decoder specially crafted compressed data can corrupt memory, and security researchers have demonstrated remote code execution against it under certain conditions.

**Mitigation:** Upgrade Brotli to 1.0.10, 1.1.1, or 1.2.1, and Node.js to 22.23.4, 24.22.1, or 26.12.1 or later; audit other Brotli-consuming runtimes (Python, Bun, Envoy, etc.) separately, since the underlying library is shared well beyond Node.js.

**Affected:** Brotli 1.0.3–1.2.0; Node.js 12.x through 26.x lines prior to the fixed releases above (including all currently end-of-life Node.js lines). Added to CISA KEV on 2026-10-27, just outside this week's disclosure window — included here because the federal remediation deadline fell on 2026-11-10, inside this week.
