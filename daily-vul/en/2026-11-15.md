## Newest items (last 24–72 hours)

### 1. CVE-2026-123039 — Check Point Gaia OS Local Privilege Escalation to Root (Exploited)

**Principle / root cause:** A root-owned helper process behind Gaia's DynamicCLI feature listens on a local socket with overly permissive (world-writable) access controls. It also does not properly check who sent a request before running the commands it receives. A local, low-privileged account or process on the appliance can therefore get commands executed as root (CWE-269 / improper privilege management; incorrect permission assignment on a critical resource). Some reports say attackers have chained it with a separate initial-access bug to fully take over gateways. That chaining has not been independently confirmed.

**Mitigation:**
- Install the fix from Check Point's advisory for this CVE. Several sources recommend the latest (November 2026) Jumbo Hotfix Accumulator for your deployed version.
- Because it is confirmed exploited, check for signs of compromise: unexpected local accounts, modified startup scripts, unfamiliar processes running as root, and unexplained configuration changes.
- Restrict who can get shell or local access to Gaia appliances (management networks only, MFA for admin access).
- CISA's guidance: apply the vendor's mitigations, or stop using the product if none are available. The federal due date is 2026-11-16.

**Affected:** Check Point Gaia OS on Security Gateways (including Quantum / Force firewalls), Management and Log Servers, Multi-Domain Security Management, and Maestro Orchestrator. Reports list Spark firewalls and Smart-1 Cloud as not affected. Check the exact versions and Jumbo Hotfix takes in Check Point's advisory (see also Canadian Centre for Cyber Security AV26-1154).

**Disclosure date:** Vendor advisory early November 2026; added to CISA KEV on **2026-11-13**.

### 2. CVE-2026-114713 — UnrealIRCd IRCv3 "label" Message-Tag Command Injection (Exploited)

**Principle / root cause:** UnrealIRCd's labeled-response module (IRCv3 `labeled-response`) echoes a client-supplied `label` message tag back into server replies without escaping it properly (CWE-140, improper neutralization of delimiters). Because the tag is not escaped, an ordinary connected user can make the server treat attacker-chosen data as a separate, server-originated protocol line. The server then runs IRC commands with server or IRC-operator authority (e.g., KILL, GLINE) on the attacker's behalf. The project called it its most serious vulnerability in roughly 15 years.

**Mitigation:**
- Upgrade to **UnrealIRCd 6.2.7.1** or later (security release, available as a no-restart hot-patch). It also fixes eight other issues.
- If you cannot upgrade immediately, apply the project's interim spamfilter-based workaround from the official advisory.
- Review server logs for unexpected KILL/GLINE/oper actions since early November.

**Affected:** UnrealIRCd 6.0.0 through 6.2.7 (all versions before 6.2.7.1).

**Disclosure date:** Fixed and announced **2026-11-07** (oss-security); CVE published around 2026-11-08; exploited in the wild; added to CISA KEV on **2026-11-13**.

### 3. Citrix NetScaler ADC & Gateway — Security Bulletin CTX697305 (28 vulnerabilities)

**Principle / root cause:** The bulletin fixes 28 vulnerabilities in NetScaler ADC and NetScaler Gateway. The most important are:
- **CVE-2026-120868:** reported to affect NetScaler appliances in their *default* configuration, so it does not depend on an optional feature such as Gateway/AAA being enabled. Such flaws in NetScaler appliances have historically been quickly targeted after disclosure.
- **CVE-2026-107412:** the highest-scored issue in the bulletin (CVSS 9.5).
- The rest are a mix of memory-safety, input-validation and access-control weaknesses across the management and data-plane components.

**Mitigation:**
- Upgrade NetScaler ADC / Gateway to the fixed builds listed in CTX697305 for your release line (including FIPS/NDcPP builds where applicable).
- After upgrading, follow Citrix's guidance on terminating active sessions where it is recommended.
- Keep the management interface (NSIP) off the internet. Watch NetScaler appliances closely, since past bulletins were often followed by exploitation within days.

**Affected:** NetScaler ADC and NetScaler Gateway supported release lines (see CTX697305 for the version matrix). Unsupported (EOL) releases will not get fixes and should be upgraded to a supported line.

**Disclosure date:** **2026-11-12**. As of 2026-11-13, none of the 28 CVEs were in CISA KEV and Citrix had not reported exploitation.

### 4. CVE-2026-119618 — Apache HTTP Server mod_http2 Race Condition → Heap Corruption / RCE

**Principle / root cause:** A concurrency bug (CWE-362 race condition) in the HTTP/2 module's header-handling path (reported as being in `assign_headers()`). Under certain timing conditions, shared request/stream state can be accessed while it is being changed or freed, which corrupts heap memory. A remote, unauthenticated client speaking HTTP/2 could crash the worker process, and in the worst case could potentially run code.

**Mitigation:**
- Upgrade to **Apache HTTP Server 2.4.71** or later, or apply your distribution's backported package (Red Hat rates RHEL 9/10 as "Important"). Anyone building the module separately should use **mod_h2 2.0.43** or later.
- If you cannot patch immediately, temporarily disable HTTP/2 (remove `h2`/`h2c` from the `Protocols` directive) on exposed servers.
- Note that 2.4.71 also fixes two other lower-severity issues (CVE-2026-109163, CVE-2026-106023).

**Affected:** Apache HTTP Server **2.4.55 through 2.4.70** with mod_http2 enabled. Products that bundle httpd (appliances, control panels, container base images) are affected if they ship those versions. This is a separate issue from CVE-2026-23918 (a double-free fixed in 2.4.67).

**Disclosure date:** **2026-11-11**. No known exploitation as of the latest reports.

### 5. CVE-2026-126325 — PTC Windchill and FlexPLM Insecure Deserialization

**Principle / root cause:** The server deserializes untrusted data without validation (CWE-502). If attacker-controlled serialized objects reach the vulnerable endpoint, they can trigger object-instantiation chains inside the application server, leading to remote code execution in the context of the PLM server.

**Mitigation:**
- Apply PTC's November 2026 security updates for Windchill and FlexPLM.
- Until patched, restrict network access to Windchill/FlexPLM servers to trusted users and networks only. Apply any interim configuration mitigations PTC publishes (e.g., blocking the affected servlet path at a reverse proxy).

**Affected:** PTC Windchill and FlexPLM (multiple supported releases; see PTC's advisory for exact versions/CPS levels).

**Disclosure date:** **2026-11-11**. No confirmed exploitation reported.

## Other notable items from the week

### 6. CVE-2026-124194 — Microsoft Outlook Spoofing / NTLM Hash Leak (Exploited Zero-Day)

**Principle / root cause:** A specially crafted message file can make classic desktop Outlook start an outbound connection to an attacker-controlled network location. Outlook skips its usual warning or blocking for external content when this happens. During that connection Windows can send NTLM authentication, so attackers have used the bug to harvest users' NTLM hashes. Those hashes can then be cracked offline or relayed. The CVSS is only 6.5 (Moderate), but because it is being exploited, treat it as high priority.

**Mitigation:**
- Update Office via its own Click-to-Run / Office update channel. **The fix is not delivered by the Windows cumulative update.** One report gives the Microsoft 365 Apps Current Channel fix as Version 2610 (Build 20527.20196).
- Block outbound SMB (TCP 445) / WebDAV to the internet. Consider adding high-value users to the *Protected Users* group or restricting outgoing NTLM traffic.
- Reports say Office 2016/2019 will not receive a fix. Migrate those installations.

**Affected:** Microsoft 365 Apps for Enterprise (32/64-bit), Office LTSC 2021 (reportedly builds below 16.0.14334.21048), and Office LTSC 2024 (reportedly builds below 16.0.17932.21140).

**Disclosure date:** **2026-11-10** (Patch Tuesday). CISA KEV added 2026-11-10, federal due date 2026-11-24.

### 7. CVE-2026-125350 — Google Chrome Use-After-Free in XML (Exploited Zero-Day)

**Principle / root cause:** A use-after-free (CWE-416) in Chrome's XML processing component. A crafted web page can make the browser use memory after it has been freed, which can corrupt memory and lead to code execution inside the renderer sandbox. Attackers usually chain such bugs with a sandbox escape. Google says an exploit exists in the wild. This is the 8th exploited Chrome zero-day of 2026. The same release also fixes a second XML use-after-free (CVE-2026-125346).

**Mitigation:**
- Update Chrome to **157.0.8103.50** (Linux) / **157.0.8103.50/.51** (Windows, macOS) or later, and restart the browser.
- Update other Chromium-based browsers (Edge, Brave, Opera, Vivaldi, etc.) when their vendors ship the fix.

**Affected:** Google Chrome before 157.0.8103.50, and Chromium-based browsers built on vulnerable versions.

**Disclosure date:** Reported 2026-11-06; fixed **2026-11-09**; CISA KEV 2026-11-10 (due 2026-11-24).

### 8. CVE-2026-116606 & CVE-2026-111560 — Barracuda Email Security Gateway Pre-Auth Chain (Exploited)

**Principle / root cause:** Two flaws that together let an unauthenticated remote attacker run commands as root on the appliance. Public reporting describes one as an input-handling flaw reachable without authentication and the other as a flaw that allows command execution. The researchers' write-up (watchTowr) and a detection tool were published after Barracuda's patch. Barracuda confirmed attacks against a small number of organizations.

**Mitigation:**
- Make sure ESG appliances are on **9.4.0.030 or later**. Check that automatic updates were applied, and apply the fixes for the other Barracuda product lines affected by CVE-2026-111560.
- Restrict access to the administrative interface. Look for signs of compromise. After the 2023 ESG campaign, Barracuda's guidance for confirmed-compromised devices included replacement, so follow vendor incident guidance closely.

**Affected:** Barracuda Email Security Gateway before 9.4.0.030 (CVE-2026-116606, CVSS 9.3). CVE-2026-111560 (CVSS 8.6) also affects other Barracuda product lines (see vendor advisory).

**Disclosure date:** Patched early in the week of 2026-11-02; technical write-up later that week; CISA KEV **2026-11-10** (federal due date 2026-11-13). Initial reports conflicted on whether the bugs were exploited; the KEV listing settles this.

### 9. CVE-2026-123158 "SSHole" — OpenSSH Password Authentication Bypass on musl Linux (Exploited)

**Principle / root cause:** A portability code path that dates from a 2016 change behaves incorrectly on Linux systems that use **musl libc** and do password authentication **without PAM**. When the password is unusually long (reported range: roughly 256–1,024 bytes), the length check goes wrong and sshd can accept the login without verifying the password correctly. The result is authentication bypass. Attacks began within hours to a day of public disclosure. Reported payloads included botnet / cryptominer deployment and a Python-based backdoor.

**Mitigation:**
- Upgrade to **Portable OpenSSH 10.6p2** or later, or your distribution's fixed package (Alpine published fixed packages on 2026-11-05).
- As an interim measure, disable password authentication (`PasswordAuthentication no`) and use key-based authentication, or restrict SSH exposure with allow-lists.
- Hunt for compromise on any exposed musl-based hosts (including Alpine-based containers that run sshd).

**Affected:** Portable OpenSSH before 10.6p2 on **musl-based** Linux systems using non-PAM password authentication. glibc-based distributions and PAM-based configurations are not affected.

**Disclosure date:** **2026-11-05**; exploitation from 2026-11-05/06; CISA KEV 2026-11-09 (due 2026-11-12).

### 10. CVE-2026-123218 — IBM Aspera Faspex Authorization Bypass (Exploited)

**Principle / root cause:** The server does not properly check authorization on certain requests. An authenticated, low-privileged user can send a crafted message that gets past those checks and escalates their privileges within the Faspex application. IBM scores it 9.8 and lists no workaround.

**Mitigation:**
- Upgrade to **IBM Aspera Faspex 5.0.19 PL1** or later.
- Review accounts and audit logs for unexpected privilege changes. Limit Faspex exposure to the users and networks that need it.

**Affected:** IBM Aspera Faspex **5.0.0 through 5.0.19**.

**Disclosure date:** IBM bulletin early November 2026; CISA KEV **2026-11-09** (federal due date 2026-11-12).

### 11. CVE-2026-19868 — SonicWall SonicOS SSLVPN SAML/MFA Bypass (Exploited)

**Principle / root cause:** When SAML is enabled for SSLVPN logins, SonicOS does not strictly require that method. A user with valid credentials for a *different* configured authentication method (e.g., LDAP, RADIUS, TACACS+, local) can log in that way and skip the SAML flow, including any MFA it enforces (CWE-308). Stolen passwords alone then become enough to get VPN access.

**Mitigation:**
- Upgrade to the fixed SonicOS builds in SonicWall advisory **SNWLID-2026-0014** (reported as Gen7 **7.3.4-7013** or later and Gen8 **8.2.3-8015** or later).
- Reported interim workaround: disable or remove any LDAP / RADIUS / TACACS+ authentication servers configured on the firewall that are not needed for SSLVPN.
- Reset credentials for VPN users and review VPN logs for logins that did not go through SAML.

**Affected:** SonicOS Gen7 **7.3.3-7015 and earlier** and Gen8 **8.2.2-8015 and earlier**, with SAML-based SSLVPN login enabled.

**Disclosure date:** **2026-11-06** (one of seven fixes in the advisory); CISA KEV 2026-11-06 (due 2026-11-20).

### 12. Microsoft November 2026 Patch Tuesday (overview)

**Principle / root cause:** Microsoft's largest monthly release on record, covering on the order of 1,094 CVEs. Sources report between ~1,093 and 1,235 depending on whether third-party/Chromium CVEs are counted. 63–64 are rated Critical. Only CVE-2026-124194 (item 6) is marked as exploited, and none were reported as publicly disclosed before release.

**Affected:** Windows client/server, Office/Microsoft 365, and other Microsoft products (see the Microsoft Security Update Guide).

**Disclosure date:** **2026-11-10**.
